# GameBot 脚本录制与可视化编辑器重构计划

> 状态：方案设计，尚未实施  
> 编制日期：2026-08-29  
> 适用范围：脚本/函数/模板存储、YAML 语法、脚本引擎、Console 录制、可视化编辑器、手动运行与定时任务  
> 破坏性说明：本计划采用新目录和新语法，不兼容旧脚本、旧函数库及旧编辑器生成格式，也不在运行时提供自动识别、迁移或回退逻辑。

## 1. 目标

本轮重构要同时解决三个问题：

1. 在 Console 中录制真实点击和滑动操作，自动生成模板及结构化步骤，并允许用户在保存前二次裁切。
2. 以可视化、强类型的步骤编辑器替代直接编辑 YAML，减少缩进、字段名、类型和引用错误。
3. 将可执行脚本、可复用函数和模板分开管理，建立明确且不需要猜测的文件职责与运行边界。

最终使用路径应当是：选择应用分区和脚本 → 进入编辑状态 → 可手动添加步骤或启动录制 → 使用卡片和表单调整参数/分支 → 校验 → 保存 → 填写脚本参数后运行或创建定时任务。

## 2. 已确定的设计结论

以下内容视为实施契约，不再保留旧行为作为兼容分支：

- 应用分区固定包含 `yaml/`、`func/`、`tmpl/` 三类资源；目录决定文件类型，不检测内容是“纯函数”还是“纯步骤”。
- `yaml/` 只存放可运行脚本，`steps` 必需；`func/` 只存放函数库，不能直接运行和调度。
- 脚本内不再定义本地函数，函数调用只解析同一应用分区下的 `func/` 文件。
- 脚本参数和函数参数统一使用 `类型:变量名:备注[:默认值]` 声明，并使用具名 `args` 传值；带默认值的参数可在调用时省略。
- 布尔分支使用 `if`；`match` 只用于模板匹配，不接受布尔值。
- `match` 采用用户确定的紧凑缩进：候选列表直接位于 `match` 下，`else` 和 `timeout` 是当前步骤的兄弟键，不写 `- else`。
- `match` 只检测、不点击；`find` 负责等待模板并点击中心。因此录制滑动使用 `match → swipe`，避免滑动前多一次点击。
- 编辑器以结构化模型为唯一前端编辑源；YAML 是服务端持久化及导入导出格式，不是默认编辑界面。
- 不保存旧 YAML 的注释、空行和原始排版；加载后按新模型解析，保存时统一输出规范 YAML。
- 录制模式只禁用投屏区域的 Alt 行为；模板列表 Alt 点击和二次裁切区 Alt 取色仍可用。

## 3. 非目标

本计划不包含：

- 旧目录、旧脚本、位置参数 `$1/$2`、旧 `func:` 顶层段落或省略 `steps:` 写法的兼容和自动迁移。
- 继续暴露依赖位置顺序的 `^1/^2` 上下文引用；新模型中候选模板、颜色和坐标都是明确字段，需要复用时直接选择对应参数或字面量。
- 在首版中增加表达式语言、脚本变量、算术、`and/or/not` 或隐式类型转换。
- 在 YAML 中持久化可视化编辑器专用的卡片 ID、折叠状态、颜色或布局信息。
- 首版支持从任意深层嵌套步骤直接启动运行；先保留当前“顶层步骤/函数体顶层步骤”边界。
- 首版不增加自定义参数类型、可空参数、表达式默认值、参数间依赖或复杂对象参数；默认值只允许当前七种类型的字面量。
- 改变单设备单运行实例、运行取消、设备占用仲裁和 DataChannel 脚本事件的既有原则。

## 4. 当前编辑区功能盘点

当前项目存在两套脚本编辑入口，重构时必须共用同一编辑核心，不能只替换其中一套。

### 4.1 Console 内嵌编辑区

当前 `Console.vue` 与 `components/console/ScriptRunner.vue` 已提供：

- 活动应用分区下的脚本选择。
- 运行、停止、停止中、提交中状态。
- 新建、编辑、删除、保存、取消。
- 运行中实时日志。
- 非编辑状态下展示只读脚本源码。
- 点击逻辑行选择“从此处运行”；点击函数名可运行整个函数。
- `call`/跨文件函数文本链接预览。
- Alt 模式、投屏操作记录、最近三条记录以及按光标位置插入 YAML 文本。
- 模板列表 Alt 点击生成 `find`，二次裁切区 Alt 点击生成颜色判断记录。
- 页面刷新后按设备恢复活动运行实例。
- `device_busy` 冲突提示、运行 ID 跟踪和旧接口降级分支。

### 4.2 独立脚本编辑页

当前 `ScriptEditor.vue` 已提供：

- 应用分区和脚本列表、新建、删除及分区切换。
- 文本编辑、行号、Tab 缩进、语法检查状态和语法帮助。
- 校验、保存、运行、停止。
- 运行提交中、停止中、活动实例恢复和设备占用冲突处理。

### 4.3 关联但容易遗漏的功能

以下能力不在编辑框本身，但依赖脚本模型，必须同步设计：

- `ScriptPicker` 在 Console 中锁定当前应用分区，在定时任务页中允许选择应用分区和脚本。
- 定时任务当前保存 `script_id` 和 `device_id`，新语法后还必须保存强类型参数快照。
- 导入/导出按应用分区工作，重构后需包含 `yaml/`、`func/`、`tmpl/`。
- 模板短名、`#` 搜索区域元数据、缩略图、二次裁切、重命名、删除和引用检查。
- 运行事件在投屏上显示 tap、swipe、hit、miss；重构不能破坏该链路。
- 前端校验、服务端校验、默认操作模板和 `docs/YAML.md` 当前共同描述语法，切换时必须同时替换。

## 5. 目标目录与资源边界

每个应用分区采用固定结构：

```text
data/<pkg>/
├─ yaml/             # 可执行脚本
├─ func/             # 函数库
└─ tmpl/             # 灰度模板 PNG
```

### 5.1 `yaml/` 可执行脚本

严格顶层结构：

```yaml
params:              # 可选
  - bool:enable:是否启用:true
  - tmpl:account:账号模板:account.png
config:              # 可选
  interval: 500ms
  threshold: 0.85
  log_level: info
steps:               # 必需
  - if: $enable
    then:
      - find: $account
```

规则：

- `steps` 必须存在，可为空列表但不能省略。
- 只允许 `params`、`config`、`steps` 三个顶层键。
- 只允许 `yaml/` 中的文件进入手动运行、立即运行和定时任务选择器。
- 脚本调用仍是可执行步骤，但只调用同分区 `yaml/` 下的另一个脚本。

### 5.2 `func/` 函数库

函数文件顶层直接使用函数名，不再套一层 `func:`：

```yaml
login:
  params:
    - tmpl:account:账号模板:account.png
    - time:timeout:等待时间:30s
  steps:
    - find: $account
      timeout: $timeout
    - return: true

is_enabled:
  params:
    - bool:enable:开关
  steps:
    - return: $enable
```

规则：

- 文件中的每个顶层键都是函数名，函数记录只允许 `params`、`steps`。
- `steps` 必需；函数正常走完仍返回 `true`，显式 `return` 可提前返回布尔值。
- 函数文件不能直接运行、不能被定时任务选择、不能拥有文件级 `config`。
- 本计划删除旧的函数级 `cond` 特例；需要前置模板条件时，在函数体第一步使用 `match` 并在分支中 `return`，使所有控制流都能在可视化编辑器中用相同步骤表达。
- 函数路径由“文件短路径/函数名”唯一确定，例如 `common/login` 表示 `func/common.yaml` 中的 `login`。
- 只在当前应用分区解析，不跨应用查找，也不回退到同名脚本文件。

### 5.3 `tmpl/` 模板

- YAML 和结构化模型统一引用短名，例如 `account.png`。
- 磁盘文件可为 `account#100_200_300_400.png`，`#` 后缀只承载搜索区域元数据。
- 同扩展名下短名必须唯一；产生多个 `account#...png` 候选视为资源错误，不由运行时猜测。
- 模板管理 API 返回短名、完整名、搜索区域、尺寸、引用计数和缩略图 URL，编辑器无需自行解析文件名。

## 6. 参数与引用模型

### 6.1 声明格式

脚本和函数统一使用：

```yaml
params:
  - tmpl:account:账号模板:account.png
  - coord:click_pos:点击位置:[0.5, 0.8]
  - color:target_color:目标颜色:ff8800
  - time:timeout:最长等待:30s
  - key:cancel_key:取消按键:ESC
  - text:message:提示文本:"示例"
  - bool:enable:是否启用:true
  - tmpl:confirm:确认按钮模板
```

声明格式为 `类型:变量名:备注[:默认值]`。前三段必需，第四段默认值可省略；例如 `tmpl:act:账号模板:act.png` 是有默认值的可选参数，`tmpl:confirm:确认按钮模板` 是没有默认值的必填参数。每一项仍是没有冒号后空格的 YAML 标量，列表标记必须写成合法 YAML 的 `- `。

解析规则固定为：

1. 第一个冒号前为类型，第一、第二个冒号之间为变量名。
2. 第二、第三个冒号之间为备注；不存在第三个冒号表示未声明默认值。
3. 第三个冒号之后的全部内容为默认值，因此文本默认值可以继续包含冒号，例如 `text:url:服务地址:https://example.com:8443`。
4. 为避免“备注中的冒号”和“默认值分隔符”产生歧义，类型、变量名和备注均不能包含半角冒号；备注需要冒号时使用全角 `：`。
5. 默认值按声明类型解析为结构化字面量，而不是始终当成字符串；空默认值（例如 `text:name:名称:`）非法，也不等价于没有默认值。

约束：

- 变量名建议固定为 `[A-Za-z_][A-Za-z0-9_]*`，同一参数表内不可重复。
- 没有默认值的参数必填；带默认值的参数可在运行或调用的 `args` 中省略，省略时使用声明值。
- 默认值必须是当前参数类型的字面量，不能引用 `$other`，避免出现参数顺序和循环依赖。
- 显式传入的值优先于默认值；`null` 和空字符串不会触发默认值，而是作为显式值按目标类型校验，其中只有 `text` 可以接受空字符串，当前七种类型都不接受 `null`。
- `$name` 是完整值引用，不做全文字符串替换；解析后的值以 YAML 节点类型绑定。
- 只有明确支持文本插值的输入框才允许在字符串中嵌入参数，普通数值、坐标、布尔和模板字段只接受完整引用。
- 缺少必填参数、未知参数、重复参数、默认值非法、引用不存在或类型不匹配均在保存前和服务端运行前报错。

### 6.2 类型与控件

| 类型 | 合法值/默认值示例 | 运行约束 | 可视化控件 |
|---|---|---|---|
| `tmpl` | `test.png` | 当前分区唯一模板短名 | 带缩略图的模板选择器 |
| `coord` | `[0.5, 0.8]` | 两个 0～1 相对坐标 | X/Y 数字框 + 投屏取点 |
| `color` | `ff8800` | 6 位十六进制 | 颜色选择器 + 十六进制输入 |
| `time` | `1ms`、`1s` | 必须带支持的时间单位且大于相应下限 | 数值框 + 单位下拉 |
| `key` | `ESC` | 受支持按键枚举 | 可搜索下拉框 |
| `text` | `"示例"` | YAML 字符串 | 单行/多行文本框 |
| `bool` | `true`、`false` | 必须是 YAML 布尔值，不接受字符串真假 | 开关或单选按钮 |

纯数字组成的颜色值序列化时必须加引号，避免前导零丢失或被当成数字。

默认值的额外规则：

- `tmpl` 默认值仍只写短名，并在脚本/函数保存时检查当前应用分区内唯一存在。
- `coord` 默认值必须是两个 0～1 数字组成的数组。
- `color`、`time`、`key`、`bool` 使用与运行参数完全相同的校验器，不能出现“默认值能保存但运行时不能使用”的差异。
- `text` 默认值取第三个冒号后的完整尾串；可使用双引号明确空格和特殊字符，但空字符串仍是合法的 `text` 值，必须写成 `""`，不能只留下空尾串。
- 编辑器保存时统一输出规范形式；未设置默认值时不输出第四个冒号。

### 6.3 具名调用

函数调用：

```yaml
- func: common/login
  args:
    account: account.png
    timeout: 30s
  then:
    - log: 登录成功
  else:
    - throw: 登录失败
```

脚本调用：

```yaml
- call: daily/sub_task.yaml
  args:
    enable: true
    message: "开始子任务"
```

调用规则：

- `args` 的键必须与目标参数名完全一致，值可为字面量或调用者同类型参数引用。
- 没有默认值的目标参数必须出现在 `args` 中；带默认值的参数可以省略。若所有参数都有默认值，整个 `args` 块也可省略。
- 参数绑定顺序固定为“声明默认值 → 显式 args 覆盖”，绑定完成后再执行类型校验和步骤引用解析。
- 函数返回布尔值，调用步骤直接使用 `then`/`else`，不再额外套 `if`。
- 脚本调用没有布尔返回分支；异常或 `throw` 仍结束整个运行。
- 引擎按结构化节点绑定参数，不再使用 `$1/$2` 和空格切分实参。

## 7. 控制流语法

### 7.1 布尔判断 `if`

```yaml
- if: $enable
  then:
    - log: 已启用
  else:
    - log: 已禁用
```

- `if` 只接受布尔字面量或 `bool` 参数引用。
- 不进行字符串、数字或空值的真假转换。
- `then` 和 `else` 均可省略，但编辑器至少提示“空判断没有效果”。
- 判断立即完成，不接受 `timeout`。
- 首版不支持表达式；组合条件用嵌套 `if` 或封装成返回布尔值的函数。

### 7.2 模板分支 `match`

规范缩进固定为：

```yaml
- match:
  - test1.png:
    - log: 命中 test1
  - test2.png:
    - log: 命中 test2
  else:
    - log: 都未命中
  timeout: 30s
```

语义：

- 候选模板按书写顺序匹配，首个命中分支获胜，不点击模板。
- 同一轮候选尽量复用同一张截图，避免候选之间因画面变化产生不一致判断。
- 未配置 `timeout` 时只执行一轮，全部未命中立即进入 `else`。
- 配置 `timeout` 时按 `config.interval` 轮询，到期仍未命中才进入 `else`。
- `else`、`timeout` 是 `match` 步骤的兄弟键，不能写成候选列表中的空 `-` 或 `- else`。
- `match` 不接受 `true`、`false` 或 `$bool`；布尔条件统一交给 `if`。

滑动录制的规范输出：

```yaml
- match:
  - swipe_start.png:
    - swipe:
        fm: [0.5, 0.8]
        to: [0.5, 0.2]
        time: 800ms
  else:
    - throw: 未找到滑动起点
  timeout: 30s
```

### 7.3 条件动作职责

| 步骤 | 输入 | 是否轮询 | 命中后是否点击 | 主要用途 |
|---|---|---:|---:|---|
| `if` | 布尔值 | 否 | 否 | 参数或函数结果的真假分支 |
| `match` | 多个模板 | 可选 | 否 | 画面策略选择、滑动起点保护 |
| `find` | 主模板 + 障碍模板 | 是 | 是 | 等待界面元素并点击中心 |
| `color` | 坐标 + 多个颜色 | 否 | 否 | 单点颜色策略分支 |

## 8. 可视化编辑器总体架构

### 8.1 一个编辑核心、两个页面外壳

新增共享的 `script-editor` 模块，Console 与独立脚本页只能复用该模块，不能各自维护语法、卡片和校验逻辑：

```text
服务端规范 YAML
      ↕ 严格解析/序列化
共享结构化模型 + 命令历史 + 校验器
      ↙                         ↘
Console 紧凑外壳              独立全屏外壳
录制/投屏/日志                 资源导航/批量管理/大画布
```

建议模块边界：

```text
web/src/script-editor/
├─ model.ts              # ScriptModel、FunctionLibraryModel、Step 联合类型
├─ codec.ts              # 新 YAML ↔ 模型，规范序列化
├─ schema.ts             # 字段、类型、上下文约束
├─ commands.ts           # 撤销/重做、插入、移动、复制、删除
├─ validation.ts         # 结构化客户端校验及错误定位
├─ factories.ts          # 手动添加和录制共用的步骤工厂
├─ selection.ts          # 选中步骤、插入锚点、面包屑和运行目标
├─ components/           # 画布、卡片、参数表、步骤控件、分支容器
└─ __tests__/
```

可以继续使用 JavaScript，但若项目允许，编辑器模型优先使用 TypeScript；复杂联合类型能显著降低“某步骤意外带入别的字段”的风险。

### 8.2 前端唯一编辑源

```text
ScriptModel {
  params: ParamDecl[]
  config: ScriptConfig
  steps: Step[]
}

FunctionLibraryModel {
  file: string
  functions: FunctionModel[]
}

FunctionModel {
  name: string
  params: ParamDecl[]
  steps: Step[]
}

ParamDecl {
  type: ParamType
  name: string
  remark: string
  default?: TypedLiteral
}
```

`Step` 至少包含：`str_app`、`cls_app`、`tap`、`swipe`、`find`、`match`、`color`、`if`、`loop`、`call`、`func`、`key`、`text`、`log`、`wait`、`throw`、`return`。

每个步骤在浏览器内分配稳定的临时 UUID，用于：

- 选中、折叠、拖动、撤销/重做。
- 记录队列完成后准确替换待处理步骤。
- 将字段错误定位到卡片。
- 保存时将顶层步骤 UUID 映射为引擎的 `start_index`。

UUID 不写入 YAML。运行时仍使用脚本 ID、函数文件/名称和顶层序号；以后若要高亮正在执行的卡片，可另行给运行事件增加结构化步骤路径。

### 8.3 页面布局

推荐三段式布局：

1. 顶部资源栏：应用分区、脚本/函数文件、保存状态、校验、运行/停止、更多操作。
2. 中央步骤画布：参数、配置、步骤卡片、分支容器和插入锚点。
3. 右侧属性/资源面板：当前步骤字段、模板预览、函数定义、错误列表；Console 空间不足时改为抽屉。

默认不展示 YAML。可在“诊断”中提供只读的“生成 YAML”预览和复制/下载，用于排查问题，但不能在该预览中直接修改。

### 8.4 步骤卡片交互

- 卡片收起时显示自然语言摘要，例如“点击坐标 0.5, 0.8”“等待并点击 login.png”“如果 enable”。
- 左侧固定显示动作图标、中文动作名、拖动手柄和步骤序号；点击动作名可切换该类型的专用展示。
- 展开时只显示当前步骤合法的强类型控件，不提供任意键值编辑器。
- 单击选中卡片；“添加步骤”默认插入到选中卡片之后。未选中时插入当前流程末尾。
- 当前编辑流程用面包屑表示，例如“主流程 / 匹配 test1 / 如果为真”；添加操作只进入当前面包屑对应的步骤数组。
- 一层分支可直接内嵌；更深层级进入专注子流程视图，避免卡片无限向右缩进。
- 支持拖动排序，同时提供“上移/下移”按钮保证触屏和无障碍操作可用。
- 支持复制、粘贴、重复、删除；跨脚本粘贴时重新校验模板、参数和函数引用。
- 采用命令栈实现撤销/重做；一次录制点击、模板最终裁切和步骤替换应合并为一次可撤销事务。
- 切换脚本、应用分区、退出编辑或关闭页面时，如存在未保存改动或未完成录制任务，必须确认。

### 8.5 添加步骤面板

按任务而非 YAML 名称分组，并支持搜索：

- 应用：启动应用、关闭应用。
- 操作：点击坐标、滑动、按键、输入文本、等待。
- 识别：等待并点击模板、匹配多个模板、判断颜色。
- 流程：布尔判断、循环、抛出错误、记录日志。
- 复用：调用脚本、调用自定义函数。
- 函数专用：返回布尔值；在脚本编辑上下文中隐藏。

旧 `[op_templates]` 和前端 `DEFAULT_OP_TPL` 不再生成文本片段；统一改为 `factories.ts` 中的强类型步骤工厂，手动添加、Alt 添加和录制都调用同一套工厂。

## 9. 各语法的可视化编辑方案

| 步骤/区域 | 卡片摘要 | 展开后的主要控件 | 专用交互与校验 |
|---|---|---|---|
| 参数 `params` | `7 个参数 · 5 个有默认值` | 类型下拉、变量名、备注、“使用默认值”开关、类型化默认值控件、排序 | 即时检查命名/重复/默认值；类型改变时检查默认值、全部引用和调用实参 |
| 配置 `config` | `轮询 500ms · 阈值 0.85 · info` | interval 数值+单位、threshold 滑块+数值、日志级别 | 使用服务端同范围约束，不允许未知配置键 |
| `str_app` | `启动当前应用` | 无 | 只允许裸动作 |
| `cls_app` | `关闭当前应用` | 无 | 只允许裸动作 |
| `tap` | `点击坐标 x, y` | X/Y 输入框或 `coord` 参数选择 | “从投屏取点”；坐标限制 0～1 |
| `swipe` | `从 x1,y1 滑到 x2,y2 · 800ms` | 起点、终点、时长 | “从投屏重录”；起终点不能完全相同，时间必须大于 0 |
| `find` | `等待并点击 account.png` | 主模板、block 有序模板列表、verify 开关、timeout、then/else | 模板缩略图、搜索区域徽标、测试匹配；主模板不可重复出现在 block |
| `match` | `按顺序匹配 2 个模板` | 可排序候选，每个候选拥有子流程；else、可选 timeout | 候选短名不可重复；明确显示“仅检测，不点击” |
| `color` | `在 x,y 判断 2 种颜色` | 坐标、可排序颜色+子流程、else | 色板/取色器；颜色为 6 位 hex；同色不可重复 |
| `if` | `如果 enable` | bool 字面量或 bool 参数选择；then/else | 禁止选择非 bool 参数；无分支时警告 |
| `loop` | `循环 5 次`/`无限循环` | 有限/无限切换、次数、子流程 | 无限循环给出明显标识；空循环报错 |
| `wait` | `等待 1s`/`随机等待 1s～3s` | 固定/区间切换、时间输入 | 区间起点不得大于终点 |
| `key` | `按键 ESC` | 按键枚举或 key 参数 | 只允许服务端支持的键 |
| `text` | `输入文本 …` | 文本/文本参数，允许的插值帮助 | 显示转义后的预览 |
| `log` | `记录日志 …` | 单/多行文本 | 可选明确支持文本参数插值 |
| `call` | `调用脚本 sub_task.yaml` | 脚本选择器、按目标 params 自动生成 args 表单；带默认值项可选“继承默认值” | 可打开目标脚本；目标参数/默认值变化后提示受影响的继承项 |
| `func` | `调用函数 common/login` | 函数文件、函数名、自动 args 表单、then/else；带默认值项可省略覆盖 | 可打开定义；返回值分支可为空；明确显示最终采用默认值还是调用值 |
| `throw` | `终止：原因` | 原因文本，可空 | 明示会结束整个任务，包括调用链 |
| `return` | `返回 true` | bool 字面量或 bool 参数 | 仅函数编辑器可添加，脚本中属于错误 |

坐标、模板、颜色、时间、按键、文本和布尔字段均应允许在“字面量”和“同类型参数”之间切换；参数模式显示 `$name`，但底层模型保存的是类型化引用对象，不依赖字符串前缀猜测。

### 10.1 Console 紧凑外壳

- 非编辑状态显示步骤摘要卡片；顶层卡片可选择运行起点。
- 编辑状态显示紧凑卡片画布；复杂分支在抽屉中专注编辑。
- “录制”按钮固定放在“启动应用”右侧；只有编辑脚本时可用，并同时要求已选择应用分区、脚本和可用设备画面。
- 运行时沿用现有实时日志、投屏命中框和设备控制，不让编辑器自己复制运行状态机。
- 录制时顶部明确显示录制状态、当前插入位置、待处理数量和停止按钮。

### 10.2 独立全屏外壳

- 左侧资源树显示当前分区的脚本、函数库和模板；中央为共享编辑画布；右侧常驻属性与错误列表。
- 提供更完整的批量重排、引用跳转、函数编辑、参数设计和生成 YAML 诊断能力。
- “保存并运行”在存在未保存内容时先通过服务端保存，再以保存后的版本和参数启动；不运行浏览器内未持久化的临时模型。

## 11. 录制模式详细设计

### 11.1 入口与可用条件

录制按钮位于 Console“启动应用”按钮右侧。

进入录制要求：

- 当前处于脚本编辑状态，而不是只读、运行中或函数库编辑状态。
- 已选择应用分区并存在一个可编辑的 ScriptModel；允许录制到尚未首次保存的新脚本，但保存前必须补齐合法文件名。
- 设备已连接并能取得最新画面；画面不可用时不给出“录制成功”的假状态。
- 没有正在保存或等待用户处理的不可恢复错误。

录制是透传模式：点击和滑动仍立即发送给设备，游戏正常响应，同时在后台生成模板和步骤。

### 11.2 Alt 行为拆分

现有单一 `isAltAction` 应拆成作用域明确的能力：

```text
projectionAltEnabled = altMode && !recording
templateAltEnabled   = altMode
cropAltEnabled       = altMode
```

- 非录制状态：投屏 Alt 点击/滑动继续只生成步骤、不发送控制。
- 录制状态：投屏区域忽略 Alt 特殊语义，所有点击/滑动按录制透传处理。
- 录制状态：Alt 点击模板短名仍可插入 `find`；Alt 点击二次裁切画布仍可插入 `color`。
- UI 文案不能显示“录制时 Alt 已禁用”，应显示“投屏 Alt 暂停；模板添加与取色仍可用”。

### 11.3 状态机与顺序队列

建议状态：

```text
idle → recording → stopping → idle
              ↘ error/retry ↗
```

每个录制动作另有独立状态：`capturing`、`uploading`、`cropping`、`ready`、`failed`。

- 所有动作进入单一有序队列，按用户操作顺序提交模型，不能因第二张模板上传更快而颠倒步骤。
- 触摸控制不能等待 PNG 编码或上传完成；先冻结所需帧，再立即向设备发送触控事件。
- “停止录制”和“保存”必须先处理当前草稿并等待队列排空；排空期间显示进度并禁用重复保存。
- 上传失败保留草稿、截图和插入位置，支持重试、改成坐标动作或丢弃；不能悄悄漏掉一步。
- 下一次录制动作、点击“确认裁切”、停止录制或保存，均可触发当前二次裁切草稿定稿。

### 11.4 点击录制

时序：

1. 指针按下时同步冻结点击发生前的最新视频帧和相对坐标。
2. 立即把点击发送给设备，不等待截图上传。
3. 以点击位置为中心得到自动模板区 `A`，默认 50×50 像素并裁剪到画面边界。
4. 将冻结画面的可编辑区域送入二次裁切区，创建待处理模板记录。
5. 用户若不调整，最终模板为 `A`；若调整，最终模板为手动区域 `M`。
6. 上传灰度 PNG，以唯一短名保存；搜索区域写入完整文件名 `#` 后缀。
7. 用短名创建 `FindStep` 并替换队列中的待处理占位卡片。

生成语义是“等待并点击模板中心”，因此不再额外生成 `tap`：

```yaml
- find: record_click_20260829_001.png
```

若模板过于纯色、越界后尺寸太小或用户明确选择“只使用坐标”，允许改为：

```yaml
- tap: [0.5, 0.8]
```

### 11.5 滑动录制

时序：

1. 指针按下时冻结滑动开始前的最新帧，记录起点并得到 50×50 自动模板区 `A`。
2. 移动过程只更新可视轨迹，不反复截图。
3. 指针抬起时记录终点和真实持续时间，立即把滑动发送给设备。
4. 模板进入与点击相同的二次裁切、上传和命名流程。
5. 最终创建 `MatchStep`，唯一候选分支中放置 `SwipeStep`，默认添加未命中错误和 30s 超时。

```yaml
- match:
  - record_swipe_20260829_002.png:
    - swipe:
        fm: [0.5, 0.8]
        to: [0.5, 0.2]
        time: 800ms
  else:
    - throw: 未找到滑动起点
  timeout: 30s
```

不能生成 `find → swipe`，因为 `find` 命中会先点击模板中心，可能改变游戏状态或破坏滑动手势。

### 11.6 自动模板、手动模板与搜索区域

定义：

- `A`：点击/滑动起点中心的自动 50×50 模板矩形。
- `M`：用户在二次裁切区确认的手动模板矩形。
- `S`：写入模板文件名的搜索区域。

规则：

- 无手动裁切：最终模板 = `A`；`S` = 以 `A` 为中心的 100×100 区域，超出帧边界时裁剪。
- 有手动裁切：最终模板 = `M`；`S` = `union(A, M)` 向四周各扩 25px 后裁剪到帧边界。
- 二次裁切面板至少加载 `S` 对应范围，不能只给 50×50 小图，否则无法把模板移动到自动区域之外。
- 坐标换算必须以冻结帧的原始像素尺寸为基准，不能使用浏览器 CSS 尺寸或裁切预览缩放尺寸。
- 在裁切确认前展示最终模板框、搜索区域框和实际像素尺寸；保存后步骤只显示短名，同时以徽标提示搜索区域。

### 11.7 命名和引用

默认短名建议：

```text
record_click_YYYYMMDD_NNN.png
record_swipe_YYYYMMDD_NNN.png
```

- 序号在当前应用分区内分配，并由服务端原子检查冲突。
- 用户可在二次裁切区修改短名；短名冲突必须要求改名，不自动覆盖。
- 完整文件名由服务端根据短名和 `S` 生成，前端不拼接 `#` 元数据。
- 重命名模板时服务端返回受影响引用，编辑器可在当前未保存模型中安全更新；跨文件批量更新应作为显式操作，不隐式修改。

### 11.8 插入目标

- 开始录制时锁定一个明确的流程容器和插入位置，默认是主流程末尾。
- 录制栏显示“录制到：主流程末尾”或具体分支路径。
- 录制过程中用户可以暂停后更换插入位置；不能在上传过程中拖动占位卡片到另一个分支造成顺序不确定。
- Alt 模板/取色添加也使用相同插入锚点，但不进入设备触摸录制队列。

## 12. 运行、函数与定时任务

### 12.1 手动运行参数

- 点击运行前，根据脚本 `params` 生成强类型表单；带默认值的字段显示“使用脚本默认值”，用户可切换为显式覆盖，没有默认值的字段保持必填。
- 最近一次手动输入只作为显式覆盖建议保存在浏览器，并与声明默认值分开展示；默认值改变后不能让旧缓存遮住新默认值。
- 请求体增加稀疏 `args` 映射；服务端按“默认值 → 显式覆盖”生成 `resolved_args`，再做缺失、未知和类型校验后创建运行实例。
- RunRecord/运行日志应记录解析后的参数快照或其脱敏摘要，保证之后能说明该次运行实际使用了什么值。
- “从此步骤运行”仍需让所有必填参数成功解析，因为后续步骤可能引用它们；有默认值的参数无需重复填写。
- 未保存脚本只允许“保存并运行”，避免 UI 模型、磁盘 YAML 和运行日志对应不上。

### 12.2 函数加载与调用

- 函数选择器先选文件，再加载并选择函数；args 表单从目标函数参数声明生成。
- 调用卡片省略某个有默认值的 args 时，运行时使用该次加载到的函数声明默认值；修改函数默认值会改变下一次调用行为，因此保存函数时应列出所有依赖该默认值的调用点供确认。
- 引擎每次运行首次调用某函数文件时加载并严格解析，之后在该运行实例内缓存。
- 函数文件在运行期间被修改不影响已开始实例，下一次运行生效。
- 递归/嵌套深度继续限制为 32 层；错误信息包含脚本、函数路径和调用链。
- 函数测试 API 接受 `pkg`、文件、函数名、`start_index`、`args`、设备 ID；函数不能作为普通脚本 ID 进入 RunManager。

### 12.3 定时任务

任务模型增加 `args`：

```text
Task {
  id, name, cron, script_id, device_id,
  args, param_signature, enabled, ...
}
```

- 新建/编辑任务时，选择脚本后立即渲染参数表单。
- 表单先应用脚本默认值，再接收用户覆盖；任务保存的是经过类型校验的完整解析值快照，而不是稀疏覆盖或拼接字符串，保证无人值守运行可复现。
- `param_signature` 覆盖类型、名称、是否必填和默认值；脚本参数声明或默认值改变后，已有任务显示“参数已过期”，禁用调度或在调度时明确失败，直到用户重新确认参数。
- 重新确认任务时应展示“任务原快照 / 当前脚本默认值 / 本次采用值”，避免默认值变化被静默吞掉。
- 立即运行任务沿用任务保存的 args；若需要临时覆盖，应另开显式表单，不修改任务本身。

## 13. 服务端与 API 设计

### 13.1 资源 API

建议分离：

```text
/api/scripts      # yaml/ 可执行脚本
/api/functions    # func/ 函数库
/api/templates    # tmpl/ 模板
```

共同要求：

- 所有单资源接口都显式带 `pkg`，资源 ID 作为整体编码，禁止跨分区路径穿越。
- 创建/更新脚本和函数时返回规范化模型摘要、版本标识和结构化错误列表。
- 更新支持版本/ETag 冲突检测，防止 Console 与独立编辑页互相覆盖。
- 导入先 dry-run，输出三类资源的新增、覆盖、冲突、非法引用；确认后再以分区快照提交。
- 导出始终包含现有的 `yaml/`、`func/`、`tmpl/`，允许目录为空。

### 13.2 解析与校验

服务端建立明确的两套入口：

```text
parse_script_file()   # 只接受 ScriptModel
parse_function_file() # 只接受 FunctionLibraryModel
```

不要保留 `normalize_top`、纯函数推断、顶层序列推断或旧字段引导迁移。校验分层：

1. YAML 语法和允许的顶层键。
2. 参数声明格式、默认值类型及唯一性。
3. 步骤结构、字段互斥和上下文限制。
4. 类型化引用和调用 args。
5. 同分区脚本、函数、模板资源引用。
6. 运行前再次解析被调用资源，防止保存后被外部文件操作破坏。

错误结构至少包含 `code`、`message`、`resource`、`step_path`、`field`，前端可直接定位卡片而非解析中文错误文本。

### 13.3 引擎模型

- Rust 侧先反序列化为严格 AST，再执行；不要在执行循环里继续按任意 `serde_yaml::Value` 猜动作。
- 参数环境保存类型化值；完整引用在执行当前步骤前解析。
- `match` 每轮只截一帧并按序匹配候选；命中后绑定当前模板上下文，再执行对应分支。
- `if` 只读取布尔节点。
- `func` 调用切换模板解析上下文到被调用函数所在的同一应用分区，并在返回后恢复调用者上下文。
- `throw` 继续跨脚本/函数调用链结束整个运行；`return` 只退出当前函数。
- 继续保留 10 万步 guard、32 层函数嵌套、取消信号和脚本事件。

## 17. 验收标准

满足以下条件才可认为本计划完成：

1. 用户无需查看或输入 YAML，即可创建、编辑并运行所有支持的步骤、分支、脚本调用和函数调用。
2. Console 与独立脚本页使用同一模型、codec、校验和卡片组件，没有第二套语法实现。
3. 当前编辑区的资源选择、新建/删除、保存/取消、运行/停止、停止中、实例恢复、冲突提示、日志、从步骤运行、调用跳转、模板/取色交互、导入导出和定时任务均有对应新交互并通过测试。
4. 点击录制生成可二次裁切的模板和 `find`；滑动录制生成模板及 `match → swipe`，设备操作顺序不被上传延迟打乱。
5. 无手动裁切时搜索区域为裁剪后的 100×100；手动裁切时按 `union(A,M)+25px` 生成，YAML 只引用唯一短名。
6. 录制模式仅关闭投屏 Alt 特殊行为，模板 Alt 添加和二次裁切 Alt 取色继续可用。
7. `yaml/`、`func/`、`tmpl/` 职责严格，旧脚本/旧语法不会被自动识别或回退执行。
8. 七种参数及其可选默认值在脚本运行、脚本调用、函数调用、函数测试和定时任务中保持相同类型语义；必填、继承和显式覆盖行为一致。
9. 服务端权威校验能把错误定位到资源、步骤路径和字段；前端不靠解析错误字符串定位。
10. Rust 测试、前端测试和构建通过，并完成至少一轮真实 Android 设备录制、运行和任务调度验收。

## 18. 风险与控制

| 风险 | 影响 | 控制措施 |
|---|---|---|
| 可视化模型与引擎 AST 漂移 | 保存成功但运行语义不同 | 共享 schema fixture；前后端对同一规范 YAML 做契约测试 |
| 两套页面再次分叉 | 功能遗漏和修复不一致 | 页面只提供外壳，共享编辑核心拥有模型、命令、校验和卡片 |
| 录制截图晚于触控 | 模板截到操作后的界面 | pointer down 先冻结帧，再发送控制；测试记录 frame sequence |
| 快速操作导致步骤乱序 | 回放顺序错误 | 单一有序队列、占位 UUID、保存前 flush |
| 模板区域太小或低纹理 | NCC 误匹配/不稳定 | 弱模板告警、二次裁切、匹配测试、坐标动作降级 |
| 参数声明/默认值改动破坏任务 | 定时任务在无人值守时静默改变行为 | 保存包含默认值的参数签名和完整解析快照，编辑任务时标红，调度前权威校验并记录明确失败 |
| 同一文件被两个页面覆盖 | 用户改动丢失 | 版本/ETag 冲突检测，冲突时重新加载或显式另存 |
| 破坏性发布导致现有数据不可用 | 旧自动化全部停止 | 发布前整分区备份；用新格式重新建立数据快照；不在运行时代做半兼容迁移 |

## 19. 发布与回滚

- 本次应作为 `feat(engine)!`/`feat(web)!` 级别的破坏性版本发布，并在提交正文写 `BREAKING CHANGE`。
- 在部署前停止调度器和活动运行，导出现有分区并做只读备份；新版本启动后只导入人工确认的新格式快照。
- 不自动就地改写旧脚本。数据准备不完整时应阻止升级，而不是让新旧语义混跑。
- 回滚需要同时恢复旧程序版本和升级前的数据目录/数据库快照；不能只回滚二进制后继续读取新格式任务 args 和新目录。
- 建议按主题拆分提交：存储/API、引擎语法、任务数据、共享编辑器、Console 录制、文档与测试，保证每个阶段可独立审查。
