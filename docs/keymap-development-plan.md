# GameBot 按键映射与投屏可视化功能开发计划

> 多方案切换、YAML 配置、可视化遮罩与现有键盘控制兼容方案

| 项目 | 内容 |
|---|---|
| 文档性质 | 技术开发计划 / 设计基线 |
| 适用范围 | Console 投屏控制台的按键映射功能 |
| 当前状态 | 方案确认，待进入实现阶段 |
| 日期 | 2026-09-02 |

## 设计结论

四项新增要求可以统一实现：

- 映射配置由服务端以 YAML 持久化。
- 浏览器在投屏控制层执行映射。
- 点击、滑动继续复用现有 WebRTC DataChannel 控制协议。
- 未命中的按键继续复用现有游戏模式逻辑。
- 文本模式完全绕过映射。

## 1. 目标与范围

本功能面向一般 Android 模拟器式的按键映射场景：用户可以把键盘按键绑定为投屏画面中的点击或滑动操作，并通过半透明遮罩直观看到当前按键与屏幕操作的对应关系。映射方案可以按应用保存、编辑和切换。

本期目标包括：

- 在右侧功能区增加“映射”页签，支持方案新建、编辑、删除、复制和保存。
- 映射配置采用独立 YAML 格式，同时提供可视化配置和原文编辑。
- 工具条增加当前映射下拉框，第一项固定为“无映射”，默认选中，并支持切换后实时生效。
- 定义游戏模式、文本模式、映射命中和未命中的明确路由规则。
- 保留现有键盘控制、文本输入、投屏点击、模板框选和 WebRTC 控制链路。

## 2. 已确认需求与行为规则

| 需求 | 设计规则 | 验收重点 |
|---|---|---|
| 映射页签 | 右侧新增“映射”页签，负责配置管理与编辑。 | 新建、编辑、删除、复制、保存、取消可用。 |
| YAML 配置 | 配置使用独立 keymap schema，同时支持可视化编辑和原文编辑。 | 非法 YAML、非法字段和非法坐标不能保存。 |
| 当前映射 | 工具条在游戏/文本模式按钮后增加下拉框；第一项为“无映射”。 | 切换后立即影响后续按键，默认不启用映射。 |
| 游戏模式 | 映射命中优先执行映射；未命中继续执行原游戏模式逻辑。 | 映射按键不重复发送原始 Android 按键。 |
| 文本模式 | 映射直接失效，完全走当前文本模式逻辑。 | 可输入文字；不因当前选择了映射而改变文本行为。 |

## 3. 输入路由与实时生效

输入处理建议集中为一个路由层，避免现有键盘控制器和新映射逻辑之间出现双重发送。

```text
文本模式
  -> 现有文本模式逻辑

游戏模式 + 无映射
  -> 现有游戏模式逻辑

游戏模式 + 有映射
  -> 命中绑定：执行映射动作
  -> 未命中绑定：执行现有游戏模式逻辑
```

### 3.1 切换时的状态处理

- 切换方案前释放旧方案正在按住的触控状态，防止旧映射残留。
- 切换到文本模式时释放映射层状态，后续输入只进入文本模式。
- 切换到“无映射”时只关闭映射层，不改变原有游戏模式设置。
- 方案切换不追溯已经按下的物理键，只处理切换后的新事件。
- 页面失焦、浏览器隐藏、WebRTC 断开和组件卸载时统一调用释放逻辑。

> **兼容性边界**：当前键盘控制已经区分有状态的 key down/key up 与无状态的 press。映射层必须继续走 DataChannel，不能把按键按下事件降级为 REST press，否则会破坏释放语义。

## 4. 页面与交互设计

### 4.1 右侧“映射”页签

建议右侧页签调整为：

```text
模板 | 脚本 | 映射 | 日志 | 任务 | 设置
```

映射页签按当前 `activePkg` 显示方案列表，与脚本、函数库和模板共用应用包名分区。页面分为方案列表、编辑工具栏和编辑主体三部分。

- 方案列表：名称、绑定数量、修改状态、编辑、复制、删除。
- 编辑工具栏：新建、保存、取消、可视化编辑 / 原文编辑切换、导入 / 导出。
- 编辑主体：绑定列表、动作参数、按键录入、画面取点和滑动轨迹录入。
- 当前正在使用的方案显示“使用中”标记，但编辑草稿不能直接影响运行态。

### 4.2 工具条当前映射选择

现有键盘模式按钮后增加方案下拉框：

```text
🎮 游戏模式   [无映射 ▼]
```

- 下拉框第一项固定为“无映射”。
- 页面首次进入、切换设备和切换应用包名时默认回到“无映射”。
- 用户主动选择方案后立即生效，并同步更新投屏遮罩。
- 文本模式下保留当前选择，但显示“文本模式下映射不生效”。
- 方案加载或校验失败时自动回退到“无映射”，同时提示错误原因。

### 4.3 可视化配置流程

1. 点击“新增映射”。
2. 选择动作类型：点击、滑动或原始按键。
3. 点击“录入按键”，用户按下实际键盘按键；系统保存 `KeyboardEvent.code`。
4. 点击投屏画面中的目标位置，或在画面上拖出滑动轨迹。
5. 确认参数后保存绑定；多个绑定可以组成一个完整方案。

编辑态需要暂时拦截投屏画面的普通点击，避免配置操作误触 Android 设备。运行态遮罩使用 `pointer-events: none`，不影响既有投屏点击、拖动和模板框选。

### 4.4 半透明遮罩

| 动作 | 画面表现 | 交互要求 |
|---|---|---|
| 点击 | 半透明圆点 + 按键标签，例如 `Space`。 | 按下时高亮，松开恢复。 |
| 滑动 | 半透明箭头线，显示起点、终点和按键标签。 | 标记随视频缩放，不能遮挡投屏输入。 |
| 原始按键 | 小型按键标签，不显示坐标。 | 仅表示键盘透传绑定。 |
| 方案状态 | 左上角显示当前方案名和映射状态。 | 文本模式下显示映射不生效。 |

## 5. YAML 配置设计

映射配置采用独立的 `keymap` YAML 格式，不直接套用脚本 v2 loader。这样可以保持映射 schema 简洁，也避免脚本步骤字段与按键动作字段互相污染。

```yaml
version: 1
name: 战斗方案

bindings:
  - key: Space
    action:
      type: tap
      at: [0.72, 0.86]

  - key: KeyE
    action:
      type: swipe
      from: [0.40, 0.80]
      to: [0.60, 0.80]
      duration_ms: 300
```

### 5.1 校验约束

- 坐标使用 `0~1` 归一化值，适配视频分辨率变化、窗口缩放和 letterbox 黑边。
- 按键使用 `KeyboardEvent.code` 作为唯一匹配键，显示名称由前端根据 code 生成。
- 同一方案内不允许重复绑定同一个物理按键。
- 动作类型和动作字段采用白名单校验；未知字段、未知动作和越界坐标不能启用。
- 方案以版本号管理，更新接口使用 `expected_version`，避免编辑冲突覆盖。

### 5.2 建议的动作类型

| 动作类型 | 第一版语义 | 后续扩展 |
|---|---|---|
| `tap` | 按键按下时点击一次，忽略自动重复。 | 连点次数、间隔。 |
| `swipe` | 按键按下时执行一次固定滑动。 | 循环滑动、取消和方向参数。 |
| `raw_key` | 继续发送原始 Android key event。 | 组合键和特殊键。 |
| `hold` | 按下时 touch down，释放时 touch up。 | WASD、多键同时按下、虚拟摇杆。 |

> **实现建议**：第一版界面可以只开放 `tap`、`swipe` 和 `raw_key`，但数据模型应预留 `hold`。真正的模拟器体验通常需要按住 W/A/S/D 和多键同时操作。

## 6. 存储、API 与前端结构

### 6.1 存储位置

映射方案建议按应用包名分区：

```text
data/<package>/keymap/
  默认方案.yaml
  战斗方案.yaml
  探索方案.yaml
```

映射方案按应用包名分区，不提供跨分区回退。`activePkg` 变化时重新加载方案，并将当前运行选择安全地重置为“无映射”。

### 6.2 服务端 API

| 能力 | 职责 |
|---|---|
| 列表 | 按 package 返回方案名称、文件标识、版本和绑定数量。 |
| 详情 | 返回 YAML 原文和解析后的结构化模型。 |
| 创建 / 更新 | 校验 YAML、写入文件、维护版本；更新支持 `expected_version` / `force`。 |
| 删除 | 删除指定方案；如果是当前方案，前端先切换为无映射。 |
| 导入 / 导出 | 导出当前应用分区的映射 YAML；导入前逐文件校验。 |

### 6.3 预计涉及文件

- `server/src/keymaps.rs`：映射文件存储、解析、校验和序列化。
- `server/src/api/keymaps.rs`：映射方案 CRUD 与导入导出接口。
- `web/src/components/console/KeymapPanel.vue`：映射页签和配置界面。
- `web/src/keymap-control.js`：映射匹配、动作分发和状态释放。
- `web/src/views/Console.vue`：页签、当前方案、输入路由和编辑捕获状态。
- `web/src/components/console/ConsoleVideoStage.vue`：映射遮罩渲染。

## 8. 兼容性与风险控制

| 风险 | 处理方案 |
|---|---|
| 映射与原始键盘重复发送 | 命中映射后立即消费事件，不再调用原游戏键盘逻辑。 |
| 长按点击产生重复点击 | `tap` 动作只响应首次 `keydown`，忽略 `repeat`。 |
| 按住状态残留 | 复用并扩展 `releaseAll`；切换、失焦、断开时统一释放。 |
| 文本模式行为被改变 | 文本模式在路由层优先，映射层不参与。 |
| 窗口缩放导致坐标偏移 | 保存归一化坐标，渲染复用现有 geometry 映射。 |
| 不同方案编辑互相覆盖 | 服务端版本号 + `expected_version`；冲突时提示重新加载或强制覆盖。 |
| WASD 多键操作无法并行 | `hold` 阶段扩展 touch `pointer_id`；第一版一次性 tap/swipe 可暂不改协议。 |
| 系统级快捷键被浏览器或操作系统拦截 | 对 Alt+Tab、Win 键等组合提供提示，不承诺网页层完全拦截。 |

## 9. 测试与验收标准

### 9.1 功能验收

- [ ] 右侧存在“映射”页签，并能完成新建、编辑、复制、删除、保存和取消。
- [ ] 方案默认存储在当前应用包名分区，切换 `activePkg` 后不会误用其他应用方案。
- [ ] 工具条下拉框第一项为“无映射”，首次进入默认选中。
- [ ] 游戏模式下，命中绑定的按键只执行映射动作。
- [ ] 游戏模式下，未命中绑定的按键继续走原游戏模式逻辑。
- [ ] 文本模式下，无论下拉框选择何种方案，映射都不执行。
- [ ] 切换方案后无需刷新页面即可影响后续按键和遮罩。
- [ ] 投屏缩放、分辨率变化和 letterbox 黑边不会造成映射坐标明显偏移。
- [ ] 原文 YAML 编辑存在错误时不能保存，也不能破坏当前已启用方案。

### 9.2 自动化测试

| 测试层 | 覆盖内容 |
|---|---|
| YAML loader | 字段白名单、动作结构、重复按键、坐标范围、时长、版本和诊断信息。 |
| 输入路由 | 无映射、映射命中、映射未命中、文本模式、repeat、失焦和释放。 |
| API | CRUD、包名分区、版本冲突、非法 YAML、删除当前方案。 |
| 组件 | 页签、下拉框默认项、实时切换、编辑态拦截、遮罩显示和错误提示。 |
| 回归 | 现有触控、滑动、文本输入、脚本运行可视化和 WebRTC 控制不受影响。 |

## 10. 暂不纳入第一版的内容

- 虚拟摇杆和复杂轨迹编辑。
- 按住动作的多指并行控制。
- 组合键绑定和宏动作。
- 自动识别游戏界面并生成映射。
- 跨设备差异化坐标微调。

> **待确认决策**：第一版是否必须直接支持按住 W/A/S/D 和多键同时操作？如果答案为“是”，应在阶段 1 同步冻结 `pointer_id` 扩展；如果答案为“否”，可先按点击和一次性滑动交付，再扩展 `hold`。

## 附录：与现有代码的衔接点

当前实现已经提供可复用的基础：

- `Console.vue` 负责投屏区域焦点和键盘事件绑定。
- `keyboard-control.js` 负责 key down/key up、文本模式、重复键和 `releaseAll`。
- `ConsoleVideoStage.vue` 负责视频与叠加层。
- `geometry.js` 负责 `object-fit: contain` 下的设备坐标映射。
- WebRTC DataChannel 负责触控、滑动和有状态按键传输。

本计划只新增映射资源与输入路由，不改变现有脚本引擎语义，也不把映射配置混入脚本 YAML。若后续扩展 `hold` / 多指动作，再单独升级 DataChannel touch 的 `pointer_id` 语义并补充协议回归测试。
