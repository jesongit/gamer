# 直播助手接入

`gamer-live` 提供设备画面/游戏音频输出、B 站直播互动连接与消息查看。直播姬负责素材合成、麦克风与开播，插件不包含具体互动玩法。

「直播输出」还提供自动直播模式：空闲时循环播放服务端本机文件夹的视频，匹配弹幕后切到执行设备画面，沿用现有 FIFO 执行函数或自动化；队列清空后恢复视频断点。该流程由插件后台管理，不需要常驻脚本，不占设备运行槽。停止流程会封住新触发、清理等待项、取消本流程当前互动并等待收尾，再关闭输出；互动账号连接保留。

设置分为「直播输出」「互动接入」「反馈提醒」「互动规则」「用户管理」「触发日志」六个页签。互动凭据与执行目标放在「互动接入」，观众网页与主动弹幕放在「反馈提醒」；画质和提醒模板按需展开。切换页签保留未保存的输入。

完整操作、权限要求、动作参数和平台扩展边界见 [插件说明](../../plugins/gamer-live/README.md)。本插件需要配套的 Gamer 原生实现，旧本体安装会拒绝未知 builtin 或权限；不能仅靠安装 UI 包增加原生能力。

推荐同机使用：插件开始本机素材输出 → 复制地址 → 直播姬添加「多媒体」素材 → 粘贴地址。该地址是拉流素材地址，不是 B 站推流服务器地址。另提供手动 RTMP / RTMPS 输出。

需要上屏排队进度时，在「反馈提醒」打开「观众反馈」开关，将网页地址交给同机直播姬的网页素材。网页显示空闲／任务状态、一个当前或最近完成的任务、完整等待队列，以及在直播助手编辑保存的提示文字；关闭开关停止读取，互动任务继续执行。视频素材和反馈网页都复用本体端口（默认 8443），地址固定，关闭时也可复制；停止再开或重启服务后无需重新填写。

Docker 映射端口时，本机素材与反馈必须使用宿主端口，例如 `18443`。按 [Docker 本机素材配置](../../deploy/docker/DOCKERHUB.md#local-live-sources-in-docker) 将端口仅发布到宿主 `127.0.0.1`，并显式设置发布端口与实际 Docker 网关来源；默认真实回环限制不会自动信任容器网络。修改端口保留原读取密钥，需重新复制完整地址。

凭据由每位用户自己填写，保存到服务端本机私有配置，Windows 使用当前系统账号的 DPAPI 保护，页面不回显秘密，不进入 Package、不预置共享开发者密钥。OAuth 模式接收用户已经取得的 Token，不提供授权回调和自动续期。

「用户管理」可查用户名或完整 open_id，修改余额或设为无限次；新人默认 1 次。在「互动规则 → 编辑 → 每次消耗额度」按功能设置次数，填 0 即免费，余额为 0 的观众也能使用且不预占、不扣次。大于 0 时入队先预占，日常只在最后领奖实际核验后扣除；失败、取消和确认超时退回。次数不足不会排队或切换到设备。修改消耗只影响新入队，已排队及手动重试保留原消耗次数。身份绑定平台、应用、直播间和 open_id，重连及改昵称不重置次数。

连接互动后，付费礼物自动增加送礼人次数：官方单价 `price` 的单位是 1000 = 1 元 = 10 电池，按本条数量折算 `ceil(price × gift_num / 1000)`；15 电池／1.5 元增加 2 次。免费礼物不增加次数，消息 ID 持久去重，重连、重启或清理日志不重复入账；模拟测试不增加次数。反馈网页的当前任务和排队项同步显示本次消耗、剩余可用次数及已预占次数，消耗为 0 或入队时已免扣的任务显示「免费」。

当前任务、最近结果和等待队列每位观众均占两行：昵称和状态；功能名称、消耗和剩余可用次数。完整标识、粉丝牌、已预占明细和执行时长仅在管理页面查看。长昵称和功能名省略显示，完整内容可悬停查看；扫码/确认倒计时合并到状态行。空队列时隐藏队列标题和空提示。任务进入收尾或结束后停止显示扫码/确认倒计时，以实际执行状态为准；失败后恢复播视频不表示仍在等待登录。

配套云游戏脚本按以下阶段处理本人弹幕；身份同时匹配平台、应用、直播间和完整 open_id，排队中的其他人不能控制当前任务。

| 阶段 | 确认 | 取消 | 扫码 | 超时 |
| --- | --- | --- | --- | --- |
| 等待扫码 | 无效，必须先检测到登录成功 | 释放预占并退出 | 重新显示二维码，原期限不延长 | 5 分钟后释放预占，核验退出后继续下一位 |
| 登录成功，等待确认 | 开始日常 | 释放预占并退出 | 退出当前账号，重新扫码；沿用本轮确认的剩余期限 | 首次登录就绪起 5 分钟，释放预占并退出 |
| 日常执行中 | 忽略 | 忽略 | 忽略 | 沿用日常自身的异常与等待限制 |
| 退出收尾或任务结束 | 忽略 | 忽略 | 忽略 | 登录取消／超时收尾最多 60 秒；无法核验退出时暂停队列，由主播处理 |

扫码期限从本任务进入登录流程时开始；每位观众先处理残留登录并刷新扫码页，重复弹幕、刷新二维码或重复调用状态函数不会重置期限。检测到进入游戏按钮只开启本人确认等待，确认前不会点击进入。退出时核验登录页或扫码页，已经处于未登录页面则直接结束；退出失败不让下一位沿用账号。控制消息不收费，也不会匹配普通任务规则。正常日常结束仍重置输入、退出并核验。

Windows 与 Docker 字体不同，扫码就绪与退出核验同时使用对应的独立模板，不降低原阈值。准备扫码页期间持续轮询本人取消与同一五分钟期限，不再因旧模板 15 秒未命中便提前结束。未取得确认即发生初始化失败时，保留原始失败原因，退回预占并执行不刷新页面的登录退出收尾。

「反馈提醒 → 主动弹幕」配置独立发言账号的 SESSDATA、bili_jct 和房间 ID，可编辑自动提醒并手动提交弹幕。设置已保存不等于实际账号已经验收；刷新发言状态查看结果。发送在独立后台限速、去重，失败不会阻塞日常任务，模拟任务不会触发真实发言。

本轮本地证据与待实连项见 [验收记录](../evidence/LIVE_USERS_CONFIRMATION_2026_10_16.md)。源码变更需要重建本体并配套 gamer-live 0.2.14、gamer-yaml 0.3.19。候选资源准备后，`node tools/live-workflow/apply-users-confirmation.mjs apply` 会检查新宿主能力、脚本哈希、现有版本和直播空闲状态，按收尾、主脚本、规则的次序发布；它不会启停服务、开始任务或发送设备输入。

Core 新增 `media.stream`（media 域）与 `live.connect`（runtime 域）的显式权限门禁；后者只允许插件内受控的平台连接，不开放任意网络或 shell WIT。常驻 builtin 服务经 ExtensionService 的生命周期钩子接入，停用和服务退出均关闭后台任务。
