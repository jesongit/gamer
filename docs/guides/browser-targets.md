# CDP 浏览器目标

Core 使用已安装的 Edge/Chrome/Chromium 无窗口运行页面，画面显示在 Gamer 原有投屏区域。网址由目标配置提供；网站登录、排队、进入游戏和恢复流程留给用户或 YAML。

1. 在投屏工具条的「更多」中选择「新增浏览器目标」，填写名称、网址和视口尺寸；每个账号使用不同的资料 ID。
2. 选择目标并连接。Gamer 启动专用无窗口浏览器，在投屏区域显示连续画面，可发送鼠标、滚轮、键盘及粘贴文本。预览使用 CDP JPEG 连续帧：单屏最多 1920×1080、30 帧/秒；4 格最多 960×540、10 帧/秒；9 格最多 640×360、6 帧/秒，网格模式同时降低 JPEG 质量。底部显示实际帧率，页面静止时不重复传图。网页视口和输入坐标保持原始尺寸，自动化识别、截图与模板独立按需获取无损 PNG。
3. 登录产生新标签页时，使用「读取标签页」并明确选择。运行期间不能改绑。网页普通跳转仍使用原标签页；关闭页面不自动跟随其他标签页。网站弹出新标签页使当前投屏页面隐藏时，会恢复当前绑定页面的画面；新标签页保留供用户明确选择。
4. 选择配置包，在 YAML 面板运行已有识别和输入函数；任务页也可选择该浏览器目标并设置 cron。Android 应用名留空；配置包与目标账号互不推导。
5. 「断开」只关闭本页预览，后台任务和浏览器继续运行。「关闭浏览器」释放实例并保留登录资料；执行任务时拒绝关闭、改绑和手动输入。修改目标配置前先关闭浏览器。

浏览器路径可在服务端 `browser_path` 指定绝对路径，空值自动发现；无需 Node.js、Playwright 或下载 Chromium。资料存于 `<data_dir>/browser-profiles/<profile_id>/`，包括 Cookie、Local Storage 等完整浏览器数据，不随 Package 导出。目标删除保留资料；已有目标的资料 ID 不可更改，可新建目标复用已释放的资料 ID。网站是否要求重新登录由网站决定。

每个目标仅允许一个投屏页面控制；打开第二页前先断开旧预览。后台任务不依赖前端页面在线，服务重启后按目标配置重新准备浏览器，不自动续跑被中断的脚本。

“设置 → 浏览器空闲回收时间”可在没有预览、脚本、录制、采集或 AI 活动时自动关闭空闲浏览器，释放进程内存；默认 `0` 表示关闭回收，修改后立即生效。回收会保留账号资料，下次连接重新打开配置网址并使用新的帧身份；网站排队、未保存页面状态和正在页面内播放的内容会结束。需要保留云游戏排队时保持默认关闭，或设置符合使用需求的空闲时长；活跃或暂停中的 AI 会话不会被回收。

预览只保留最新一帧，前端加载确认后才发送下一帧，慢客户端不会无限积压画面。前端使用可释放的 Blob 图像，不持续保留 JPEG base64。断开投屏或隐藏目标会停止连续预览采集，保留账号登录和后台任务；重新显示时只恢复此前打开的预览。工作台不可见或浏览器标签页在后台时暂停全部预览。导航、改绑、尺寸变化仍会使旧画面的操作失效，原图捕获也必须验证服务端帧身份。实际帧率取决于页面变化频率、浏览器负载、网络和客户端解码能力，各模式的帧率是发送上限，不是云平台内游戏帧率的保证。

浏览器目标当前只提供图像预览，浏览器进程始终静音，单屏或多格都不会让网页声音直接从服务器扬声器播放。浏览器目标不能使用 Android 应用启停和数字键码，也不支持相对鼠标锁定；后台浏览器拒绝网页的 Pointer Lock 权限，防止云游戏把服务器桌面的真实鼠标限制在隐藏窗口内。仅支持强制锁鼠标的游戏操作仍需另外验证。不同云平台的无窗口视频、验证页面和游戏内输入仍需实际验证，不能仅凭网址可打开就认定兼容。

## 本机开发验收

使用独立 worktree、临时数据库/资料目录和 `127.0.0.1` 页面；不使用主仓运行数据。设置 `GAMER_LOCAL_ONLY=1` 与 `ADB_MDNS=0`，避免运行需要局域网监听的测试，不修改防火墙。实际浏览器测试默认 ignored，显式运行 `browser_roundtrip_isolation_navigation_and_profile_persistence`；普通编译和单元测试不会因此启动浏览器。

本次 schema 升为 v6，保留 Android 任务，新增长期浏览器目标并允许任务 Android 上下文为空。合并后首次运行新版本前遵循正常数据备份流程；旧版本不能读取 v6 数据库，回退需恢复升级前快照。
