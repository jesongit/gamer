# 插件与配置包的来源预设

插件页和配置包页分别提供“插件来源”和“配置来源”下拉框。内置 GitHub 与内网来源，可直接切换；只读取当前所选来源，不混合不同仓库的同名版本。

| 来源 | 插件 | 配置包 |
| --- | --- | --- |
| GitHub | `https://github.com/jesongit/gamer-plugins` | `https://github.com/jesongit/gamer-packages` |
| 内网 | `http://192.168.31.10:13000/posase/gamer-plugins` | `http://192.168.31.10:13000/posase/gamer-packages` |

## 添加自己的地址

1. 在对应页面点击“管理预设”。
2. 输入容易辨认的名称和来源 URL，点击“保存预设”。保存后即选用该来源。
3. 选中自定义预设后，可在管理区编辑名称、地址或删除。内置预设保持固定，其他服务器可另存为自定义预设。

预设保存到 Gamer 服务端，其他浏览器重新读取后也能使用。插件与配置包分别记住当前浏览器的选择；一个浏览器切换不会改变另一个浏览器的选择。删除预设不卸载插件、不删除配置包或业务数据。

支持公开 GitHub 仓库、Gitea / Forgejo 仓库以及静态目录。仓库地址可带 `.git` 后缀；静态目录分别提供 `registry.json` 和 `packages.json`，归档放在同一目录。GitHub 前缀镜像的配置包格式见 [配置仓库与发布](package-publishing.md)。

公共来源使用 HTTPS。局域网私有 IP 与回环 IP 可使用 HTTP；不接受来源 URL 中的账号、密码、查询参数或片段。读取公开来源无需令牌；目前不存储私有仓库认证信息。

## Git 源码与发行附件

推送 Git 提交和标签不会自动产生可安装的归档。来源仓库需要发布 Release：

- 插件 Release：`registry.json` 和目录中全部固定版本的 `.gplugin` 文件。
- 配置包 Release：`packages.json` 和目录中对应的 `.gamerpkg` 文件。

Gitea / Forgejo 的读取使用公开 Release API。归档从所选 Release 的实际附件地址下载，不会因为镜像目录仍写着 GitHub URL 就绕回 GitHub；固定大小与 SHA-256 校验仍然生效。没有目录附件时，界面会说明需要发布什么文件。

所有市场目录和归档由 Gamer 后端读取，再通过同源 API 返回浏览器，避免浏览器跨端口请求内网仓库。内网 HTTP 请求不使用公网代理；每次重定向均检查地址，公网 HTTP、凭据 URL 和 HTTPS 降级会被拒绝。

## 安装与错误处理

切换来源只更改可选版本，不自动更新现有安装。点击刷新会重新检查当前来源；请求迟到不会把旧来源的目录覆盖到新来源。

插件继续经过归档检查、权限确认和宿主能力门禁；配置包继续检查归档大小、SHA-256 和包内元数据，同 ID 覆盖仍需确认。自定义来源不会被记录成官方来源。

“URL 导入”用于单个 `.gplugin` 文件的下载地址。仓库 URL 应添加到来源预设，不能填进单包导入框。读取失败时可切回其他来源，已安装内容继续保留；官方 GitHub 来源仍保留随发行附带目录的离线回退。
