# Windows 启动器使用

完整包名为 `Gamer-<版本>-windows-x64-full.zip`，使用 SHA256 校验。在线安装下载同一 Release 的 `gamer-launcher.exe` 放入专用目录后运行；测试版启动器会发现已公开的 beta，稳定版仍只读取稳定发布入口。

完整包目前是离线安装布局：外层 ZIP 带齐各组件的压缩包（`seeds/`），第一次点击“安装 Gamer”才将它们校验并展开到 `versions/` 和 `runtime/`。这一步不需要重新下载这些组件；保留 seeds 可供后续离线修复。因此解开外层 ZIP 后仍有一次本地展开步骤。

## 第一次使用

1. 如果正在运行源码开发环境，先在仓库执行 `./gamer.ps1 stop`，释放默认 8443 端口。开发环境与发行安装的数据各自独立。
2. 将完整 ZIP **全部解压**到一个可写目录，例如 `D:\Gamer`。软件会安装在该目录；不要在压缩包内运行，也不要只复制 EXE。桌面入口可创建指向原 EXE 的快捷方式。
3. 双击解压目录里的 `gamer-launcher.exe`，在小窗口点击“安装”（另一按钮为“取消”）。完整包从自带 seeds 安装软件及 ADB、FFmpeg/FFprobe、scrcpy 等组件，不要求预装 Rust、Node 或这些工具。
4. 安装后勾选需要的官方插件，展开查看权限并点击“继续”；也可点“跳过”，后续在工作台插件页安装。
5. 浏览器打开工作台，首次设置至少 8 位管理员密码；以后用该密码登录。默认地址为 `http://127.0.0.1:8443`。

个人配置包可通过开发环境的导出和新安装工作台的导入转移；完整包不会自动携带当前仓库的脚本、数据库、媒体或密码。

## 日常使用

| 操作 | 行为 |
| --- | --- |
| 再次双击启动器 | 在后台检查；已安装、健康且无可用更新时直接打开网页并留在托盘，不先弹启动器窗口 |
| 发现更新 | 小窗口只显示“更新 / 取消”；取消收起窗口、不启动本体，也不会停止原本已在运行的本体 |
| 下载中断 | 小窗口用“暂停 / 继续”；安装中“取消”会请求安全结束并退出，保留可恢复进度 |
| 关闭启动器窗口 | 收到右下角托盘，后台服务继续运行 |
| 再次打开界面 | 双击 EXE、双击托盘，或右键托盘选择“打开 Gamer”：运行时打开网页；安装、更新、暂停或出错时显示对应窗口 |
| 文件异常 | 启动时自动校验并修复缺失或损坏的文件；错误时显示小窗口，可重试；完整维护可在退出后运行 `./gamer-launcher.exe repair --probe` |
| 完全退出 | 托盘选择“退出 Gamer”，关闭浏览器或运行中的启动器窗口不会停止后台服务 |

`0.2.0` 正式版启动器支持工作台“设置 → 软件更新”的实际版本切换；失败时自动恢复原版与升级前的数据快照。安装采用已经下载并确认的版本，期间发布源出现更新不会改变候选。beta.4 及更早启动器需要先通过启动器完成这次升级，旧版网页安装入口只会校验下载内容；beta.5 保留为未公开草稿。

插件页默认独立检查官方插件仓库发布，不必等本体发布才能看到兼容的新插件版本。点击“刷新”立即检查；网络失败时显示缓存或本体附带列表。选择安装或更新后仍需确认权限，归档经过大小与 SHA256 校验；不会自动覆盖已安装插件。插件新增宿主原生能力时仍需配套升级 Gamer。

配置在安装目录 `config/config.toml`，运行数据在 `data/`，日志在 `logs/`。不要删除这些目录后期待启动器恢复个人数据。

常规窗口为 440×250 逻辑像素；首次插件选择为 440×320，权限按需展开，长信息在内容区滚动，底部按钮固定可见。Windows 缩放设置会影响实际屏幕像素大小。托盘仅保留“打开 Gamer / 退出 Gamer”；主动检查更新在工作台“设置”里。

需要同时运行开发版与发行版时，先在发行安装的 `config/config.toml` 将 `port = 8443` 改成空闲端口（如 18443），再启动发行版。无需改 ADB/FFmpeg/scrcpy 路径，启动器会按清单注入。

`gamer.ps1` 继续用于当前仓库的开发服务管理；发行安装的启停和更新使用其自己的启动器。脚本隔离回归可运行 `./tools/test-gamer-process-scope.ps1`，测试使用模拟进程，不停止真实服务。

如果提示目录切换“拒绝访问”，检查是否有开发预览、文件监听器或其他程序占用安装目录，关闭对应程序后重试；不要直接删除个人数据。曾有以整个仓库为根的临时 Vite 预览占用 `release/dist` 内的安装 staging，停止该预览后原目录即可正常安装。

## 官方插件来源

本体与依赖从 Gamer Release 下载；首次可选的官方插件合集从 `gamer-plugins` 的固定版本 Release 下载，版本和 SHA256 由本体发行清单锁定，不随远端最新提交漂移。完整包携带同一份插件归档，无需联网即可安装。软件内插件页通过宿主独立发现插件仓最新公开目录，按通道筛选，缓存五分钟；手动刷新立即检查，网络失败回退缓存和发行快照。目录发现不会自动安装或更新插件。

正式官方插件为 `0.1.0`，公开 beta 可正常升级；此前 1.x/3.x 为内部开发编号。已有内部测试安装不会自动降级插件；请先导出配置包，保留数据，卸载旧测试插件后再安装本次版本。

## 本机测试与防火墙提示

`0.2.0-beta.6` 起可在安装目录的 `config/config.toml` 顶层设置 `local_only = true`，或启动前临时设置 `$env:GAMER_LOCAL_ONLY = '1'`。HTTP 和 WebRTC 都仅使用回环地址，本机浏览器与 USB ADB 仍可使用；其他电脑不能访问该实例。该选项不能与 `rtc_external_ip`、`rtc_udp_port`、`rtc_external_port` 的非默认值同时使用。

需要其他电脑通过局域网访问时，保持 `local_only = false`。Windows 可能为 `gamer-server.exe`
显示网络访问许可提示；在可信的家庭或办公网络上，可仅允许“专用网络”，不要为了消除提示关闭防火墙。
Gamer 不会自动添加放行规则。当前服务端位于 `versions/<版本>/gamer-server.exe`，升级后程序路径
变化可能再次触发询问，现阶段不保证跨版本只询问一次。参见 [Microsoft 的防火墙说明](https://support.microsoft.com/en-us/windows/security/windows-security/firewall-and-network-protection-in-the-windows-security-app)。

发行验收脚本默认临时开启此选项，启动器会将它传递给普通、升级及回滚服务。Windows 按 EXE 完整路径匹配程序规则，反复解压到新测试目录会产生新程序提示；仅本机测试无需对局域网开放监听，也无需关闭系统防火墙通知。旧版本尚不支持此开关，跨版本回归仍可能触发旧 EXE 的一次提示。

ADB 的 mDNS 无线自动发现是独立的网络服务，不受 `GAMER_LOCAL_ONLY` 控制。本机/USB 验收在首次运行 ADB 前设置 `$env:ADB_MDNS = '0'`，或用仓库的 `tools/prepare-test-adb.ps1 -AdbPath <adb.exe绝对路径>` 预启动并检查；USB 和显式 IP 连接仍可用，但不自动发现无线设备。已有 ADB 服务不会因客户端环境变量变化而重新配置，应先确认没有用户会话再安全重启。beta.6 启动器尚不透传此变量，测试旧包需预启动已禁用 mDNS 的同版本 ADB；0.2.0 正式版启动器会保留显式 `ADB_MDNS` 设置。
