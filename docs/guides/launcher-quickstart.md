# Windows 启动器使用

本次预发布版本为 `0.2.0-beta.2`，完整包为 `Gamer-0.2.0-beta.2-windows-x64-full.zip`，使用 SHA256 校验。在线安装下载同一 Release 的 `gamer-launcher.exe` 放入专用目录后运行；测试版启动器会发现已公开的 beta，稳定版仍只读取稳定发布入口。

完整包目前是离线安装布局：外层 ZIP 带齐各组件的压缩包（`seeds/`），第一次点击“安装 Gamer”才将它们校验并展开到 `versions/` 和 `runtime/`。这一步不需要重新下载这些组件；保留 seeds 可供后续离线修复。因此解开外层 ZIP 后仍有一次本地展开步骤。

## 第一次使用

1. 如果正在运行源码开发环境，先在仓库执行 `./gamer.ps1 stop`，释放默认 8443 端口。开发环境与发行安装的数据各自独立。
2. 将完整 ZIP **全部解压**到一个可写目录，例如 `D:\Gamer`。软件会安装在该目录；不要在压缩包内运行，也不要只复制 EXE。桌面入口可创建指向原 EXE 的快捷方式。
3. 双击解压目录里的 `gamer-launcher.exe`，在小窗口点击“安装”（另一按钮为“取消”）。完整包从自带 seeds 安装软件及 ADB、FFmpeg/FFprobe、scrcpy 等组件，不要求预装 Rust、Node 或这些工具。
4. 安装后勾选需要的官方插件，展开查看权限并点击“继续”；也可点“跳过”，后续在工作台插件页安装。
5. 浏览器打开工作台，首次设置至少 8 位管理员密码；以后用该密码登录。默认地址为 `http://127.0.0.1:8443`。

个人配置包可通过开发环境的导出和新安装工作台的导入转移；完整包不会自动携带当前仓库的脚本、数据库、媒体或密码。

## 日常使用

| 操作 | 行为 |
| --- | --- |
| 再次双击启动器 | 在后台检查；已安装、健康且无可用更新时直接打开网页并留在托盘，不先弹启动器窗口 |
| 发现更新 | 小窗口只显示“更新 / 取消”；取消收起窗口、不启动本体，也不会停止原本已在运行的本体 |
| 下载中断 | 小窗口用“暂停 / 继续”；安装中“取消”会请求安全结束并退出，保留可恢复进度 |
| 关闭启动器窗口 | 收到右下角托盘，后台服务继续运行 |
| 再次打开界面 | 双击 EXE、双击托盘，或右键托盘选择“打开 Gamer”：运行时打开网页；安装、更新、暂停或出错时显示对应窗口 |
| 文件异常 | 启动时自动校验并修复缺失或损坏的文件；错误时显示小窗口，可重试；完整维护可在退出后运行 `./gamer-launcher.exe repair --probe` |
| 完全退出 | 托盘选择“退出 Gamer”，关闭浏览器或运行中的启动器窗口不会停止后台服务 |

配置在安装目录 `config/config.toml`，运行数据在 `data/`，日志在 `logs/`。不要删除这些目录后期待启动器恢复个人数据。

常规窗口为 440×250 逻辑像素；首次插件选择为 440×320，权限按需展开，长信息在内容区滚动，底部按钮固定可见。Windows 缩放设置会影响实际屏幕像素大小。托盘仅保留“打开 Gamer / 退出 Gamer”；主动检查更新在工作台“设置”里。

需要同时运行开发版与发行版时，先在发行安装的 `config/config.toml` 将 `port = 8443` 改成空闲端口（如 18443），再启动发行版。无需改 ADB/FFmpeg/scrcpy 路径，启动器会按清单注入。

`gamer.ps1` 继续用于当前仓库的开发服务管理；发行安装的启停和更新使用其自己的启动器。脚本隔离回归可运行 `./tools/test-gamer-process-scope.ps1`，测试使用模拟进程，不停止真实服务。

如果提示目录切换“拒绝访问”，检查是否有开发预览、文件监听器或其他程序占用安装目录，关闭对应程序后重试；不要直接删除个人数据。曾有以整个仓库为根的临时 Vite 预览占用 `release/dist` 内的安装 staging，停止该预览后原目录即可正常安装。

## 官方插件来源

本体与依赖从 Gamer Release 下载；首次可选的官方插件合集从 `gamer-plugins` 的固定版本 Release 下载，版本和 SHA256 由本体发行清单锁定，不随远端最新提交漂移。完整包携带同一份插件归档，无需联网即可安装。软件内插件页使用该发行快照的同源副本；独立插件新版本的动态市场发现尚未接入。

首次公开插件为 `0.1.0-beta.1`，此前 1.x/3.x 为内部开发编号。已有内部测试安装不会自动降级插件；请先导出配置包，保留数据，卸载旧测试插件后再安装本次版本。
