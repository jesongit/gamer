# 运行依赖

打开“设置 → 运行依赖”。ADB、FFmpeg/FFprobe、云游戏浏览器、Tesseract、简体中文/英文模型统一显示状态、来源、路径与生效时机。scrcpy-server 随应用协议版本固定，不能独立更新。

程序启动时检测所需工具。有效的指定路径优先；自动模式复用兼容的现有工具，缺失时安装锁定版本到 Gamer 的 `runtime/<id>/<version>/`。不修改系统 PATH、注册表或服务，不调用系统安装器，不覆盖用户软件。下载经过 SHA256、大小和安全解包检查，探测成功后原子发布。已有版本保留，损坏的同版本目录也不会被静默覆盖。

如果指定路径失效，修正路径或留空保存，恢复自动检测。ADB/FFmpeg 与已启动的浏览器连接采用启动时绑定的路径，更换选择后按界面提示重启；OCR 下次调用采用新设置。启动准备在后台完成；识别和任务执行路径不触发下载。

Windows x64 支持 ADB、FFmpeg、浏览器与 OCR 自动准备；Linux x64 可自动准备独立浏览器，语言模型在各平台可下载。Linux Docker 镜像在构建时安装所有运行工具，服务启动主要验证，不在容器里执行 apt 或 sudo。其它平台优先使用已有工具，缺少受验证自动安装源时显示明确原因。

OCR 的旧私密配置复制到 `data/state/ocr/settings.dat`，保留加密字节及随附密钥，原 `extension-data/gamer-ocr/private/` 不删除、不改写。旧插件安装、配置包、运行记录与账号资料保留；历史 OCR 插件不可执行，新识别不再依赖其启用状态。损坏或无法解密的配置明确报错，不能当成空配置丢弃。

Core MCP 显式提供 `gamer.core.ocr_status`（`ocr.read`）与 `gamer.core.ocr_recognize`（`ocr.recognize`）。原插件 scope 不自动升级为新权限，需要重新签发/调整令牌。授权图片来源、设备/配置包/运行/素材范围与撤销取消约束继续生效。安装软件和修改路径仅开放给管理界面。

安装失败可继续使用原软件/旧镜像；先修正设置或恢复配置备份。升级 Docker 时复用原数据卷，切勿重新初始化或重新激活调度。
