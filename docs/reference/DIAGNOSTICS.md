# 生产诊断与数据保留

此改造先在本地构建与隔离数据中验证。部署中的 Docker v1.0 不会因源码变化而更新，生产卷不作为测试目录。
后续切换生产前，应先停机制作完整备份并在独立卷验收。回滚使用旧镜像与对应备份新建卷；
旧 v1.0 仍按旧保留周期清理，不能把旧镜像直接指向新版唯一数据卷作为保留策略回滚。

## 默认取舍

| 数据 | 新运行的默认策略 |
| --- | --- |
| 运行摘要及版本身份 | 365 天 |
| 成功运行详细事件 | 14 天 |
| 失败/取消运行详细事件 | 30 天 |
| 成功图像 | 采集中每 10 秒最多一张普通观察图，完成后最多 5 条关键图像记录，24 小时 |
| 失败/取消图像 | 保留采样上下文、实际失败判断帧和成功取得的新截图，168 小时 |
| 临时图像容量 | 总计 512 MiB，单次 64 MiB；时间窗口同时受容量限制 |
| 手动保留的图像证据 | 独立 256 MiB、最多 10 次；超限拒绝新保留，不自动删除已有保留 |
| 普通系统日志 | `log_retain_days=14`；Docker stdout 由日志驱动按容量滚动 |

任务/账号/凭据、配置包、脚本/模板、全部工作稿版本、发布事务、不可变安装版本、媒体和独立素材
不属于本策略的自动清理对象。退休插件的原始私密数据不处理。

示例配置（需重启，`log_retain_days` 仍走原系统设置热更新）：

```toml
[diagnostics]
summary_retain_days = 365
success_detail_retain_days = 14
failure_detail_retain_days = 30
aggregate_repeated_events = true

[trace]
production = true
capture_interval_ms = 10000
success_max_images = 5
retain_hours = 24
failure_retain_hours = 168
global_max_bytes = 536870912
run_max_bytes = 67108864
run_max_images = 1000
error_reserve_bytes = 16777216
queue_capacity = 4
min_observation_ms = 1000
retained_max_bytes = 268435456
retained_max_runs = 10
```

`diagnostics` 天数为 0 表示关闭对应到期清理；缩短摘要期限仍会随摘要删除关联事件。
不要把摘要期限配置得短于希望保留的详细事件期限。开发或专门复现时可设 `trace.production=false`，
恢复逐条图像记录；错误优先通道和容量限制仍有效。`trace(false)` 保持原语义。

## 旧数据保护

新运行记录与 Trace manifest 带独立的策略版本。未标记以及未知版本的历史记录/图片不进入新策略的
自动到期、配额淘汰和成功精简；已有索引和像素不重写。新配额只统计当前策略管理的临时证据，
因此磁盘总量还会包含原始旧证据，不能把新配额当成整个数据卷大小上限。

第一次以新版打开数据库时，原有 `logs` 最大 ID 写入 `diagnostics-policy.json`；该水位前的原始
文字日志不自动删除，后续新日志继续按 `log_retain_days` 清理。水位随备份/迁移保留，重启不重置。
文件不存在时用新临时文件原子创建；状态损坏时拒绝加载而不猜测或覆盖。传统滚动日志文件的原有
日期策略不变；本轮没有打开或清理任何真实安装。旧资料归档是后续独立动作，不在启动时执行。

SQLite 表结构仍为 v7，没有为本改造迁移用户表。清理和测试只在隔离数据库上执行。

## 图片、队列与真实性

生产采样在 PNG 编码/写盘前覆盖普通匹配、操作前后、补充观察和 OCR 图像；开关边界、结束记录和
错误现场单独处理。自动化本身需要的截图与匹配不被跳过；没有额外持续截图循环。
每次匹配或 OCR 实际消费仍更新有界的“最后判断帧”引用，失败时使用该帧本来的时间/FrameStamp/模板，并在重新
取得现场时另存 `error_fresh`，不把事后截图当作此前的判断依据。

普通图像使用原有有界队列。两种根错误图使用独立的 8 槽优先通道，并保留单次图像/元数据容量；
生产普通采集不占用单次 `error_reserve_bytes` 和全局最后四分之一空间。错误证据也有上限，
磁盘失败、异常尺寸、优先队列满或所有预算耗尽时明确记录 gap，不能保证无限故障下仍保存全部图片。

成功后保留首张及最近的图像记录，包括能留下的结束前实际观察帧；先提交精简索引，再删除新策略
拥有且不再引用的 PNG。保留 seq/image_id/采集时间，不重编号或换图。全局超限优先淘汰已结束成功运行，
之后才淘汰已结束失败运行；不淘汰活动运行或手动持久副本。

API/UI 显示采样次数、成功精简数量、当前 image_ids、到期与缺口。没有截图不代表没有操作；
客户端会移除服务端已精简的旧 image_id，不用其他截图补齐。

## 高频事件

只合并相同执行身份、模板及其余字段完全相同的连续 `vision found=false`，允许分数变化。
第一条立即持久化；一个合并组最多覆盖 2 秒/1024 条观察，记录额外观察次数、首末时间、
这组额外观察的最高分和末次结果。在后续事件到达、查询/导出或正常关闭时冲刷。

最多为 64 次运行保留缓冲；所有输入、命中、错误、步骤/调用边界及 producer-owned detail 原样保存。
不修改已经发出的事件 ID，因此游标不会漏掉摘要更新。突然崩溃可能丢失一个尚未冲刷的重复观察组，
第一条观察及已完成的关键事件不依赖缓冲。未保存的现场不会被重造。

超出 128 KiB 的单条事件会显式截断并保留原始摘要指纹，避免任意字段绕过数据大小限制。

## 单次运行诊断包

管理界面在已结束运行提供“下载诊断包”：顶部“任务”页找到对应任务，在“最近运行”栏点“查看日志”，
选择一条已结束记录即可下载；自动化插件的运行详情也有同名入口。同源原生下载不在浏览器 JavaScript 中完整缓冲 ZIP。
`GET /api/runs/:run_id/diagnostics` 复用现有管理认证，拒绝活动运行；不开放新的 MCP 工具或控制权限。

- `run.json`：精确 run/task/device/entrypoint、终态、错误、冻结的宿主/源码/模板/实际 WASM 指纹。
- `events.jsonl`：该次运行的脱敏事件，最多 16 MiB；到期或截断会明确注明。
- `trace.json`：实际图像/模板关系、采集时间、FrameStamp、采样、缺口、文件 SHA-256。
- `assets/`：该次运行的原始无损 PNG，优先导出错误现场，最多 128 MiB。
- `manifest.json`：包格式、导出工具版本、是否截断、遗漏原因与文件校验值。

不读取整个数据库、浏览器 profile、Cookie、私密插件配置或安装密钥。参数、返回值、敏感键和常见
凭据文本被脱敏，源码正文留在本地，用冻结指纹关联；任意自由文本不可能保证自动识别所有秘密，
截图本身也可能包含账号/游戏信息。原始数据和本地 Trace 不因导出而改写。

服务端一次处理一个诊断下载，临时文件按 64 KiB 流式输出；结束/断开后删除本轮临时包。
缺少的历史、图像或超出导出预算的内容在包内注明；不以别的任务或全局最近一次运行替代。
