# 自动化与函数

自动化功能由 `gamer-yaml` 提供。先选择设备、Android 应用和配置，再打开工作台的「自动化」。

## 创建第一个脚本

新建脚本，依次添加启动应用、等待、点击和日志步骤，也可以在原文编辑中使用：

```yaml
name: 第一次运行
run:
  - launch: {}
  - sleep: 2s
  - tap: [0.5, 0.8]
  - log: 操作完成
```

`launch: {}` 使用设备当前选择的 Android 应用。点击坐标只是示例，运行前请改为目标画面中的位置。

保存后从头运行，观察画面和状态条。需要局部调试时，可以使用步骤上的“从此运行”；前面步骤产生的变量不会因此自动补齐，依赖这些变量的步骤仍需从相关入口运行。

## 步骤编辑

添加步骤时选择函数或流程结构。函数参数由 schema 提供：无默认值的必填参数直接展示，可选参数通过展开入口编辑；返回值使用同一类内联入口设置。

模板参数从当前配置的模板列表中选择。步骤折叠后可以使用图标操作；展开后填写参数，修改顺序时注意变量依赖。

运行前保存并查看校验结果。结构化错误通常包含步骤位置与原因，状态条提供详情或定位入口。

## 函数与流程结构

步骤有四类：函数调用、`if`、`repeat`、`return`。`tap`、`sleep`、`find` 等是函数。

原生函数和当前配置内的函数库共同组成调用列表，同名冲突会被拒绝。可复用的流程放在「函数」中，使用与自动化一致的可视化画布编辑和测试。

函数库存放在 `automations/_function*.yaml`，默认文件是 `_function.yaml`。函数调用使用函数名，移动定义文件不会改变调用名。重命名或删除函数前，需要先处理其他脚本中的引用。

## 参数和返回值

脚本的 `params` 定义运行参数。保存运行结果使用步骤上的 `as`，后续用 `$变量名` 或 `$变量名.字段` 访问。比如找图返回值为 `null` 时，应先通过 `if` 判断再读取 `.center`。

完整案例见 [YAML 案例教程](../guides/yaml-tutorial.md)，字段与表达式规则见 [YAML V1 参考](../reference/YAML.md)。
