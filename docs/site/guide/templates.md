# 模板与图像匹配

模板是自动化寻找画面元素时使用的图片，由 `gamer-yaml` 管理，保存到当前配置包。

## 创建模板

可以从实时投屏框选，也可以上传图片。使用视频分析时，先定位到指定帧，再框选提取模板。保存视频模板时使用选定帧，不会重新抓取设备当前画面。

选择有辨识度且布局稳定的区域：按钮文字与边缘通常比大面积纯色背景更容易区分。避免把经常变化的数字、动画或高光作为唯一依据。

模板保存时会归一化为灰度 PNG。修改模板后，在当前场景测试匹配分数与位置，再投入实际脚本。

## 在脚本中使用

```yaml
run:
  - wait_find:
      template: 确认.png
      timeout: 5s
    as: button
  - if: $button
    then:
      - tap: $button.center
    else:
      - log: 等待超时，未找到确认按钮
```

先在当前配置中创建 `确认.png`。`find` 只查找一次；`wait_find` 会等待出现；`tap_template` 找到后点击；`wait_disappear` 等待消失。超时未命中与模板文件不存在是不同结果，后者需要修复资源引用。

## 调整匹配

- **搜索区域**：尽量限制到元素可能出现的位置，减少误匹配。
- **阈值**：结合命中分数调整，过低容易误判，过高可能漏掉轻微变化。
- **分辨率与缩放**：画面、模板和应用布局应保持一致；虚拟屏能减少适配差异，但不能消除应用自身的缩放。

模板名称可以携带搜索区域后缀，脚本可通过唯一短名引用。具体后缀、参数和返回值见 [YAML 案例教程](../guides/yaml-tutorial.md)。

重命名模板通过界面完成，插件会同步处理可识别的脚本引用。资源保存遇到版本冲突时，先比较当前内容，避免覆盖其他编辑。
