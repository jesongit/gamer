# 任务与日志

任务将调度方式、执行入口、参数和设备组合起来。脚本描述流程，任务决定何时、在哪运行。

## 创建任务

1. 在「任务」页新建任务，选择目标设备。
2. 选择调度方式，内置方式为 `cron`。
3. 选择执行器与入口。使用 YAML 自动化时，先确保 `gamer-yaml` 已安装并启用。
4. 选择配置中的脚本，填写运行参数，保存任务。
5. 先手动运行一次，确认设备、应用和资源正确后再启用调度。

Cron 以服务端本地时区执行。浏览器关闭后任务仍由服务端调度；电脑休眠或服务停止时不会继续执行。

修改时间应在任务页保存，或使用正常 API/MCP 保存入口；不要直接修改 SQLite 的 `schedule_json`，否则旧 `next_wakeup` 仍可能执行一次。仓库维护工具 `tools/gamer_change_cron.py` 使用已有 MCP 令牌，先按服务端时区预览，再以 `expected_updated_at` 做快照 CAS 保存，保留多输入、并发和通知配置；默认只读，追加 `--apply` 才保存，不会立即运行任务：

```sh
python tools/gamer_change_cron.py --url http://127.0.0.1:8443/api/mcp --token-file /private/gamer-mcp-token --task-id <任务ID> --expected-expression "17 4 6 * *" --expression "0 5 6 * *"
```

令牌需要 `task.read`、`task.write`，修改已启用任务还需要 `run.submit` 及所有输入目标的对象授权；保留正常外部执行权限策略。工具显式提交多输入字段，旧宿主不支持时会拒绝保存。遇到并发冲突应重读任务，写请求断线等结果不明时不要自动重试。

## 执行状态

同一设备同时只允许一个活动运行，避免不同流程争抢输入。设备忙时请求可能被拒绝，先查看当前运行。

插件缺失或停用时，依赖它的任务会保留并显示依赖缺失。恢复对应插件后，任务可重新获得执行能力。

任务编辑页还可配置「运行结果通知」，选择成功、失败、取消、跳过等结果对应的通道与消息。通知默认关闭；通知助手未安装或停用时，配置仍可保存，通知跳过且不改变任务的执行结果。通知是可选能力，不会让任务变成依赖缺失。通道配置、脚本中的 `notify` 函数及升级说明见 [通知助手](../guides/notifications.md)。

脚本参数变化后，任务会按当前定义重新绑定：已有有效参数保留，新参数使用默认值，缺少必填值时需要补齐。不要假设历史任务保存的参数永远适用于新版脚本。

## 查看日志与报错

「日志」页用于筛选和查看服务端运行记录。工作台状态条用于当前步骤、结果和错误的轻反馈；有定位信息时可跳到对应资源或步骤。

排查时先确认：运行对应的设备和配置、脚本保存版本、首个失败步骤与详细原因。资源在运行开始后发生变化时，错误位置可能不适用于当前编辑内容，应先核对版本。
