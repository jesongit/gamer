# CDP 连续预览验收（2026-09-27）

## 变更

原预览每 500ms 调用一次 `Page.captureScreenshot` 输出 PNG，理论上限约 2fps，复杂 1080p 页面单次截图约半秒。现在预览采用 `Page.startScreencast` 的 JPEG 连续帧，质量 80、保留原视口尺寸，发送上限约 30fps。识别/模板匹配的 `capture()` 仍独立获取无损 PNG；没有新增视频编码器、外部服务或运行时依赖。

CDP 接收侧即时确认帧、用 watch 通道只保留最新图像；WebSocket 每次只允许一张未确认显示的画面，前端 img 加载确认后才发下一张。输入优先处理。断开停止连续采集；导航/坐标变化使旧 FrameStamp 失效并重新请求画面。相同映射的下一帧加载期间保持键鼠可用，防止高帧率下频繁阻断输入。底部显示实际预览帧率，静止页面提示等待更新。

## 本机测量

使用本机已安装 Chrome/Edge，无窗口、独立资料目录、临时目标。页面为本地 `127.0.0.1` 的 1920×1080 动画、按钮和文本框，不涉及云账号或游戏。后端设置 `GAMER_LOCAL_ONLY=1`、`ADB_MDNS=0`，不启动测试用 Android/ADB 连接，不修改防火墙。

- Rust 直接 CDP：2.01 秒收到 99 帧；消费侧保留最新帧，积压不随时间增长。
- 完整 UI（隔离 8444）：约 30fps，点击注入约 31ms、投屏画面反馈约 129ms。机器同时编译/运行测试时另一次约 20fps，说明该数字不是性能保证。
- 实际开发链路 `localhost:5173 → 127.0.0.1:8443`：约 30.3fps；点击注入约 40ms、投屏反馈约 126ms；输入 `123` 到页面值约 30ms、投屏文字显示约 102ms。JSON 帧消息平均约 24.9KB（简单动画场景）。
- 最终 Release 重启后在同一开发链路复测：约 30.27fps，点击注入约 29ms、投屏反馈约 99ms，输入页面值约 30ms、投屏文字显示约 96ms，无前端或输入错误。
- 完整 UI 验证通过后，原始预览客户端暂停 ACK 700ms：仅收到一帧，同时发送按键仍成功；恢复 ACK 后收到最新帧。导航后携带旧 stamp 的按键被拒绝，目标文本没有改变。
- 预览与无损截图并用、按键/文本输入、停止后重新连接静态页面、目标隔离、标签页改绑、资料持久化均通过实际浏览器测试。

以上延迟为本机抽样，包含本地测试驱动和读回开销；不是网络云游戏端到端时延。未进入真实云游戏，游戏内帧率、音频、相对鼠标和受保护视频不在本次验收范围。

## 用户复测

刷新 `http://localhost:5173/`，选择原浏览器目标并重新连接。在有动画的页面观察投屏底部帧率，再试点击、键盘和粘贴。页面静止时不重复推图；不要把静止页面的低更新率当成游戏帧率。自动化识别和定时任务仍使用原有入口。
