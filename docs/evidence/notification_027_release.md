# 通知能力 0.2.7 发行验收

2026-10-01。通知能力合并远端已发布的宿主 0.2.6 和配套插件后，采用宿主 0.2.7、通知助手 0.1.0、自动化 0.1.3。原始隔离联调记录见 [开发构建验收](notification_026_acceptance.md)。已有公开版本与标签不覆盖。

- 合并后前端 1,154 项测试和生产构建通过，覆盖新增任务通知、可选通知函数及原有编辑器回归。
- 文档网站构建通过，通知入口、升级说明和消息模板字面量实际生成到 HTML；构建日志无页面渲染异常。
- Windows Clippy 全目标、全 feature、`-D warnings` 通过。原生调用名称与 JSON 参数成对传递，存储路径参数使用 Path 切片；不压制门禁警告。
- 六个插件本地构建、自检与独立 CI 构建通过。键盘映射 0.1.4、视频 0.1.2、直播 0.2.5、配置包发布 0.1.0 的 CI 归档与公开版本逐条目内容一致，复用其已发布字节。
- 初次 Windows 全量回归发现 WASM 测试缓存中的 wit-component 归档损坏；仅清理该 package 的 release 缓存后，18 项真实 WASM 回归通过。离线视觉测试原使用发行 LGPL FFmpeg 未包含的 libx264，夹具改用内置 MPEG-4；最终全量回归另行核对。

SDK 仍固定到包含通知能力的宿主提交 95c666403fa30d902f52e637ffec7e4cb10d3b00，七份接口文件哈希与宿主一致。最终发行必须使用通过 CI 的插件完整快照，再更新主仓公开资产锁；本地候选或未公开草稿不替代发行锁。

Windows 最终回归：765 项先通过；另外六项媒体夹具需要 libx264，使用与发行依赖同月份的独立 BtbN 测试构建补验后六项全部通过（下载按 GitHub 提供的 SHA256 校验）。771 项有效测试完成，17 项按原有环境条件忽略；测试工具只在 target 下，发行 FFmpeg 锁与 LGPL 构建未改动。Linux 宿主 CI 已通过版本、格式、严格 Clippy、无 WASM 路径、完整测试、正式 guest 校验和 release 构建，文档及前端 CI 通过。

已有用户升级路径检查：旧更新器在停服前拒绝已安装插件扩权，且旧宿主不能检查 notify.send。文档和发行说明明确：先备份，空闲时卸载自动化的全部已安装版本（保留数据，直到显示未安装），更新宿主后重装并确认；或停服后迁入新的完整包。卸载当前版本会回退到剩余版本，仅禁用也不能解除更新门禁。配置包资源与任务保留，迁移仍由新宿主启动完成，不修改旧安全门禁或静默授予权限。
