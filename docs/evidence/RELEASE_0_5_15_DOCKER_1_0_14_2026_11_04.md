# Gamer 0.5.15 / Docker v1.0.14 发行：定时任务多输入与并发（2026-11-04）

- 需求：定时任务支持「多个输入 + 并发数量（默认 1）」；线上 4 个「云游戏日常」任务（155/188/136/173，cron `1 4 * * *`）合并为 1 个多输入任务（并发 2），任务通知合并为一条。
- 实现：`Task` 新增 `inputs`（runner 私有对象数组，Core 校验对象形态/`id` 非空/≤64 条/单条 ≤16KiB；gamer-yaml 输入支持 `device_id` 覆盖）与 `concurrency`（默认 1，上限 64）。`TimerCore::dispatch_multi` 按输入×payload 浅合并并发派发，信号量许可覆盖运行全生命周期（完成回调释放）；`MultiFinisher` 在全部输入终态后写 `result_summary_json`、折叠 `last_result`（成功/部分成功 k/n/失败）并经既有 result_hook 发出单条聚合通知（gamer-notify 模板新增 `summary.total/success/failed/lines`）。`submit_now_multi` 让「立即运行」派发全部输入。
- 数据：SQLite schema v7→v8（`inputs_json`/`result_summary_json`/`concurrency`，逐列幂等 ALTER）；`release/contracts/schema-policy.md` 与 `manifest-v2.md` 的取值表同步（min/max/target=8）。
- 前端：TaskBoard 设备区改为多输入行编辑（添加/删除输入行 + 每行设备与备注 + 并发输入框），列表对多输入任务显示「×N 输入 · 并发 M」徽标；保存 body 携带 `inputs`/`concurrency`，客户端校验重复设备与目标类型混用。
- 宿主测试：服务端 1221 通过 / 0 失败（rate_limit 一例为并发跑全量的环境抖动，单独复跑通过）；Web 893 通过 / 0 失败（含新增多输入保存 body 用例）。
- Docker 镜像：干净 Git 归档 `25c34c6ed70952b0d298897d41bbf21f16270ac2` + pinned submodule `493a1b551022d8a4384aa34796cc44bb1586fbb3`（插件仓 gamer-notify 聚合摘要变量），linux/amd64。`posase/gamer:v1.0.14` 与 `latest` 摘要均为 `sha256:4ca7d41220194128ccb7f9e72da07a2e29730ee357aa735786e07a00e61c7c92`，目标服务器匿名拉取核对一致。
