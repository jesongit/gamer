## 部署交付与资源边界

发布提供 `gamer-docker-v1.0.1-amd64-deploy.zip`、固定摘要回执、YAML 0.3.23 归档及 SHA256SUMS。
部署 ZIP 为 454,610 bytes、10 个条目，SHA-256
`a5c3e9e1ae5abd98292ba48b4be93db49ff5d8ad2f60a1e2e1efab56a304f6e9`；逐项清单与 CRC 自检通过，
恢复 shell 在新镜像中 bash -n 通过。Docker Hub 仓库说明已更新并匿名读回与源码一致。
恢复脚本使用上面的不可变摘要，拒绝非空卷，默认关闭调度；确认账号后单独 activate。
所有启动操作使用 docker run，不依赖 Compose；保留原数据卷、旧镜像及独立回滚点。

主机迁移工具在当前生产卷只读统计：包含 3,457,761,142 bytes / 3,429 文件，
省略 8,763,704,866 bytes / 13,446 文件；这是压缩前的运行中估算，正式停机包以实际结果为准。
省略仅明确的本机备份、上一平台原副本、本机排查副本和浏览器缓存，未知目录和应用历史保留。
本轮没有停止生产导出实际账号数据、没有更新本机生产容器、没有执行新的日常任务。

构建使用单 Cargo job；这次 BuildKit 编译 cgroup 另设 6 GiB 上限和 4 GiB 回收阈值，
未发生 OOM。该临时 cgroup 随构建完成消失，不是生产容器参数。备份/恢复辅助容器继续限制为 512 MiB。
WSL 的 8 GiB / 4 GiB swap 为另行授权的主机配置，不属于项目业务配置。

详细本机回执位于 `server/target/docker-release-v1.0.1/`；公开摘要位于 `deploy/docker/releases/v1.0.1.json`。
真实目标机迁移、出口 IP 变化后的登录、新一天全部任务分支、ARM64 与 Android USB/投屏不在本次新镜像验收范围内。
