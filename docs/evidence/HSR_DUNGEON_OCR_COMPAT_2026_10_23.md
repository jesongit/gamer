# HSR 副本数值 OCR 兼容性验收（2026-10-23）

结果：用户新提供的 14 张截图与 18 张历史实际帧，在 Windows Tesseract 和隔离 Linux Tesseract 下均准确返回副本布局、当前体力/上限、单次消耗、当前次数和次数上限。相同 14 个边界场景均通过；这不是线上设备或整套日常验收。

## 问题与改动

失败运行 `021bb533-163c-4b94-9624-439049f7ed2f` 停在历战余响，实际体力 `247/300`，旧固定框混入图标而返回空字符串。新图补充证明：体力位数改变时资源图标和文字一同横移，按三位数截图修出的固定框也不能覆盖两位数。位面饰品页还有独立的 `0/12` 资源及不同的底部控件布局。

候选增加五种左上标题模板分流（花萼金/赤共用布局），用体力图标确定数字左界，排除图标、加号和其他资源；按布局选择首选缩放，并使用其他版面/缩放回退。体力须完整分数解析和两次一致才返回，空值、低置信度及不一致有界失败，`0/300` 保持有效。消耗、次数同样动态定位，位面页使用独立区域，次数增加低置信度拒绝；按钮总消耗仍除以实际当前次数还原单次消耗。

使用现有 YAML 函数及模板，未增加语法、Core 业务或模型调用。保留原登录、导航、战斗、领奖逻辑；本次未恢复之前用户明确不要增加的战斗残留弹窗处理。
