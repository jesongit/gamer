# 浏览器投屏框选修复（2026-09-27）

## 原因与修复

运行中的自动化插件是历史版本 3.3.13，其取图和坐标映射仍只读取 `videoWidth/videoHeight`。CDP 预览使用 `<img>`，导致 1280×720 画面被按缺省 1920×1080 换算，随后报「无法截取画面，请稍后重试」。更新 Core 壳不会替换已安装插件的 UI 模块；必须构建并更新实际使用的插件。

连续 JPEG 换帧时，`img` 也可能暂时没有 `naturalWidth`。Core 现在按需从最后一张已显示帧的固定数据加载独立图像，取图过程中仍校验目标连接和画面代次；不逐帧增加 Canvas 拷贝，也不在保存模板时重新截取最新画面。舞台提供稳定尺寸；插件的浏览器框选通过舞台快照裁切，Android 视频保持原同步取图路径。

插件源码先在插件仓提交 `f35d5c3`，主仓更新固定 gitlink。按当前仓 manifest 的版本 **0.1.0** 完整构建 gamer-yaml，并通过正常插件更新 API 更新本机实例；这遵循仓库已有版本号收敛，并非修改历史 3.3.13 安装目录。权限集合未增加，其他插件未更新，用户配置包未改动。

## 验证与交付

- 原始问题在 `localhost:5173 → 127.0.0.1:8443`、原已安装 3.3.13 UI 上复现。
- 使用独立无窗口浏览器资料、本地动画页面、临时目标及临时配置包，1280×720 画面连续 5 次真实鼠标拖动框选成功，无前端异常。
- 裁切窗口打开后修改目标页面背景，裁切 Canvas 内容不变。
- 点击保存模板后，通过资源 API 读回 PNG：250×149、PNG color type 0（灰度），与裁切窗口及框选坐标一致。
- 前端 84 个文件 / **794 项**通过；插件 UI 29 个文件 / **257 项**通过；固定插件 SDK 与宿主检查通过。
- Core 前端生产构建、gamer-yaml UI/guest/归档构建和归档自检通过；本机插件运行状态为 running，前端已更新。不涉及 Rust 服务源码变更，不需要重启后端或真实云游戏浏览器。
- 临时目标和配置包均测试后删除；测试未进入真实云账号或触达 Android 设备。

复测：刷新 5173 页面使插件 UI 模块重新加载，连接原目标，选择模板页的「框选」，拖动选区后应进入「二次裁切」并可保存。
