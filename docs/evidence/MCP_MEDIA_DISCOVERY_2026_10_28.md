# MCP 录像发现与素材链路补齐（2026-10-28）

用户录制“退出云游戏”后，外部 Agent 只能查询已经制作的素材包，无法按视频名称定位原始录制。审计当前服务工具目录和各模块接口后，确认是 MCP 的原录像发现缺口，不能要求用户手工寻找内部 ID。

## 实现

- 七项新工具均为 Core 的只读媒体机制，复用 `media.read`、实际媒体对象范围；录制同时检查实际设备与全部分段的媒体授权。未生成任何分段的失败录制要求明确的全部媒体授权，避免空集合绕过对象检查。先过滤授权再搜索和分页，不暴露其他对象的名称、总数或引用。
- 使用现有视频显示名称，重命名后搜索同步更新；支持中文与大小写不敏感的包含查询。同名保留设备、时间和分段信息，不替用户猜选录像。
- 原始操作事件保留时间、按键负载、来源和坐标，支持类型/时间过滤。拒绝仍在录制或收尾的事件读取；读取前后重新核对元数据与实际设备/分段授权，发生变化明确报错。真实帧使用已有精确 PTS 提取，不启动或连接设备，也不执行事件回放。
- 输出分页默认 20、最多 100；事件读取最多 16 MiB / 100000 条，保留完整性校验。损坏、缺失或超额明确失败，错误不返回绝对路径和工具 stderr。
- 录制名称发现只读取元数据，不逐个加载事件。只读状态不会写入过期会话的恢复状态；正常管理端的恢复行为保持。录制服务按数据根共享，避免同一进程的不同数据上下文串用第一次初始化的录像目录。

## 本地验证

- `cargo test --manifest-path server/Cargo.toml --bin gamer-server mcp`：45 项通过，含新增的 6 项媒体/录制集成测试。
- 录制模块：27 项通过，4 项原有环境依赖测试保持忽略；架构边界：7 项通过。
- 新增测试覆盖中文/大小写名称查询、授权后分页与引用过滤、重命名、多分段权限、Alt+Q 原始事件与时间范围、事件缺失/损坏/预算、只读历史不写回和不同数据根隔离。
- 使用隔离生成的 64×64 MP4 实际验证帧数量、PTS/index 对应、PNG 像素尺寸与互斥参数，不连接任何真实设备。
- `cargo clippy --manifest-path server/Cargo.toml --all-targets --all-features -- -D warnings`、Rust 格式检查及 `git diff --check` 通过。

## 待继续的用户流程

新宿主更新到用户实例后，按“退出云游戏”找到录像，从实际 Alt+Q 事件开始制作独立素材包，再按素材编写退出流程。用户还要求正常结束与超时失败都退出；普通 YAML 当前没有可凭空使用的 finally 语法，不能只把退出步骤追加在末尾就宣称覆盖异常收尾。需要继续检查并实现相应生命周期能力，保留原日常结果与输入屏障。

本次不将隔离测试等同于用户录像制作、正式脚本发布或真实游戏退出已通过。
