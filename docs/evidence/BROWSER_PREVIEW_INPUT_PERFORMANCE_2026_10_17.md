# 2026-10-17 点击后投屏卡顿

此前刷新及静止预览修复见 [第一轮性能记录](BROWSER_PREVIEW_PERFORMANCE_2026_10_17.md)。用户继续反馈点击后卡顿，本轮专门测量完整工作台的输入链，不向真实账号发送游戏输入。

## 浏览器复现

使用独立新目标及空浏览器资料，完整工作台选中 hsr 配置包与自动化面板。临时源页面显示相同 1920×1080 动态 JPEG，额外放置明确的本地诊断按钮；浏览器在实际预览上点击 12 次，再持续移动鼠标，所有动作经过当前前端、Keymap、Core 手动屏障和 CDP。

修前报告 `server/target/external-agent-mcp/preview-throughput-mvbbn97h/`：静止阶段平均帧间隔 38.68ms、最大 55.1ms；点击阶段平均 122.23ms、最大 501.1ms；移动阶段平均 251.15ms；停止操作后仍出现 1110.5ms 的最长停顿。源页面确认收到全部 12 次点击。全程约 11.51 FPS，没有断联。这证明之前单测静止画面的结论不足以覆盖交互体验。

## 修改

- Keymap 每个鼠标事件原先通过全量快照读取全部历史版本。输入现在只读取当前状态和精确活动版本，并继续校验实际 manifest 字节、版本目录、guest、退休权限与当前进程运行状态；生命周期读租约保持。不删除或修改任何历史安装。
- 后续端到端延迟测量发现，公共运行状态校验内部再次调用 `snapshot_for`，遗漏的间接全量扫描仍使 Keymap 输入变慢。最终热路径将已经精确读取的 manifest 交给同一运行状态校验，其他调用方保持原行为；新增 service 级真实 guest 回归，避免只验证 store 而漏掉整个调用链。
- WebSocket 循环并行轮询一个有序输入操作与一个预览操作，ACK、画面及导航/模式恢复不再等待整条输入处理完成。没有无限任务或无界帧队列。
- 第一轮实测仍有约 0.22–0.25s 停顿，进一步定位为稳定帧的只读校验等待实际输入的 CDP 锁。稳定坐标帧现在只做原帧身份/代次/图片与元数据校验；尺寸变化的写入仍等待原锁并使旧 revision 失效，实际输入及截图的锁和校验没有放宽。新增并发测试专门验证此边界。
- 输入队列有 64 条上限，信任票据在收到事件时冻结，不能等处理时换成暂停/恢复后的新代次。过载结束本次预览并经原屏障释放输入，不能静默丢失 UP。
- 断开时丢弃排队或尚未入场的动作；已入场动作收尾后才释放 viewer 与原人工清理票据。FrameStamp、连接 epoch、坐标 revision、按帧 ACK 与有限解码重试保留。
