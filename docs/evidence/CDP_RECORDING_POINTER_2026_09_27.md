# CDP 录像与单指针映射验收（2026-09-27）

## 实现边界

- Core 复用 `RecordingService` 的会话、素材、输入记录和停止/取消状态机；浏览器目标开放 `recording` 能力。
- 录制和投屏各自订阅同一个 CDP screencast。关闭投屏后录制继续，无投屏连接也能起录；导航、换目标、断连使原录像结束，不拼接另一目标。
- 新画面最多每 33ms 暂存一次 JPEG，保留单调时间戳。停止后后台编码可变帧率 H.264 MP4，静止尾帧的停留时间不丢失。FFmpeg B 帧关闭以避免稀疏 VFR 的容器时长错误；显式转换并标记 TV 范围/BT.709，避免浏览器播放发暗。
- 持续映射复用 `TouchService`，浏览器用一个鼠标指针执行。句柄绑定按下时的帧身份；第二接触点和抢占同一指针的操作拒绝。模糊焦点释放及目标失效后，旧句柄不能发送移动。
- gamer-keymap 0.1.3：自定义及内置映射的重复按键被消费，手柄按钮使用命名 Space，不发送 Android 数字键码。
- 不增加 Node/Playwright/浏览器安装包/服务依赖，不改变普通预览为二次编码流。

## 验证范围

仅使用本机回环 HTTP 页面、独立 headless 浏览器配置目录；测试后清理临时目标、配置包、录像和历史。未操作云游戏登录、账号或真实游戏，未对 Android 真机做本轮实测。

- Rust 录制测试 21 项通过，含真实 FFmpeg 的不规则帧间隔、静止尾帧、MP4 时长及颜色标记回归。
- 浏览器相关测试 7 项通过（包含上述录制回归）；覆盖预览订阅与录制订阅生命周期、单指针按下/移动/释放、第二接触点拒绝、导航后旧移动拒绝。
- 核心架构守卫 7 项通过；SDK 来源与 7 个文件哈希校验通过。
- 键位映射测试 18 项通过，包含自定义及内置映射重复按键消费。
- 最终 Release + 实际安装 gamer-keymap 0.1.3：并发起录只接受一个会话；真实 WASM 按住/移动/松开；无投屏起录、投屏断开继续录、导航和目标断开中断、取消后重复停止均通过。
- 静止尾帧样例：实际会话视频区间 3.912602s，ffprobe 容器时长 3.912603s；H.264 / 1280×720，无音频。
- 实际 5173 → 8443 页面验收：视频插件的录制按钮可用，开始/停止后素材为就绪，浏览器能播放 1280×720 MP4（readyState=4）；录制区间 1.605991s，播放时长 1.605992s。HTML 背景 RGB(18,52,86)，录像播放 Canvas 取样 RGB(16,52,85)，JPEG/H.264 有损误差范围内，无控制台错误。
- 安装包验证通过；SDK 契约未变化，插件不需要新增传输实现。

## 当前限制

录像不含音频；直播音视频输出和真正多点触控仍未开放。临时 JPEG 上限 4 GiB，磁盘余量低于 1 GiB 时结束；停止后需要等待编码，编码最多等待 5 分钟，失败保留临时文件。命名按键的录像记录目前由 YAML 草稿明确诊断为待手工补充，不伪造 Android 键码。

FFmpeg 参数依据：[concat 格式文档](https://ffmpeg.org/ffmpeg-formats.html#concat-1) 与 [编码参数文档](https://ffmpeg.org/ffmpeg.html)，并以实际生成文件和浏览器播放验证。
