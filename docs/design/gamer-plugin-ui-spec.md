# Gamer 插件界面设计规范

版本：1.0 · 2026-09-29。适用：官方插件及采用 Gamer 风格的第三方插件面板。

本文规定插件如何组织入口、编辑内容与反馈，供设计、开发和验收共同使用。「必须」为验收要求；「建议」允许根据实际任务调整，但需说明原因。本文是 [Gamer 界面设计规范](gamer-ui-spec.md) 的补充，颜色、字体、尺寸与公共反馈不重复定义；现有页面作为参考，不代表已满足所有条目。

## 1. 入口与命名

1. 宿主主导航保持「工作台 / 任务 / 日志 / 配置包 / 插件 / 设置」。插件贡献工作台功能入口，不自行增加宿主主页面。
2. 工作台原则上一个插件一个外层入口。入口用清楚的业务名称，避免过于宽泛的缩写、插件 ID、技术名或版本号。例如使用「键盘映射」，不只写「映射」。
3. 同一插件共享上下文的相关功能放在内部子页签，不把每一种资源类型都注册成外层入口。确有独立工作流、需要多个入口时，须先说明用户场景。
4. 多个功能使用一行子页签；只有一个功能时直接显示内容。禁止为了层级对称添加只有一项的子页签，或继续增加第三层页签。
5. 资源选择器用于选具体对象，筛选器用于收窄列表，更多菜单用于操作；三者不得替代页面导航。
6. 可见名称与稳定标识分开：修改标题不改变插件 ID、面板 key 或资源路径。名称在导航、空态和相关操作文案中应保持一致。

| 外层入口 | 内部组织 | 内容 |
| --- | --- | --- |
| 自动化 | 脚本 / 函数 / 模板 | 脚本编辑、函数编辑、模板列表与框选 |
| 键盘映射 | 直接显示，无重复单项页签 | 映射方案选择、键位与动作编辑 |
| 视频 | 素材库 / 项目 / 草稿 | 素材管理、项目组织、自动化草稿 |

外层入口的排序、启用状态和应用适用性由宿主管理。子页签由插件管理，使用固定业务顺序；除非确有需求，不引入另一套拖动排序或持久化配置。

## 2. 面板结构与视觉层级

面板按以下顺序组织；没有相应内容的区域直接省略，不放空占位。

```text
宿主工作台功能导航：键盘映射 | 视频 | 自动化 | …
当前插件内部导航：脚本 | 函数 | 模板
当前内容工具栏：资源选择或搜索 | 当前主操作 | 更多
主要内容：编辑画布、资源列表或当前任务表单
必要的局部说明、校验和结果
宿主底部：当前插件操作反馈
```

- 必须复用宿主主题令牌和公共控件；不得在插件根节点修改全局背景、字体或其他插件样式。
- 外层导航使用宿主现有选中样式；子页签采用视频与自动化面板的紧凑按钮样式：28px 高、13px 字号、3px 圆角、4px 间距，选中项以边框、背景与字重区分。子导航底部使用细分隔线，与内容保持约 8px 间距。
- 导航已明确当前功能时，不再重复一个同名大标题、图标横幅或介绍卡片。必要说明就近放在具体操作旁。
- 子页签与常用工具栏不被长内容挤走；主要内容区承担滚动。避免同一列表或编辑任务出现无意义的多层滚动。
- 以面板实际宽度布局，不只检测浏览器宽度。320px 左右窄面板仍须可操作；工具组可换行，长名称截断并提供完整值，不靠缩小字体解决溢出。
- 列表优先紧凑行式布局；缩略图、名称、关键属性和操作按列对齐。详情按需展开，不把简单对象都做成大卡片。

## 3. 操作与控件

| 类别 | 要求 |
| --- | --- |
| 主操作 | 放在当前对象工具栏，如保存、运行/停止、应用、生成；名称用明确动词。请求中防重复提交，结束后恢复可用状态 |
| 低频操作 | 放在一个「更多」菜单，如新建、重命名、原文、导入导出、删除；不嵌套多层菜单 |
| 表单 | 标签与字段对应，必填、默认值、单位、范围由真实 Schema 决定；少量辅助说明就近展示 |
| 下拉选择 | 收起与展开状态都匹配主题；封闭枚举使用选择器，允许自由输入的候选使用公共可搜索组合框。不使用未处理样式的 `datalist` 弹层 |
| 键位输入 | 同时支持选择和一次按键录入；明确显示等待状态，录入完成或取消后退出监听，切换/卸载时清理监听，不能把录入事件同时传给设备控制 |
| 行内操作 | 作用于当前行对象；图标必须具备可访问名称，危险操作与普通操作在文案和样式上区分 |
| 复杂编辑 | 在主内容区就地进行；弹窗用于短任务、确认和必要详情，不作为日常脚本/函数编辑主入口 |

菜单必须使用不透明主题背景，能在视口边缘调整方向，不被父级滚动容器裁掉。关闭菜单或弹窗后恢复合理焦点。禁用原因须可获知，不能只依靠禁用按钮本身不可触达的悬停提示。

重命名输入中的未提交文字也属于未保存修改。保存成功后保留当前对象、编辑模式和必要的撤销历史，不因重新加载列表而回到第一个对象或长期停留在加载态。

## 4. 上下文、选择与导航

必须区分设备、运行应用、配置包、插件四个上下文。切换子页签只切换查看的功能，不能顺带切设备、配置包、启动应用或更改执行目标。

| 场景 | 必须保证 |
| --- | --- |
| 脚本/函数/模板往返 | 分别保留当前配置包内各功能的选择；共享编辑模型时核对资源类型和完整身份 |
| 切换时有未保存修改 | 先确认，再切换；取消后页签高亮、下拉值、画布、原文和未提交名称保持原状 |
| 切换配置包 | 经既有未保存守卫后，清理旧包选择和待提交参数；不能把旧包草稿写到新包 |
| 查看 YAML / 原文编辑 | 显示当前选择的对象；函数级编辑按真实定义文件合并保存，保留同文件其他函数 |
| 跳转函数定义与返回 | 先完成必要保存，加载正确函数后切到函数子页签；返回时恢复来源对象和步骤 |
| 视频草稿打开脚本 | 打开自动化入口并选中脚本子页签，定位请求中的配置包和脚本；上下文不符时明确拒绝或按现有守卫切换 |
| 异步请求迟到 | 成功和失败响应都校验发起时的上下文与请求代次；旧请求不能覆盖当前选择或清空新内容 |
| 功能暂不可用 | 保留可用的查看/编辑能力，只限制确实依赖设备、权限或连接的操作，并指出恢复方法 |

子页签可以在当前会话内记住选择；持久化或写入 URL 只有在确有恢复、分享需求时增加。外层 URL 与注册面板保持一致，不依赖已移除的函数/模板独立面板 key。当前未实现直达子页签的 URL 时，不宣称支持。

缓存隐藏的组件仍须按非活动状态处理：关闭悬浮菜单，停止不必要的监听和状态发布。原本在后台执行的任务可以继续，但不能抢走当前焦点、选择或反馈区域。

## 5. 状态、错误和确认

状态归属和生命周期遵循 [状态条完整设计](gamer-statusbar-design.md)。当前操作结果使用宿主统一反馈；字段错误和解决问题所需的信息保留在内容旁。避免同一事件同时弹出多个提示。

| 状态 | 表现与下一步 |
| --- | --- |
| 首次加载 | 说明正在加载什么，保持页面框架稳定 |
| 无数据 | 区分尚未创建、筛选无结果、未选配置包、缺依赖；提供对应操作 |
| 保存/运行/上传中 | 使用准确动词，防重复提交；只有后端支持取消时才提供取消操作 |
| 成功 | 依据服务端结果更新；区分已保存、已提交、运行中与已完成 |
| 失败 | 结束加载状态，保留输入；指出失败对象、原因和可执行下一步，允许合理重试 |
| 版本冲突 | 保留本地草稿，明确重新加载/覆盖的含义；不能静默覆盖他人修改 |

错误提示先给用户能定位的信息，技术路径作为补充。例如：`“账号登录”仍被引用：函数“账号日常” → 第 3 步（automations/_function.yaml）`。嵌套调用应补上条件分支、循环或模板分支位置；不能只有一个库文件名。

网络错误应区分连通性、认证、权限、限流和服务异常中可确认的原因；无法确认时明确未知，不将所有情况都归因于权限。不得向用户展示令牌、带凭据的 URL 或未清理的进程输出。

已有默认值直接采用，不为每次执行强制增加参数覆盖确认；只补齐缺少的必填值。删除、覆盖、公开发布等按真实后果确认，确认中写出目标对象；无副作用的页签切换不增加额外确认。

## 6. 键盘与可访问性

- 所有操作必须能通过键盘到达，焦点清晰可见；输入框、图标按钮、菜单和弹窗有明确名称。
- 子导航可以使用有名称的 `nav` 加原生按钮及 `aria-pressed`；若使用 `tablist/tab/tabpanel`，必须同时实现相应的选中关系与方向键导航，不能只添加角色声明。
- 颜色不作为唯一状态信号。选中、禁用、错误和未保存状态同时有文字、图标或语义属性。
- 在文本输入、下拉、弹窗或按键录入期间，不得触发投屏控制或后台插件快捷键；中文输入法组合输入不得被当作确认或快捷键。
- 打开浮层后合理转移焦点，Esc 按当前操作语义关闭；关闭后回到触发控件。页面切换或组件销毁后不残留透明遮罩和键盘监听。

## 7. 实现与交付检查

优先复用现有组件和数据契约；同类交互先检查是否已有实现，不为插件另建通用平台。

| 参考位置（仓库根目录相对路径） | 用途 |
| --- | --- |
| `web/src/styles/theme.css`、`web/src/components/ui/` | 主题、按钮、字段、图标、弹窗与反馈 |
| `web/src/workspace/PluginWorkspace.vue` | 宿主工作台功能入口与排序 |
| `plugins/gamer-yaml/ui/src/components/console/AutomationWorkbench.vue` | 脚本/函数/模板子导航与切换守卫 |
| `plugins/gamer-video/ui/src/components/video/VideoWorkbench.vue` | 视频功能分区与紧凑子导航 |
| `plugins/ui-shared/ThemedCombobox.vue` | 可输入、可搜索的主题候选框 |
| `plugins/<id>/manifest.toml` 与 `ui/entry.js` | 外层贡献、可见名称和面板接线 |

交付前按改动范围检查以下项目，并区分自动测试、实际页面验收和仍未验证的外部能力：

- 外层名称、子页签数量及顺序正确；单功能不出现重复页签，已移除贡献不残留旧入口。
- 窄面板、长名称、大量数据、无数据和加载失败均可操作；菜单弹层完整可见。
- 当前对象与画布、原文、预览、删除、运行目标一致；往返切换、取消确认、迟到响应不串台。
- 保存、错误、冲突、断连和禁用状态有明确下一步，不无限加载，不丢草稿。
- 键盘选择、焦点恢复、Esc、输入法与按键录入正确，不误触设备控制。
- 构建并部署实际使用的插件 UI；修改贡献清单时同步已安装 manifest 和运行时注册状态，刷新页面后检查服务 API 与真实界面。仅改源码或只通过组件测试不算已上线。

新增或修改插件时，设计说明至少写清：入口名称、子页签或无子页签的理由、各区主操作、资源作用域、未保存处理、异步失败与恢复方式，以及本次验收范围。
