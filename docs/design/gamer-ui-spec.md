# Gamer 界面设计规范

版本：1.0 · 2026-09-19。适用：Gamer Web 宿主、官方插件、第三方插件的宿主风格面板。

本规范以用户最终确认的居中投屏方案为依据。交互原型说明布局和交互意图，真实产品以服务端能力、资源校验和权限为准，不复制示例数据或虚构功能。具体实现的修正与未覆盖项记入工作报告。

## 1. 设计目标

Gamer 是面向桌面的游戏自动化工作台。用户需要同时观察 Android 画面和编辑脚本，典型设备画面为 1920×1080，电脑屏幕也为 16:9。优先保证可读性、操作直接、上下文明确和空间利用率。

视觉使用黑、灰、白作为主体，少量信号黄提供选中、未保存和主操作提示。参考明日方舟的工业终端式层次：直线、紧凑边界、小圆角、克制强调。不要引入复杂装饰、发光、渐变大卡片或影响内容阅读的切角。

### 基本原则

1. 常用操作直接可达，低频管理操作最多经过一个“更多”菜单。
2. 编辑内容就地展开，不为函数编辑另开大弹窗。
3. 控件大小按用途统一，不随不同插件任意改变。
4. 状态反馈描述用户当前操作，避免常驻运行总览或信息仪表盘。
5. 空间不足时截断文本、合理换行或内容滚动，不压缩文字到难以辨认。
6. 色彩只辅助语义；状态必须同时具备文字或图标。

## 2. 上下文与信息架构

四个独立上下文必须保持分离：设备、Android 应用、配置包、插件。

| 上下文 | 意义 | 入口 |
| --- | --- | --- |
| 设备 | 当前投屏、输入与执行目标 | 投屏上方第一行设备选择 |
| Android 应用 | 当前设备上执行的应用 | 第一行应用选择，与配置包独立 |
| 配置包 | 脚本、函数、模板、映射、视频项目的数据作用域 | 第一行右侧配置包选择 |
| 插件 | 提供能力和编辑面板 | 工作台功能导航，根据 Running 贡献生成 |

不得从 Android 包名推导配置包，也不得将配置包切换理解为切换设备或启动应用。

主导航固定为工作台、任务、日志、配置包、插件、设置六项。首次访问（URL 未指定页面）进入工作台，扩展贡献就绪后打开第一个可用功能；没有可用插件则留在工作台空态。显式任务/日志等直达链接仍保留目标。插件功能导航来自注册表，不硬编码可下载插件的安装状态。右侧功能页签可拖动排序，插入位置显示细黄线；排序本身不切换面板。顺序按稳定面板 key 保存在当前浏览器，暂时隐藏/停用的面板恢复后保留原位置，新面板追加；支持 Alt+Shift+左右键和恢复默认顺序。没有安装、停用或应用不匹配时，应提供相应空态或管理入口；不凭原型强行显示不可用功能。

管理页已经由导航明确选中时，内容区不再重复展示同名大标题；保留筛选、计数、搜索和操作栏。弹窗仍需要明确标题。

配置包同页分区展示管理与市场；插件将已安装与市场条目合并为一个列表。均不增加二级分类页签或独立市场页面：

| 页面 | 上方 | 下方 |
| --- | --- | --- |
| 工作台 | 投屏与插件功能操作 | 当前功能内容（保留既有功能页签排序） |
| 配置包 | 已安装包、当前包选择、详情；导入/导出/新建/复制/删除直接展示 | 配置市场：来源、适用应用、插件依赖、安装/覆盖 |
| 插件 | 搜索、数量、刷新、本地导入、URL 导入工具栏 | 一个统一插件列表：按 ID 去重，已安装显示启停/更新/卸载，未安装显示安装 |

配置包的两个区域以小标题、数量、细分隔线区分；插件不分区、不重复展示同一插件，安装状态直接标在条目上。管理页采用横向资源列表，共用外边框、行间细分隔，避免多列大卡片割裂阅读。宽屏按列对齐，窄屏在条目内换行。使用同一个纵向滚动区，避免两套内嵌列表分别滚动。URL 导入只展开一行地址输入，不替换列表内容。本地导入直接打开文件选择器。权限、覆盖和卸载等必要确认继续保留。

插件列表以已安装快照与市场条目的 ID 并集为来源，同一市场插件存在多版本时只选最新条目；已安装版本、权限和运行状态以管理快照为准。本地独有插件保留管理功能。安装/卸载后更新原条目状态，卸载仍在市场中的插件会变成可安装条目；状态读取失败标为“状态未确认”，不误报“未安装”。配置包弹窗由 Console 保留单一宿主，页面工具栏只触发相同上下文中的操作，避免重复弹窗。

## 3. 视觉令牌

令牌以 `web/src/styles/theme.css` 为实现单一来源。插件优先消费宿主变量，不在每个组件中重复定义颜色。

| 用途 | 目标值 | 说明 |
| --- | --- | --- |
| 页面底色 | `#17191a` | 工作台底层 |
| 顶栏/状态条 | `#131516` | 收敛界面边缘 |
| 投屏工具区 | `#222526` | 左侧面板 |
| 编辑背景 | `#282b2d` | 右侧内容 |
| 展开步骤 | `#343739` | 单一连续面，不叠黑边 |
| 输入框 | `#181b1c` | 与周围灰色明显区分 |
| 常规边线 | `#454b4e` | 面板、列表分隔 |
| 控件边线 | `#626a6e` | 输入框和交互边界 |
| 正文 | `#edf0ee` | 主要文字 |
| 次要文字 | `#c5cbc8` | 标签、说明、路径 |
| 辅助文字 | `#a4adaa` | 时间、次级信息，不能用于主按钮文字 |
| 信号黄 | `#e4c956` | 主按钮、重要编辑状态 |
| 成功 | `#8fc9ae` | 成功结果 |
| 错误 | `#ed9696` | 错误文字与危险操作 |

### 对比度

- 普通文字与实际背景的对比度目标至少 4.5:1；大字及必要图形至少 3:1。
- 禁止用低透明度整体处理含有效正文的行。
- 实心信号黄按钮使用深色文字；灰色按钮使用浅色文字。
- 禁用态仍保留基本可读性，并提供禁用原因；不要让文字与背景一起变成不可辨识的灰块。
- 选中导航采用浅底深字或明确的细强调线，不混用多套选中样式。

## 4. 字体与尺寸

正文使用系统中文无衬线字体。代码、参数名、坐标和时间使用等宽字体。无需联网加载字体。

| 元素 | 字号 | 高度/间距 |
| --- | --- | --- |
| 常规正文、任务和日志内容 | 14px | 行高 1.5–1.6 |
| 输入框、下拉选择 | 13px | 工作台 28px，管理表单 30px |
| 工具按钮、页签 | 12–13px | 工作台 28px，管理页面 30px |
| 辅助说明 | 12px | 保持可读，不低于 12px |
| 弹窗标题 | 15px / 500 | 紧凑标题行 |
| 主操作保存/运行/停止 | 12–13px | 同组相同宽高；默认 60×28px |
| 图标按钮 | 图标 14–16px | 28×28px |
| 步骤编号 | 11–12px等宽 | 23×23px，始终居中 |
| 轻操作反馈条 | 12px | 28–30px |

间距基准为 4px。常见控件间距 4–6px，组间距 8–12px，内容内边距 12–14px。按钮/字段圆角 3px，弹窗 4px。触摸输入设备应扩大点击区域，而不是缩小文字。

工具条与其下方列表之间必须由所属面板显式提供 8–16px 纵向间距，不能依赖外层宿主的 gap 穿透组件内部。任务面板使用 10px，日志 12px，插件 16px；工具条不压缩，长列表在自身容器滚动。市场/插件条目按面板容器宽度换行，不仅按浏览器视口判断。

## 5. 应用外壳与投屏

### 顶栏

- Gamer 字标、主导航、账户操作共用一条 48px 顶栏；左侧为小块 G 标记与文字组合，紧接工作台、任务、日志、配置包、插件、设置导航。
- 账户与退出登录靠右；不常驻显示服务就绪状态和版本号。前后端版本不一致时仍保留条件式异常提示。
- 不在顶栏重复当前设备、配置包和脚本执行按钮。

### 双行投屏工具条

第一行：设备选择、连接/断开、设备管理；应用选择与启停；右侧配置包选择及详情/管理入口。

第二行：截图、返回、全屏、游戏模式与功能菜单；功能菜单承接放大镜、坐标/框选、键盘输入、录制和来源切换等实际能力。画面分辨率、FPS、延迟和码率统一显示在底部左侧内核状态条。设备管理中的强制重连、安装 APK、删除等保留在更多菜单，不冒充普通连接操作。

同一工具组用小间距聚合，组之间用一条细竖线区分。图标必须有可访问名称和悬停说明。窄窗口允许整组换行，禁止图标与其下拉控件分离。

### 投屏与分屏

- 桌面默认左侧约 54%，向左拖动仍至少保留一半宽度；向右上限按投屏内容区实际可用高度 × 16/9 计算，替代固定 65%。计算排除上方工具条和底部状态条，右侧编辑区至少保留 320px（窗口不足时以左右各半为边界）；无法同时满足时优先保留编辑空间。窗口和工具条尺寸变化自动重算，隐藏/全屏状态不覆盖正常布局测量值。状态条中线是另一条独立分界，不跟随投屏分界。
- 画面保持真实来源比例；1920×1080 时为 16:9。竖屏、旋转和其他分辨率不能被强制拉伸。
- 两行工具条固定在上方，画面在余下空间水平、垂直居中；调整宽度时不把所有空白留在下方。
- 真正应用使用可用窗口高度约束画面，并通过 `object-fit: contain` 适配。交互坐标必须按实际有效画面计算，排除黑边。
- 在当前编辑面板长于窗口时，编辑区独立滚动，不拖动整个投屏工具区。
- 小于并排工作所需宽度时改为上下布局，所有控件仍可操作。
- WebRTC 单 viewer 接管、离线媒体输入门禁、键盘焦点、防误触与框选不能因布局重写失效。

## 6. 轻操作反馈条

所有功能的状态归属、生命周期、超宽交互及有意保留的就地提示，见 [状态条完整设计](gamer-statusbar-design.md)。以下原则与该逐项清单配合使用。

**展示当前操作反馈、相关便利动作和当前投屏的轻量状态。** “内核”和“插件”表示归属，不需要作为可见分类标题。

左侧左对齐：设备、投屏、输入、资源宿主等内核相关操作的结果。右侧右对齐：当前插件操作的结果。

连接时左侧同时显示 `分辨率 · FPS · 延迟 ms · 码率 Mbps`；键盘焦点处于可控制的实时投屏时显示“键盘控制已启用”。使用无边框的紧凑文字，投屏内不再叠加键盘徽标或统计浮层，也不以高亮边框表示键盘启用。断开连接隐藏实时指标，离开键盘焦点/进入媒体模式隐藏键盘提示。实时状态与操作结果独立更新，不覆盖坐标复制等内容，超宽仍统一裁切并在悬停提示中补全。

默认一边一半，分界位置在当前浏览器记忆。中间细分界可拖动，双击恢复各半；键盘支持左右调整及 Home/End。超出各自区域的内容被裁切，悬停或聚焦会补全同一条内容，隐藏的复制/详情/跳转也可点击；Esc 收起。补全区域只是一小条或一小段，不增加标题、字段清单和历史列表。左侧先显示当前操作结果，再显示较弱的画面/键盘指标。

| 操作 | 反馈 | 允许的紧邻动作 |
| --- | --- | --- |
| 点击画面 | `点击了 (300, 500) (0.1563, 0.4630)` | 两组数值分别点击复制 |
| 编辑脚本/函数 | `未保存` | 不放保存按钮 |
| 保存完成 | `已保存` | 无 |
| 运行步骤 | `步骤 01 · 等待模板出现` | 详情 |
| 运行报错 | `步骤 01 · 等待模板超时` | 复制错误、跳转错误、查看简短详情 |
| 其他操作 | 简短结果或失败原因 | 仅与该结果直接相关的动作 |

像素坐标以当前源宽高为准；相对坐标使用 0–1 浮点值。复制结果为脚本可用数组，例如 `[300, 500]`、`[0.1563, 0.4630]`。复制成功就地短暂提示。剪贴板受限时明确反馈，不能谎报成功。

禁止放入：设备连接总览、插件 ID、空闲/就绪占位、常驻运行历史、保存/运行/停止重复按钮、日志控制台。

## 7. 自动化与函数编辑器

### 顶部

资源选择、保存、运行/停止、更多位于同一行。自动化与函数使用同样的选择器样式和按钮尺寸。更多包括新建、重命名、原文、删除等低频操作；不再并排铺满管理按钮。

工具栏下为默认展开的步骤画布和折叠的“参数与变量声明”。YAML 预览、原文编辑、撤销/重做、运行详情收进更多菜单；运行参数在发起运行时按真实 Schema 提示。只读诊断与实际原文编辑必须区分。

函数编辑使用相同内联步骤画布。当前函数选择为下拉；函数名修改通过重命名入口，参数声明独立组织。库文件来源等技术信息放辅助说明或详情，不抢占主要编辑空间。

所有 `_function*.yaml` 均可直接选择函数并编辑，写回真实定义文件；新建默认进入 `_function.yaml`。同名冲突拒绝。重命名/删除若仍有引用，列出受影响资源并拒绝保存；不做部分联动。删除最后一个函数保留带版本校验的空库，避免删除整个文件时丢失并发改动。

报错位置按运行 ID、调用帧、定义资源和执行版本定位；优先最内层失败，不以父调用退栈事件覆盖。只有当前编辑内容与执行版本一致且没有未保存修改，才直接定位画布；其余打开紧凑只读位置预览。文件已修改/删除时说明差异，不能把旧路径硬套到新内容。预览不是函数编辑入口，正常编辑仍在主画布。

### 步骤卡片

- 收缩态一行呈现：编号、函数/控制流与摘要、展开入口、图标动作。
- 从此运行、复制、上移、下移、删除等常用动作不因收缩而消失。
- 展开后保持编号垂直居中，卡头与卡体使用同一连续背景，不产生首行灰块及两条黑边。
- 按函数 Schema 判断：只有 `required=true` 的参数直接显示；其余放“更多参数”。不能按猜测的“常用程度”分组。
- 必填参数带默认值时仍按 Schema 的必填语义呈现；不要为了展示而把默认值重新写入 YAML。
- 可选参数摘要只统计可选实参；接收返回值使用同级独立折叠项，摘要显示未设置或变量名。展开后直接填写变量名，留空/清除表示不接收；折叠不删除原值，不使用勾选框或弹窗。
- 模板必须用候选下拉/搜索选择，不用输入框充当静态示意，也不能触发整个工作区变化。
- 参数尽量标签与控件同一行；坐标、时长等相关字段组成紧凑组。
- 嵌套 if/repeat 保留清晰层级、错误定位和实际执行路径。

### 编辑与运行

- 同一个正在执行的文档只读；停止后恢复编辑。
- 同设备已有运行时，不再启动第二个运行。其他文档可编辑的前提是能保证文档隔离。
- 运行前校验、必要保存及运行参数确认有明确顺序；保存失败或缺必填项不得运行。
- 原文编辑、版本冲突、非法 YAML、未保存切换等真实情况必须有明确交互，不丢草稿。
- 运行错误定位必须核对完整资源身份，不将历史错误定位到另一个同名资源。当前版本对当前文档的直接步骤保留完整嵌套路径；跨函数调用缺少可靠调用栈时打开运行详情，不猜测目标位置。

## 8. 其他功能面板

| 面板 | 规范 |
| --- | --- |
| 模板 | 紧凑列表，小缩略图、名称、尺寸和行内图标；大预览按需打开；上传、zip、替换、重命名、匹配、裁切入口完整 |
| 按键映射 | 紧凑键位标记、动作与摘要、编辑图标；保存/取消/应用对齐，不将每个键位做成大卡片 |
| 视频素材 | 行式媒体列表，小图标、文件名和元信息；录制状态与导入动作紧凑 |
| 视频项目 | 名称、关联素材和标记采用列表，资源引用保护和版本冲突保留 |
| 时间轴 | 同一定位操作只使用一条可拖动时间轴；逐帧以服务端真实帧表为准，不伪造固定帧率 |
| 视频草稿 | 紧凑条件、事件和预览，生成/保存/打开编辑器职责清晰 |
| 任务 | 通用 ScheduleProvider + Runner 表单，显示运行目标和参数；列表操作文字必须可读 |
| 日志 | 正文 14px、时间等宽；级别区分有文字，避免低对比度；过滤与详情不混淆 |
| 配置包 | 创建/详情/导入导出/复制/删除完整；Android Targets 与插件依赖分别呈现 |
| 市场/插件管理 | 来源、版本、权限、依赖、安装启停更新状态真实；确认与失败原因明确 |
| 设置/登录 | 继承统一色彩、字段和按钮；不出现默认密码或伪造登录态 |

## 9. 弹窗与菜单

- 简单输入/重命名约 400px；常规详情约 560px；任务、裁切等复杂内容约 680px，窄屏留出边距。
- 标题内边距 12×16px，正文 12×16px，底部 9×16px；字段间距约 9×12px。
- 对话框必须有名称、明确关闭/取消、键盘焦点约束与 Esc 关闭；破坏性操作或不可取消请求遵循实际语义。
- 确认按钮与取消按钮同高，危险动作明确标识；异步请求中防重复提交。
- 下拉菜单使用不透明背景，宽度与内容匹配，在视口内定位；不能被父容器的 overflow 裁掉。
- 编辑器为默认工作区域。重命名、配置详情等短任务可用弹窗；不要把常规函数编辑塞进弹窗。

## 10. 插件接入契约

1. 插件继续通过 manifest contribution 和宿主注册表提供面板，不绕过权限或生命周期。
2. Core 宿主只定义通用 UI/反馈契约，不了解某插件的 YAML、映射或媒体项目内部格式。
3. 官方 Vue 面板使用公共按钮、字段、菜单、布局、图标和颜色令牌；第三方 iframe 不继承宿主 CSS，需消费文档化主题令牌或使用自己的符合规范样式。
4. 反馈项包含简短文字、可选详细文字、语义级别、可选便利动作；不要将主操作通过状态条重复输出。
5. 插件反馈只作用于其当前活动面板；切换、停用、卸载应清理其反馈及回调。异步旧结果不能覆盖新面板。
6. 便利动作仅允许明确的本地复制、详情或导航；iframe 通过受控桥请求，不向宿主注入 HTML 或任意可执行代码。
7. 对话框、下拉、空态、错误态、加载态必须与主要内容一同设计和验收。
8. 不设置全局通配 CSS，不修改宿主 body，不泄漏监听器、定时器或对象 URL。

### 实际接入方法

官方 Vue 面板通过 `CorePanelHost` 自动获得操作归属，复用 `components/ui/useOperationStatus.js`：

```js
useOperationStatus(() => ({
  text: saving.value ? '保存中…' : dirty.value ? '未保存' : result.value,
  tone: error.value ? 'error' : '',
  actions: error.value ? [{ label: '复制', copy: error.value }] : [],
}))
```

`readMessage` 应只读取当前操作的响应式结果。空 text 清空反馈；最多 4 个动作。宿主已为面板注入身份，不在业务代码重复填写插件 ID。面板卸载清理；面板切换清空旧反馈。不要通过异步回调持有旧页面的 DOM。

iframe 使用现有 `gamer-ui@1` MessagePort 桥，保留 `sandbox="allow-scripts"`，不增加 `allow-same-origin`。下面的 `rpc` 表示插件已有的桥请求封装：

```js
const context = await rpc('context.get')
// context.theme: name, background, field, text, secondaryText,
// border, accent, controlHeight, radius
await rpc('status.set', {
  text: '匹配失败 · button.png',
  tone: 'error',
  actions: [
    { label: '复制', copy: '未找到模板 button.png' },
    { label: '详情', detail: '搜索区域…\n匹配结果…' },
  ],
})
await rpc('status.clear')
```

底层请求格式为 `{type:'gamer-ui:request', version:'gamer-ui@1', id, method, params}`；请求走宿主握手转交的端口，响应 `gamer-ui:response` 带同一 id 与 `ok/result` 或结构化 error。参考 `workspace/bridge.ts` 和现有 `workspace/iframe-poc.html`，不要自己寻找宿主内部对象。

| 字段 | 约束 |
| --- | --- |
| `text` | 字符串，最多 1000 字符；产品文案建议 10–40 个中文字符 |
| `tone` | `error`、`success`、`warn` 或默认普通色 |
| `actions` | 最多 4 项，每项 label 最多 80 字符 |
| `copy` | 待复制纯文本，最多 10000 字符 |
| `detail` | 详情纯文本，最多 10000 字符，宿主显示紧凑弹窗 |
| `panel` | 已注册面板 key，用于便捷跳转；宿主验证后导航 |

同一 action 只选 copy/detail/panel 中的一种。iframe 不接受 run 函数、HTML、任意脚本。身份来自宿主注册的 pluginId/panelId，payload 不能冒充其他插件；后台面板发送的状态会被忽略。底层长度上限是保护措施，不代表应当塞满状态条。

## 13. 已验证的尺寸与对比度基线

当前桌面头部与主导航合并为一条 48px 顶栏，工作台插件导航约 39px，底部操作条 29px。相比双行头部，内容区增加约 40px 可用高度。投屏容器消耗其余可用高度，画面继续保持原比例居中；控件和菜单不占用画面内部坐标。800px 及以下切换上下布局，工具组可换行，页面允许纵向滚动。

基于实际颜色的 WCAG 相对亮度公式计算：正文对编辑背景 12.42:1，次要文字对展开步骤背景 7.28:1，辅助文字对展开步骤背景 5.22:1，字段文字对输入底色 15.09:1，黄色按钮深字 10.00:1，控件边线对输入底色 3.14:1。这是令牌基线，不代表任意叠加透明度后的组件自动合格；禁用态不纳入正常文本对比度声明。

后续修改至少在 1920×1080、1366×768、800px 宽窗口检查：页面无横向整体溢出、文字可读、长内容正常滚动、弹窗不超出视口、焦点可见。新增内容容器若位于纵向 flex 滚动区，应避免默认 shrink 把实际内容压到相邻区域。

## 15. 日志、配置包和插件管理页

三页共同使用深黑页面底色、稍浅列表底色和细分隔线，不重复导航标题，不用大图标装饰空态。桌面内容内边距为 18px 24px，700px 以下为 12px。动作沿工具栏右侧与列表右侧对齐，沿用公共控件尺寸；主操作为黄色深字，普通操作为灰底浅字。

- **日志**：时间、级别、正文三列；宽屏列宽 190px / 64px / 剩余宽度，680px 以下为 125px / 44px / 剩余宽度。密集记录正文 13px、行高 1.65，时间 12px 等宽，级别 11px 等宽标签。正文保持浅白，语义颜色主要用于级别，错误行仅轻微染色；设备与运行目标使用紧凑分组头。顶部搜索只筛选当前加载的最近 200 条，设备/级别由服务端筛选；页脚明确显示匹配数、加载数和 200 条范围。自动刷新可暂停，手动刷新独立。用户上翻时刷新不强拉回底部。读取失败就地提示，切换筛选、清空或卸载后旧请求不能覆盖新状态。
- **配置包**：当前包选择和导入、导出、新建、复制、删除构成一条可换行工具栏，详情在当前选择旁。下方“本地配置”按名称/独立 ID、版本、作者、使用状态排列，整行可选择，当前使用以细黄边及文字识别。窄屏隐藏作者列（完整信息仍在详情），其余字段换行。再下方“发现配置”直接列出市场内容、适用应用、依赖及安装动作，无二级页签。两区共用页面滚动。
- **插件**：保持 ID 合并后的唯一列表，按插件说明、状态/版本、操作三列排列；宽屏身份与描述并排，容器变窄后逐级换行，650px 以下把状态与动作放在内容下方。名称 14px，描述 13px，元信息 12px。启停、安装、更新直接展示；权限、执行形态、历史版本和卸载操作收在一次展开的“详情”中，避免堆满常用操作区。失败原因、缺失依赖、版本不兼容等阻断信息保持外显，不藏到详情里。已停用用中性色，有更新用黄色，运行中用绿色，均附文字。

允许通过展开查看低频信息，但不能新增重复管理页或多层菜单。局部按钮样式必须检查 hover、disabled 和 primary 的最终计算颜色，尤其不能用统一透明背景覆盖黄色主按钮后仍保留深色文字。

## 16. 统一确认弹窗

应用内确认使用 `components/ui/useConfirmDialog.js`，由 App 中唯一的 `ConfirmDialogHost.vue` 展示，不直接调用浏览器的 confirm/alert/prompt。已有专用表单与覆盖详情框继续复用，轻结果仍进入状态条，不把所有反馈改成弹窗。

标准宽度 480px、视口两侧至少 16px，整体高度不超过视口减 32px；标题与按钮区固定，长内容只在中间滚动。黑灰底、细边界、4px 圆角；正文 13px、标题 15px、按钮 28px 高。右下角取消在左、确认在右；按钮写具体动作（确认更新、卸载、覆盖安装等），破坏性动作使用危险色。安装与更新分为插件名、信息字段、请求权限、权限变化、必要提示；更新必须展示旧版本 → 新版本，新增权限与执行方式变化可见。

使用 `const confirmDialog = useConfirmDialog()`，随后 `if (!await confirmDialog(message, {title, confirmText, danger})) return`。所有调用链都要等待决定，不能把 Promise 当作布尔值；特别是草稿保护和配置切换。单次只展示一个确认，重复请求返回取消；调用方销毁或被停用时取消等待，不在后台继续提交。确认后检查操作目标是否仍有效。

默认焦点落在取消，Tab 限制在框内；Esc、关闭、遮罩均取消，只有明确确认才返回 true。背景不可交互，关闭恢复可用的原焦点。字段按纯文本渲染。iframe 插件通过既有 `dialog.confirm` 桥使用同一弹窗，不放宽 sandbox 或执行传入的 HTML。刷新/关闭标签页触发的 beforeunload 未保存提醒由浏览器控制，保留原生外观；系统文件选择器也不属于应用确认框。


## 17. 操作下拉菜单

菜单内统一使用简短的纯文字动作，不混用 emoji、图标加文字或仅图标项，也不预留图标列。例如配置包菜单为“导入、导出、新建、复制、删除”，设备菜单为“新增设备、设备设置、安装应用、强制重连、删除设备”。自动化与函数共用同一菜单规格。

- **入口**：外部普通按钮采用文字加小号下拉箭头；工具栏拥挤时可用 28×28px 的省略号图标入口，必须有 title 和可访问名称。箭头是展开指示，不是动作装饰图标，统一使用 `.menu-chevron`；原生选择框保留浏览器箭头。不得为套用文字规范把拥挤工具栏强行加宽。
- **面板**：复用 `styles/theme.css` 的 `.action-menu`，最小宽度 140px，按最长标签自然扩展；内边距 4px、行间距 2px、细边框与 3px 圆角，距入口 4px。定位由宿主负责，投屏工具条、模板列表菜单挂载到 body，避免被滚动容器裁切；模板菜单在底部空间不足时向上展开，列表滚动或窗口缩放时关闭，避免浮层脱离原行。
- **菜单项**：`.action-menu-item`，13px 字体、20px 文字行高、最小高度 28px、水平内边距 10px；文字左对齐，不把每项画成独立描边按钮。悬停使用稍浅灰底，键盘焦点使用可见细黄框，禁用项使用统一灰字和透明度。
- **危险动作**：删除、停止应用等使用 `.danger` 红字，放在最后，前加 `.action-menu-separator` 分隔线。保留既有确认流程，样式调整不能绕过确认或运行守卫。
- **交互**：选择动作后收起；沿用点击外部、Esc 关闭。不得为了统一外观增加二级菜单。配置包管理页的平铺工具栏仍使用普通按钮，不套用弹出菜单布局。

本节规范针对操作菜单。脚本、函数、模板等选择器继续承担选值功能；搜索、函数说明和按需模板预览属于选择辅助信息，不作为装饰图标移除。内容折叠控件（更多参数、返回值、详情）不视为操作菜单。


## 18. 步骤编辑器间距与添加列表

自动化、函数以及专注子流程共用画布：工具条、插入位置提示、根步骤容器、诊断区之间保持 8px 的明确间隔；插入提示使用 12px 字号、20px 行高。根容器首尾卡片不额外叠加外边距，空流程提示与已存在步骤使用同一间距。画布纵向布局中的内容不参与压缩，长步骤由外层编辑区滚动。

“添加步骤”是可搜索的功能列表，面板宽度 320px（窄窗口按可用宽度收敛），高度上限 480px，超出内容在列表内部滚动。打开和滚动后使用同一尺寸约束；下方不足时向上展开，两侧均不足时选较宽敞的一侧并缩小上限，距视口至少 8px、距入口 4px。菜单挂载到 body，不参与步骤列表布局、不受编辑区裁切；内部滚动不触发重新定位，并阻止滚动穿透到编辑区。外部滚动或窗口变化才重新计算位置；视口恢复后允许恢复到正常高度。


## 19. 品牌名称与网页标题

当前产品显示名称统一为 `Gamer`。浏览器页面标题只使用 `Gamer`，不附加产品描述、页名或版本；登录页、工作台与管理页沿用同一文档标题。设置页版本卡可以显示 `Gamer <版本>`。启动提示、CLI 帮助、项目文档和发行说明使用相同大小写；新发行资产使用 `Gamer-<版本>-...` 前缀，打包、下载和验证端同步命名。


## 20. 投屏工具条分组与视频主操作

投屏上方保持两条语义行：首行为“设备”选择、连接/断开、刷新设备、设备更多操作，右侧为独立的“配置包”上下文；次行为“应用”选择、读取列表、启动、停止应用，右侧为“操控”组（截图、返回、全屏、键盘模式、更多）。设备、应用标签位于各自组左端；配置包与操控整组靠右，两组标签放在各自操作按钮之后、所在行最右端，均使用 12px 次级文字；键盘按钮显示“键盘：游戏 / 键盘：文本”，避免与应用运行状态混淆。

组内间距 6px，组间距 16px，两行以细线区分。投屏工具条上的普通操作按钮统一为 16px 线性图标加文字，保持 28px 高度与原有颜色；设备、配置包、操控的更多入口统一为 28×28px 单省略号图标，不带文字或额外箭头，保留 title 与可访问名称，菜单内部继续使用纯文字。停止应用紧随启动，使用危险动作样式，不再放在操控菜单内。设备、应用和配置包选择框使用 field-sizing:content 按当前选中文字加内边距及箭头所需宽度布局，不按候选列表最长项计算，也不拉伸填满余下空间；最大宽度不超过所在行，极长内容在窄面板内收缩。工具条变窄时优先按整组换行；单组仍放不下时允许组内继续换行，文字不隐藏、不压成纯图标，避免挤出视口或需要横向寻找。配置包与应用仍是两个独立上下文。

视频素材库标题独占一行；下方按“录制设备下拉、开始录制、刷新、导入视频”排列：开始录制为黄色主按钮，刷新和导入为普通灰色按钮；录制期间在同一位置换成“停止并保存 / 取消”。录制状态显示在操作区内，空间不足时另起一行；移除原有带边框的两行录制动作框。设备与动作在窄面板允许换行，不压缩按钮文字；录制设备仍是独立选择，不从配置包或 Android 应用推断。
