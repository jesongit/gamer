# Gamer 前端重写工作报告

日期：2026-09-19。设计基准：用户最后确认的 `gamer-centered-stage.html`（居中投屏、两行上方工具条、轻操作反馈条），以及此前逐次明确的紧凑编辑器、必填参数、图标操作和黑灰色系要求。

## 1. 交付范围与结论

本次修改真实 Vue 前端，沿用现有 Rust API、插件贡献、Package 资源、WebRTC 和 YAML V1 编辑模型。交互原型没有被当成产品页面嵌入，也没有将示例脚本、假设备或演示状态写进产品。

交付三部分：

1. [界面设计规范](../design/gamer-ui-spec.md)：设计语言、尺寸、布局、参数展示、编辑运行流程、弹窗、插件主题与状态桥协议、验收标准。
2. 实际前端实现：应用外壳、动态导航、居中舞台、配置入口、轻状态条、自动化/函数内联编辑器及其他功能面的样式与密度。
3. 本报告：功能清单、偏差、修正、验证证据和剩余限制。[实施记录](../plans/gamer_ui_rewrite_plan.md)记录基线与范围。

代码已构建到 `server/web-dist/`。没有发布到 Sites，没有建立外部站点，没有提交 Git。工作区开始时已有大量未提交的服务端、YAML、API 和测试改动，本次保留这些改动；不能把当前整个 `git diff` 都归为此次界面工作。

- 设备、Android 应用、配置包安排在投屏上方第一行，第二行承接截图、返回、全屏、游戏模式和功能菜单。

### 2.3 轻操作反馈条

实现 `operation-feedback.js`、`OperationStatusBar.vue` 与官方面板接入辅助函数。

- 底部 29px；左边是宿主相关当前操作，右边是当前插件操作，不显示“内核就绪/插件在线”等总览。
- 默认各半，分界独立于工作台分隔；支持拖动、方向键、Home/End、双击恢复均分，限制 20%–80%。
- 两侧内容在分界处裁切，悬停 title 显示该条完整文字与动作标签。
- 投屏点击/拖动结束发布像素和相对坐标，分别点击复制脚本可用数组；复制成功短暂提示，权限失败明确提示。
- 编辑器发布未保存/保存中/已保存、运行步骤和运行报错；主操作保存/运行/停止没有重复出现在状态条。
- 报错提供复制、详情和跳转。当前文档的直接运行错误按完整嵌套路径定位；无法确认文档或跨函数调用时显示详情。
- `status.set/status.clear` 接入现有 iframe 桥；身份取宿主注册信息，只接受当前面板；复制/详情/面板跳转为受控数据动作。
- `context.get` 增加主题快照。保留 iframe `allow-scripts` 沙盒，不增加 `allow-same-origin`，没有解除安全隔离。

| 用户要求/功能 | 实际处理 |

## 3. 与原型不同的地方及原因

| 原型意图 | 实际差异 | 判断/原因 |
| --- | --- | --- |
| 固定 1920×1080 示例画面 | 画面遵循实际来源比例、尺寸和剩余高度 | 必须支持竖屏、旋转和其他设备分辨率，避免拉伸和错误坐标 |
| 桌面两行工具条 | 窄窗口可变为更多行；媒体模式有来源选择浮层 | 保留真实控件、素材切换和只读提醒；800px 改为上下布局 |
| 静态功能按钮 | 插件功能按服务端贡献和 Android Targets 动态出现 | 安装/启用状态真实，Core 不预置业务面板 |
| 统一紧凑按钮 | 主工作台统一 28px；复杂表单和个别原有动作仍按内容自适应 | 不把长错误、权限、任务参数挤进固定小框 |
| 所有函数都像普通脚本编辑 | 默认 `_function.yaml` 可编辑；拆分 `_function*.yaml` 仍只读查看/运行 | 沿用项目已有资源编辑范围，未擅自改变文件拆分和跨文件写回规则 |
| 一条时间轴 | 项目制作页一条共享时间轴；离开项目页后舞台恢复独立播放条 | 只保留当前可操作的一个入口；独立挂载 Timeline 仍可用原生播放器 |
| 单一主画面 | 精确帧结果仍有按需小预览 | 模板保存必须以服务端确定帧为准，不能把浏览器预览冒充精确帧 |
| 简洁错误跳转 | 可确认的当前资源直接定位；跨函数/其他资源转详情 | 现有事件缺少完整调用帧身份，不猜测跳到错误步骤 |
| 所有操作都只占状态条 | 高频编辑/运行/输入已接入；部分管理动作仍保留原有 toast/局部结果 | 确认、导入错误、依赖门禁和长诊断不能只靠短条承载 |
| 全部自定义下拉 | 脚本、函数、模板参数继续使用原生 select | 保留键盘与平台可访问性；展开后的系统菜单外观会随平台略有不同 |
| 全套一致线性图标 | 主要舞台和步骤动作改 SVG；少量旧功能 emoji/字符仍存在 | 本次未重新绘制所有业务图标，已统一其外围控件尺寸与颜色 |
| 重命名即时反映 | 修改名称先成为编辑草稿，按保存提交 | 与正文使用同一版本冲突/校验机制，不绕过保存语义 |

## 4. 验收中发现并修正的问题

1. **导航挂载顺序**：Teleport 的目标尚不存在时可能导致 Vue patch 异常；挂载前禁用传送，挂载后再接入主导航。
2. **冷启动空面板**：注册表的普通 Map 不触发 computed 重算；显式订阅贡献列表，避免导航已经出现而页面仍空白；底部当前插件反馈采用相同订阅，冷启动后能显示保存状态。
3. **路由过早回退**：插件快照未返回前，不能把合法的插件书签改成任务页；等待首次发现完成后再判断无效路由。
4. **配置切换错误接线**：未保存检查引用不完整；改为 composable 提供守卫，正常切换可确认，外部切换不会静默丢草稿。
5. **只读配置上下文**：通过统一选择函数恢复上下文，并持久化最终接受的 ID，避免只读 computed 赋值失败或刷新后跳到错误配置。
6. **旧资源画布滞留**：切换 Package 后清空已保存旧模型和选择，新包候选到达后重新打开；迟到 GET 通过代次保护不能覆盖新模型。
7. **函数库误判不存在**：新建函数前强制刷新真实库；加载失败不继续新建，不覆盖已有函数库。
8. **保存退出画布**：显式保存改为 keepOpen，保留命令栈；旧调用者默认行为保留。
9. **从此运行丢起点**：保存可能重建 UUID；脚本/函数均在保存前保存步骤序号，成功后继续使用该起点。
10. **函数参数新增入口缺失**：内联参数声明区域明确开启新增参数按钮。
11. **配置详情重复弹窗**：舞台和全宽配置页复用上下文时，只保留当前页面的弹窗宿主。
12. **配置详情贴边**：移除对父级 scoped CSS 的隐含依赖，详情组件自身提供 12×16px 内边距。
13. **视频纵向重叠**：1366×768 下 flex 子内容被压缩；设置内容块不收缩，长内容按正常顺序滚动。
14. **素材选择无预览**：选择素材直接请求舞台切换；按 ID 加载的新素材补入舞台候选，避免空下拉。
15. **重复播放进度**：项目 Timeline 获得舞台控制权时隐藏舞台播放条，释放后恢复。
16. **状态条过期与复制提示**：切面板清空旧状态，后台 iframe 不能覆盖当前反馈；增加成功和失败的真实剪贴板反馈。
17. **分隔条点击后键盘无效**：拖动开始显式获取焦点，保持方向键与 Home/End 可用。
18. **错误定位依赖已清空状态**：使用终态仍保留的 RunRecord 核验完整 entrypoint；解析中文函数路径；跨调用不误跳。

## 6. 尚存缺失、限制及未验证项

以下不是伪造完成，也不应在后续开发中遗漏：

1. **真实 Android 端到端验证未执行**：隔离环境关闭 ADB。WebRTC 接管、真机触控坐标、截图/录制、全屏键盘、运行/停止实际游戏效果，需要连接目标设备再验收。原有相关自动化测试保留并通过不等于真机通过。
2. **拆分函数库写入仍未开放**：`_function*.yaml` 非默认库只读查看/运行；要全面开放编辑，需要单独梳理跨文件重命名、删除、冲突与选择行为。

8. **浏览器/性能覆盖有限**：实际可视验收在当前 Chromium 桌面环境完成；没有宣称 Safari/Firefox、移动触屏、屏幕阅读器全量验收；构建大 chunk 警告仍在。

## 10. 剩余事项逐项推荐方案

建议按“先验证真实使用，再补影响正确性的功能，最后收敛视觉与性能”的顺序处理。以下优先级是结合当前项目的判断，不是外部标准：P0 为下一次真实使用前，P1 为近期功能补齐，P2 为随相关功能迭代。

### 10.1 真实 Android 端到端验证：P0，优先安排

**推荐：选一台日常设备，先跑可恢复的最小验收流程。** 不必先建设完整设备测试平台。准备独立测试 Package 和可随时退出的应用页面，明确测试设备、应用、连接模式，避免与日常运行争抢 viewer。

执行顺序：

1. 1920×1080 虚拟屏连接、断开本页、重新连接；双浏览器接管确认；确认断开浏览器不会错误杀掉设备应用。
2. 在画面中心、四角及靠近有效画面边缘点击；比对像素坐标、0–1 相对坐标、复制结果与实际落点。调整分隔比例、窗口尺寸、全屏后重复。
3. 录制短片，包含点击、滑动和按键；停止后在素材库播放、逐帧定位、建模板并离线匹配，验证媒体模式不会把操作发给真机。
4. 在脚本中使用短等待、一次点击、可控失败，检查保存、运行只读、停止、错误详情与正确文档定位。
5. 测试镜像/竖屏一次；如果不日常使用，可列为次级覆盖，不阻塞虚拟屏主流程。

**完成标准：** 每项有设备/版本、实际结果和失败复现步骤；关键流程全部通过。真实环境问题先复现、再修，不能仅把单元测试通过记为真机通过。

### 10.2 拆分函数库编辑：P1，开放现有文件编辑，不增加文件管理层级

**推荐：用户仍然只选择函数；写回时由函数视图携带的真实 fileId 决定定义文件。** 继续统一函数命名空间，文件名不进入调用名。

第一阶段复用 `loadFunctionFile`、共享画布、资源 `expected_version` 和现有冲突弹窗，取消仅默认库可编辑的 UI 限制；编辑/删除始终写入所属文件，新函数仍默认进入 `_function.yaml`。下拉里用轻量来源提示区分拆分库，不要求用户先打开文件再选择函数。

函数重命名要与“资源文件改名”分开处理：先查当前已有引用处理能力。若不能原子更新当前 Package 内引用，明确列出受影响调用并阻止会留下坏引用的提交；补齐原子更新后再开放一键联动，不静默部分成功。实现归 gamer.yaml，不让 Core 解释函数名。

**完成标准：** 默认/拆分库都能选择、修改、保存和重新打开；同名冲突拒绝；删除最后一个函数有明确文件处理；并发版本冲突不丢内容；调用名称与移动文件无关。

### 10.3 跨函数运行错误定位：P1，优先于外观清理

**推荐：从执行事件中携带准确定位信息，不解析错误文案猜位置。** 这是需要补契约的功能。

在 gamer.yaml 的解释器/宿主事件链补齐一次调用的身份：run_id、调用帧标识、父帧标识、函数目标、定义资源三元组和该资源内的 step_path；记录执行时资源版本或内容摘要。现有 Core 运行记录和事件通道负责传输，YAML 路径的解释仍归插件。

前端点击报错后：核对 run_id → 打开定义文件和函数 → 比较执行版本与当前版本 → 展开祖先步骤并定位。当前有未保存草稿时先保留草稿并展示只读错误位置；不能为了跳转覆盖当前编辑。源文件已改动/删除时展示执行时信息和明确版本差异，不把旧步骤号硬套到新文档。

**完成标准：** 脚本→函数→嵌套函数、递归、中文函数、repeat/if 深层步骤、执行后改文件、不同 Package 同名函数均定位正确。契约完成前保留现有详情退路。

### 10.4 iframe 风格统一：P1 提供轻量接入包，保留隔离

**推荐：在 SDK 中提供可选的 Gamer 主题 CSS 和少量基础 HTML 示例。** 通过现有 `context.get().theme` 映射 CSS 变量，覆盖按钮、输入框、下拉、间距、空态和错误态；若以后真的支持动态主题，再加主题变化事件。

简单表单优先现有 declarative 面板；复杂自定义面板继续 iframe。官方插件遵循同一主题规范，第三方可选择接入；不要求为了接入主题安装一整套重型框架，也不访问父页面 DOM。iframe 本身是独立文档环境，保留 sandbox 符合其隔离模型。[MDN iframe 文档](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/iframe)

**完成标准：** 提供一个独立 iframe 示例，使用实际握手、主题变量和状态条；深色背景下所有交互文字可读，Tab/焦点/窄面板可用；不增加 allow-same-origin 或取消 CSP 来解决样式问题。

### 10.5 管理动作反馈：P1，统一语义，不把所有消息强塞进状态条

**推荐：为现有操作定三条明确规则，继续复用当前反馈机制。**

| 场景 | 推荐展示 |
| --- | --- |
| 当前操作的短结果，如截图成功、模板匹配、保存完成 | 轻状态条；只附复制、详情、定位等便利动作 |
| 字段/保存校验失败，需要用户在原处修正 | 对应字段或表单内提示；状态条可给简短摘要 |
| 需要立即处理的异步全局失败或权限确认 | 短 toast 或明确对话框，详情留在相关页面 |

先接模板上传/替换/匹配，再接配置包导入导出，最后系统管理。左侧宿主反馈和右侧插件反馈各自只保留当前一条；后台旧请求返回不能覆盖新操作，不把保存/运行主按钮再放到底部。不需要增加一个全局通知中心或历史消息数据库。

**完成标准：** 同一次成功不同时出现 toast、局部绿框和底部三份重复提示；失败仍有可找到的详情；切包、切设备、切面板后没有过期结果。

### 10.6 录制会话历史：P1/P2，复用 Core 的真实会话元数据

**推荐：为现有 recording 持久化记录增加轻量列表查询，而不是从媒体文件名推断会话。** 先确认当前元数据能否完整列举，缺少列表能力时再补查询端点；V1 不为此另建通用分析库。

列表最小字段：会话 ID、设备、开始/结束时间、状态、中断/失败原因、素材分段 ID、事件数量。服务启动时将未正常结束且没有活跃录制的会话标为中断；素材被删除时保留历史并标记缺失。视频插件只消费 Core 提供的记录，不自行读 Core 私有目录。

UI 采用紧凑记录列表，默认最近记录，点击展开分段；预览/进入草稿直接可达。清除历史与删除素材是不同动作，已有引用保护继续生效。

**完成标准：** 正常停止、取消、设备断线、编码变化分段、服务重启、素材缺失都可区分；录制来源能准确进入草稿，不产生虚构会话关联。若短期只用手动导入视频，这项可放 P2。

### 10.7 图标与残留样式：P2，逐页收敛，避免再做一次全面重写

**推荐：继续使用现有 UiIcon、主题令牌和控件基类。** 按工作台→任务/模板→视频→设置/市场顺序替换旧 emoji/字符图标，优先统一相邻按钮。

整理同一文件里叠加的 scoped 覆盖规则，把最终有效颜色、高度和间距并回原规则；保留特殊业务布局，不用大量 !important 强压。不要趁样式清理改变运行、资源和权限逻辑。

**完成标准：** 主要按钮 28px、同组同高，图标有名称与提示；复杂表格不隐藏有效文字；已启用控件文本对比达标；1920/1366/800 三种宽度有可比的验收记录。

### 10.8 浏览器与性能：P1 建基线，P2 按数据优化

**推荐：先以实际主要使用的桌面 Chromium（Chrome/Edge）作为支持基线，再扩展 Firefox；Safari 和移动触屏按真实使用需求补测。** 跨浏览器测试不能只看页面渲染，还要覆盖 H.264 协商、播放、自动播放限制、剪贴板、全屏和键盘输入。WebRTC 存在规定的必备编解码器，但具体 H.264 参数与运行链路仍需实测。[MDN WebRTC 编解码器文档](https://developer.mozilla.org/en-US/docs/Web/Media/Guides/Formats/WebRTC_codecs)

性能先记录冷启动下载量、首次打开工作台时间、编辑 100/500 步时的响应和连续切页内存。再按面板惰性加载视频工作台、市场/插件管理、原文编辑等较重内容；共享编辑器依赖单独复用，避免重复加载。Vite 支持基于动态 import 的异步加载优化，但仓库当前 Vite 5 的具体配置须以安装版本为准，不为消除警告直接改高体积阈值。[Vite 异步加载说明](https://vite.dev/guide/features.html#async-chunk-loading-optimization)

**完成标准：** 有优化前后相同设备/网络的测量；主流程不增加明显等待；切换后的状态、样式和插件注册无退化。键盘可访问性先覆盖页签、拖动替代、弹窗和编辑器，再逐步增加屏幕阅读器检查。

### 推荐实施批次

1. **第一批：** 真机关键流程 + 桌面浏览器基线，确认现在的主要使用链路可靠。
2. **第二批：** 跨函数定位契约与拆分函数库编辑，解决正确性和操作能力缺口。
3. **第三批：** 状态条剩余操作接入、iframe 示例接入包、录制历史（有录制需求时提前）。
4. **第四批：** 图标/样式清理与依据实测数据的分包优化。

建议按这四批分别验收，保持每批可回归和可撤销；不把所有后续事项再次捆成一次大型改写。

## 11. 顶栏合并

Gamer 字标、工作台等主导航、账户和退出登录合并为一条 48px 顶栏，移除常驻服务就绪状态与版本号；导航挂载位置从 Console 内容区移至 MainLayout 顶栏。内容区增加约 40px 可用高度，投屏仍按原比例居中。前后端版本不一致的条件式提示保留。较窄桌面窗口缩小导航水平间距。

验证：5 个相关测试文件、96 项测试通过，生产构建成功，既有主块体积警告保留。日常服务浏览器处于未登录状态，本轮未完成登录后的实际布局验收；没有操作真实设备或改变认证配置。

## 12. 投屏右拖边界随可用高度计算

取消投屏最多占 65% 的固定上限，改为按实际投屏容器高度 × 16/9 计算最大有效画面宽度，右侧编辑区最低 320px，向左仍为投屏保留至少一半宽度。默认比例和浏览器保存偏好继续保留；实际渲染与键盘调整均受动态边界约束。ResizeObserver 同时观察工作区和画面容器，工具条高度或窗口变化会重算；隐藏舞台与全屏尺寸不覆盖正常高度。

示例：总窗口宽 1920px、分隔条 6px、有效画面高 800px 时，左侧最多约 1422px，右侧约 492px。若高度足以让 16:9 画面挤占编辑区，则优先保留 320px 编辑宽度，画面继续等比居中。

验证：3 个相关测试文件、30 项测试通过，覆盖拖动两端边界、高度变化、隐藏舞台和键盘调整；生产构建成功，相关文件 `git diff --check` 通过。本轮未新增登录后的浏览器或真机验收。
