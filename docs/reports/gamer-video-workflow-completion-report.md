# 视频工作流补齐报告

日期：2026-09-20。视频插件：gamer-video 1.0.1。

## 核查结果与修正

| 原问题 | 修正后的行为 |
| --- | --- |
| 历史“查看”直接跳草稿，零事件也跳转，详情刚展开就卸载 | 详情留在素材库；“生成脚本”独立操作，零事件、事件丢失、录制未结束时禁用并解释 |
| 完成状态掩盖素材已被删除 | 完成状态与资源可用性分别显示，标明视频不存在、无操作记录或操作记录丢失 |
| 无素材的历史无操作可做 | 增加两次点击确认的历史清理；服务端拒绝活动录制或仍有关联视频的删除，保持引用保护 |
| 草稿要求手填会话 ID，初次带来源挂载不加载 | 改为录制下拉，来源直接带入并自动读取，空状态说明如何录制，支持刷新与失败重试 |
| 视频内部切换页签丢草稿 | 保留草稿组件实例；选择、注释、文本、保存名保留；隐藏时不占用状态条 |
| 新建项目没有录制关联 | 依据真实录制分段的 media_id 关联会话；存储仅含 recording_id，设备上下文从历史读取，遵守服务端严格 schema |
| 项目和素材入口之间衔接不清楚 | 素材选中后可预览或直接创建制作项目；录制停止和导入后选中视频，不强制进入草稿 |
| 切换录制设备使事件异步响应失效 | 录制来源与运行上下文分别管理；上下文变更不取消仍属于该会话的事件读取，未知设备不套用当前应用 |
| 时间轴切换素材仍可能出现旧事件响应 | 素材或会话变更递增请求代次，丢弃迟到结果并恢复加载入口 |
| 删除项目后解除媒体引用失败无重试入口 | 保留失败状态，项目详情关闭后仍可重试解除引用 |
| 删除当前视频后舞台保留旧来源 | 成功刷新时同步舞台素材列表，当前媒体不存在则返回实时来源 |

分段原因使用中文说明。新增使用引导和完整文档，明确素材库、项目、草稿各自的作用。缺配置时不能生成绑定空配置的草稿，避免保存按钮无实际效果。

## 接口与数据

- GET `/api/recording` 新增 `events_available`，保留 `missing_media`；列表不再把终态等同于仍可使用。
- DELETE `/api/recording/:id` 清理终态历史和残留事件；有关联媒体或活动录制返回 409，未找到返回 404。删除前校验媒体根边界和来源所有权。
- 事件文件丢失时，内存会话与重启后恢复会话都明确报错，不伪装成空事件列表。
- 没有修改 YAML 语法、项目 schema、设备运行目标或自动运行策略。生成、保存脚本都不会自动执行。
- 原有用户录制历史未自动删除，用户可在新入口明确清理。

## 验证

- 前端全量测试：731 个宿主测试、188 个自动化插件测试、7 个视频插件测试，共 **926 通过**。
- Rust 录制测试：**15 通过**，覆盖删除守卫、重启后清理、内存会话事件丢失、分段与事件映射等。
- 前端生产构建及官方 `.gplugin` 打包、摘要和归档校验通过。
- Chrome 1920×1080，独立服务端及独立数据目录，使用真实 HTTP、插件、FFmpeg 视频、确定帧、资源保存与引用接口：
  1. 从页面导入视频并自动预览。
  2. 孤立历史显示原因、禁用生成，确认后删除；关联视频存在时服务端拒绝删历史。
  3. 创建项目，读取资源确认录制来源正确。
  4. 提取精确帧、框选模板、真实保存、离线匹配命中。
  5. 勾选事件、注释、生成脚本，切换页签后保留编辑。
  6. 保存脚本、跳转自动化编辑器，重新读取确认文件存在。
  7. 项目引用阻止媒体删除；删除项目并完成引用同步后允许删除媒体，再清理历史。
- 浏览器上述路径无未处理页面异常。操作记录使用符合真实格式的测试夹具，**未重新实测 Android 真机采集及输入注入**。
- 本地后端已重建重启，已安装视频插件通过更新接口升级至 1.0.1；使用时需刷新页面加载新模块。

## 仍然存在的边界与建议

1. **跨页面重载的未保存草稿**：此次保留视频内部页签状态，刷新页面、关闭页面或卸载面板仍会丢失未保存编辑。当前先保存脚本或复制文本；后续若需要恢复，可按配置和录制 ID 存浏览器恢复草稿，恢复前复核来源，不自动覆盖服务端脚本。
2. **事件文件随首段媒体删除**：沿用现有 Core 存储。先生成并保存脚本再删除视频；缺失状态现已正确呈现。若需要“删视频、留操作”，应再把事件日志所有权统一移至会话归档，避免双份日志和不明删除语义。
3. **跨分段制作**：项目可引用多个视频，但当前时间轴制作针对主素材。需要其他片段时设置主素材或另建项目；界面说明切换方式。未新增多轨剪辑或自动拼接。
4. **脚本内容不是自动复现保证**：等待、滑动时长仍为建议；文本脱敏、不支持事件和异常恢复需要人工补全，保存后到自动化编辑器检查再运行。
5. **真实设备验证**：建议在实际使用设备上录制一次点击、滑动和按键，核对事件时间与分段画面。此次使用模拟操作日志验证后半链路，不把它当作真机录制通过。

## 追加修复：暂停匹配、播放结束框选与重复素材

- 模板列表及步骤测试原先仍向实时设备请求匹配，现按舞台来源选择：视频模式冻结当前帧，以 `media_id + frame_index` 测试，无需设备连接；切换画面后不展示迟到的旧结果。
- 播放器结束位置可能超过末帧 PTS，现先解析展示帧索引，播放位置在两帧间取前一帧、结尾取最后一帧，再以同一帧身份截取和匹配。后端“首个 PTS 不小于请求值”的查询契约保持。
- 第一段录制复用起录媒体目录，媒体列表过滤尚未完成的 importing 元数据。现存空占位记录只隐藏，保留其操作事件；用户删完实际视频并明确删除历史后，才清理空占位元数据和事件。
- 追加后前端全量 **931 通过**（宿主 736、自动化插件 188、视频插件 7）；Rust 录制 **16 通过**，媒体相关 **29 通过、2 个既有用例忽略**。独立 Chrome 1920×1080、真实服务端/FFmpeg/插件测试通过：暂停在两帧之间，从模板页框选保存后匹配命中；实际播放结束后框选保存并匹配末帧命中；全过程无设备连接、无页面异常。
- 前后端生产构建、插件归档验证通过。本地后端已重建重启，自动化插件已通过更新接口升级至 **3.1.3**。只读复核实际素材库剩 **1 条可播放视频**，原有录制 **36 条事件仍可用**。需要刷新浏览器加载最新模块。
- 未重新进行真实 Android 设备录制；首段目录复用与真实分段保留由录制回归测试验证。浏览器验证数据与用户数据分开。
