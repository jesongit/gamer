# Autonomous script repair

The user authorized implementation on 2026-10-09. Repair rounds default to zero
(unlimited); no-progress detection and fresh evidence govern retries. A request
binds one package, candidate, script, device, immutable sample set, and completion
contract. Model output cannot broaden that authority.

The opt-in autonomous mode may apply private proposals, validate all samples,
run the frozen candidate through the production interpreter and Core lease,
diagnose terminal failures, and publish a successful unchanged revision when
auto-save was authorized. Legacy one-trial/manual-save behavior remains available.
Cancellation revokes subsequent actions and drains any current trial. Restart
retains the workflow journal but never replays historical inputs.

Private templates are immutable resource leases, not temporary formal files.
Failures preserve actual run source and evidence. Required completion checks,
threshold floors, samples, arguments and task goal survive repair. Scripts must
observe current completed states before resource-consuming steps; a checkpoint
only passes after its expected template is observed in this run.

Acceptance covers unlimited/finite budget semantics, authorization/revocation,
candidate isolation, shared interpreter/control behavior, no-progress policies,
goal preservation, concurrent-edit protection and rollback. Local fixtures,
real provider calls and actual game completion are reported separately.

Model requests compact older automation receipts while retaining the newest
explicit source reads, failure diagnostics and image identities. The durable
journal remains complete. Request context keeps three recent images; a failed
read does not replace the last successful source read. Mutation receipts reflect
the bound apply/save authority instead of asking for already granted approval.
Browser preparation recaptures a changing page within a bounded startup window;
ordinary screenshots and inputs still reject retired frame identities.
Actual observation matching uses only the latest bound observation or the
selected run's Trace image, retains production thresholds, and never grants a
validation/execution receipt. Focused candidate reads return exact current JSON
paths and bounded source fragments for local patches.
# 完成条件中的错误别名修复

工作流在首次冻结完成条件时保存其视觉目标绑定。原生函数误用目标别名后，可以修成原绑定的实际模板文件；目标模板和完成项 ID 不能替换，阈值只能保持或提高。旧工作流只从已应用候选快照补齐绑定，不使用待审核提案推导原目标。区域与等待参数仍不属于完成谓词。素材验证和真实运行通过条件保持不变。

同一对话收到新的监督消息后，旧自动化回答在下一次模型请求之前或工具执行之前结束，未执行的工具调用写入中断回执，新消息随后按队列处理。旧回答不得因权限已撤销继续产生模型和工具重试；该行为不依赖有限的重试预算。

自动化对话采用网络无响应超时：持续返回流式数据的完整提案允许超过普通聊天的单次总时长，连接超时、读取静默超时、响应大小限制、取消与整体任务预算仍然生效。普通聊天和游戏决策保持原单次总时长；素材批量生成仍有外层请求预算。

单帧模板诊断在原搜索区失败时，可以额外返回同一原始帧上全画面的最佳几何位置；`failure_stage: region` 表示符合原阈值的模板被搜索区截掉。实际 `found`、搜索区、阈值和执行权均不变，这个额外位置不能充当通过素材回放或输入授权。

自动任务遇到可识别的暂时性模型网络错误、HTTP 429/5xx 时，在同一授权消息下退避重试，等待从 500ms 递增至 30s。零预算保持不限次数；非零失败/时间/令牌预算仍生效。新消息和取消可在等待期间撤销旧回答，解析不完整的工具调用不会执行。认证错误、输出格式错误和输出上限不按网络错误盲重试。
