## 1. 本轮目标与范围

本轮覆盖全部当前官方插件及其公共交互：

| 范围 | 包含内容 |
| --- | --- |
| 插件中心 | 安装、启用、停用、更新、卸载、版本处理、依赖提示、失败恢复 |
| gamer.yaml | 自动化可视化编辑、参数编辑、Package 函数、模板管理、匹配测试 |
| gamer.keymap | 方案选择、编辑、保存、应用、输入录入、投屏标记、输入释放 |
| gamer.video | 素材、录制会话、项目、时间轴、确定帧、校准、模板与草稿联动 |
| 必要公共机制 | 异步请求保护、编辑上下文、资源安全提交、媒体引用、Stage 联动 |
| 验收 | 前后端契约、故障恢复、浏览器流程、设备输入与正式构建 |

本轮目标不是“每个后端接口都有一个按钮”，而是：

1. 用户可以通过前端完成已有能力对应的完整工作流程。
2. 可视化编辑结果符合实际 YAML 与 Keymap 语义。
3. 保存、替换、切换、更新等操作不会丢数据、串上下文或产生隐式副作用。
4. 插件状态由系统处理，不要求用户手动理解并操作内部状态机。
5. 所有完成结论都有对应测试证据。

### 1.1 保留的已确认设计

- Core 负责设备、输入、画面、媒体、资源、调度等通用机制；插件负责业务。
- 插件功能保留在右侧插件功能区，不重新向投屏顶部堆积插件按钮。
- Android 应用、Package、Plugin、StageSource 是不同上下文，不互相替代。
- 普通插件不强制签名，继续保留完整性、权限和运行时边界。
- 视频插件当前的 builtin 定位不因本轮修改而改变。
- YAML 保留唯一解释器，不新增第二套执行器。
- 面向用户的函数来源仍只有插件函数和当前 Package 函数。
- Package 默认函数文件仍为 `automations/_function.yaml`。
- `_function*.yaml` 仅作为额外函数文件的加载规则。
- 前端只维护默认 `_function.yaml`，不增加多文件函数库管理页面。
- 不恢复 `functions/` 专属目录，不增加 `tools/` 分类，不引入 `kind` 类型声明。
- `find` 保持单次匹配；`wait_find` 等继续属于插件便利函数。
- `stop_app` 不顺带断开设备或终止当前 Runner。

### 1.2 本轮不做

不重写插件运行时，不建设复杂依赖管理器，不增加分布式 RPC、通用工作流引擎或公共插件审核平台。

不强制将所有官方插件迁移到 WASM，不开放任意 Native 动态库加载，不恢复插件签名流程。

不扩展 YAML 表达式语言，不增加算术表达式、字符串插值、动态索引、try/catch 等新语法。

不把视频工作台扩展成复杂剪辑软件，也不新增 AI 自动生成完整脚本功能。

## 4. 全阶段公共约束：上下文、异步与编辑状态

本节适用于所有插件。优先抽取少量公共工具或复用现有机制，不建设新的全局状态框架。

### 4.1 异步请求必须绑定发起上下文

在请求发出前捕获必要信息：

```text
Package ID
Plugin ID
资源 ID
资源版本
当前草稿版本
设备或媒体 ID
Stage generation / 校准版本
请求序号
```

只携带该操作确实需要的信息，不为所有接口强制设计庞大的通用对象。

要求：

- [ ] 函数选择、方案选择、项目打开、事件读取、确定帧读取均有过期结果检查。
- [ ] 切换上下文时立即使旧请求失效，即使新上下文暂时没有发出请求。
- [ ] 请求返回后不得重新读取当前响应式 Package ID，再把旧结果写入新 Package。
- [ ] 旧请求的 finally 不能清除新请求的 loading/saving。
- [ ] 按稳定资源或步骤 ID 关联结果，不仅按列表下标。
- [ ] 取消请求可作为优化，但仍保留响应代次检查。
- [ ] 请求失败与正常空列表是不同状态，不用清空列表掩盖失败。

### 4.2 保存必须保护新编辑

- [ ] 保存请求绑定提交时的资源、版本与草稿快照。
- [ ] 保存期间再次编辑后，旧保存成功不能将新改动标记为已保存。
- [ ] 保存期间防止重复提交同一操作。
- [ ] 允许继续编辑时，以草稿版本判断哪些内容已提交；不支持时明确禁用编辑。
- [ ] 原资源保存成功不能关闭后来打开的另一份草稿。
- [ ] 服务端版本冲突不得自动 force 覆盖。
- [ ] 保存失败保留本地编辑内容，并提供实际可执行的重试。
- [ ] 返回列表、切换资源、切换 Package、关闭编辑区域时保护未保存内容。

未保存提示采用必要的三种选择：

```text
保存后继续
放弃改动
取消切换
```

不要每次点击普通按钮都弹确认框。只有确实会丢失编辑状态时才询问。

### 4.3 状态与提示

区分：

```text
加载失败
无数据
数据已过期
保存失败
保存成功但后续同步失败
权限不足
依赖不可用
```

成功提示不得被随后的刷新立即清除。

前端提示不代替服务端校验；服务端校验也不代替前端合理交互。

## 5. Phase 1：优先修复资源与状态正确性

本阶段优先处理可能丢数据、失去引用保护、使用错误配置或错误帧的问题。

### 5.1 模板覆盖改为安全替换

处理 T01。

禁止继续使用：

```text
deleteTemplate
→ createTemplate
```

实现要求：

- [ ] 优先复用现有模板替换能力；缺少必要字段时补齐同一服务路径。
- [ ] 新图片完整读取、校验和处理成功后，才提交替换。
- [ ] 上传失败、图片非法、处理失败时旧模板仍然存在。
- [ ] 使用现有资源版本或等价并发检查，防止覆盖其他页面刚保存的版本。
- [ ] 模板图片、名称和搜索区域等关联元数据保持一致。
- [ ] 存在文件名变化时，作为明确的重命名/替换操作处理，不留下半更新状态。
- [ ] 所有入口统一走同一替换逻辑：模板页、框选覆盖、视频模板制作。
- [ ] 真正删除模板仍要求明确删除操作，不由覆盖流程提前执行。

验收：

模拟新图上传或处理失败，旧模板内容和引用保持可用；成功替换后只存在正确的新版本。

### 5.2 媒体引用与项目提交一致性

处理 V01、V02、V03。

先修正前后端引用字段契约，避免 Workbench 传入对象与 API 封装读取对象不一致。

引用同步不能只依赖浏览器当前项目列表，也不能简单通过“先刷新一下列表”掩盖多窗口并发问题。

推荐处理方向：

- 项目 JSON 的业务解释归 gamer.video。
- 通用资源提交、引用保存和删除保护归 Core 机制。
- 由视频业务保存路径或插件保存钩子，根据本次提交后的项目状态维护引用。
- 不把视频项目 JSON 的解析写进 Core 通用资源服务。

具体要求：

- [ ] 统一引用对象格式，转换只在明确的 API 边界进行一次。
- [ ] 按本次成功提交后的项目集合计算引用，而不是旧前端摘要。
- [ ] 一个素材被多个项目使用时，删除其中一个项目不能解除其他项目的保护。
- [ ] 只更新当前授权 Package/插件作用域内的引用，不覆盖其他 Package 或插件的引用。
- [ ] 更新引用时有并发保护，不采用无版本检查的“读全部—前端改—写全部”覆盖模式。
- [ ] 项目创建、保存、素材替换、删除使用一致的引用维护路径。
- [ ] 核对 Package 导入、复制、覆盖、删除是否绕过引用维护。
- [ ] 媒体删除检查与引用更新不能竞态地允许删除仍被使用的素材。
- [ ] 项目缺失素材属于可诊断状态，不能把缺失记录直接删掉来让项目看起来正常。

优先将项目提交和必要引用维护组成一次业务操作。

如果文件与元数据确实不能原子提交，应提供最小的待完成标记、补偿或重试机制，保证部分失败时媒体仍受到保守删除保护。不要承诺无法实现的“跨文件和数据库绝对原子”，也不要只依赖前端再次点击保存修复。

前端至少区分：

```text
项目已保存，引用同步完成
项目已保存，引用同步失败
项目保存失败
```

引用失败时提供独立且可点击的“重试同步”，不要求先修改项目使其重新变脏。

### 5.3 视频确定帧与预览位置

处理 V04。

明确区分：

```text
预览位置
    浏览器当前播放或 seek 的位置

制作帧
    服务端已解析的确定帧身份
```

要求：

- [ ] 用户主动播放、拖动进度或切换素材后，使旧制作帧失效。
- [ ] 由程序显示确定帧而触发的 seek，不得错误地立即清除刚锁定的帧。
- [ ] 创建模板、添加标记、相邻帧操作使用明确的素材和确定帧身份。
- [ ] 帧请求返回后校验媒体、请求代次和校准版本。
- [ ] 旧帧请求不能被重新解释为新素材上的同一帧序号。
- [ ] 锁帧失败时禁止制作操作，不静默退回旧帧。
- [ ] 校准或来源改变时清理不再有效的命中框、取点和裁切状态。
- [ ] 相邻帧继续使用服务端真实帧索引，不恢复固定 33ms 步进。

验收流程：

```text
锁定帧 A
→ 拖动到 B
→ 创建模板或加标记
→ 使用 B 对应的确定帧，而不是 A

素材 A 请求未完成
→ 切到素材 B
→ A 请求返回
→ 不影响 B 的帧、标记和制作入口
```

### 5.4 录制会话与草稿状态绑定

处理 V05。

- [ ] 录制会话切换时同步处理事件列表、选择顺序、注释和草稿来源。
- [ ] 不通过 loadedOnce 阻止新会话读取自己的事件。
- [ ] 旧会话请求返回后不能覆盖新会话。
- [ ] 会话为空或读取失败时，不能继续提交上一会话的事件 ID。
- [ ] 服务端验证事件属于指定录制会话。
- [ ] 已编辑草稿切换来源时，提供保留、放弃或取消，不静默丢弃。
- [ ] 保存草稿绑定生成/编辑时的 Package，不能在请求完成后误跳到另一个 Package。
- [ ] 事件重排不能产生负等待或静默猜测时序；无法转换时返回诊断。

### 5.5 Keymap 方案应用与保存保护

先处理 K02、K04，完整交互在 Phase 4 完成。

- [ ] 方案详情请求绑定 Package、方案 ID 和请求序号。
- [ ] 只有最后一次有效选择可以更新实际应用模型。
- [ ] 方案读取失败时保留明确的旧状态或安全停用状态，不显示 B 却实际使用 A。
- [ ] 修正 saving 上下文传递。
- [ ] 保存函数自身增加重入保护，不能只依赖按钮 disabled。
- [ ] 保存结果只能更新原草稿，不能关闭后来打开的另一份编辑内容。
- [ ] 取点请求绑定稳定 binding ID，不能因删除或排序后写入另一条绑定。

### 本阶段验收

所有 P0 项都应有确定的失败测试和修复后的回归结果，再进入大范围 UI 调整。

## 6. Phase 2：插件中心按用户操作自动完成流程

### 目标

保留底层生命周期守卫，在其上增加最小的用户操作编排。

用户表达的是“更新”“卸载”，不应该收到“运行中，请先手动停止”后自行完成状态转换。

### 6.1 操作行为

| 用户操作 | 系统行为 | 需要确认的情况 |
| --- | --- | --- |
| 安装 | 检查包与权限，安装成功后按默认产品行为启用 | 新权限、来源、执行形态及缺少依赖 |
| 启用 | 处理已安装的必需依赖，再启动目标 | 需要改变其他插件状态时说明影响 |
| 停用 | 自动停止实例并停用 | 活动任务、录制、未保存内容或必需依赖方 |
| 更新 | 预检查，记录原状态，停止，更新，恢复原状态 | 权限增加、依赖影响、活动业务 |
| 卸载 | 自动安全停止，卸载，默认保留数据 | 删除本身、依赖方影响 |
| 删除数据并卸载 | 安全停止后按确认范围清理 | 始终明确确认删除范围 |
| 重试启用 | 基于当前真实状态重试 | 不重复执行已经成功的破坏性步骤 |
| 历史版本处理 | 复用已有版本能力并自动处理停止/恢复 | 不兼容、权限和数据格式变化 |

历史版本 UI 按当前实际支持能力处理：

- 已有正式版本切换接口时，提供可理解的切换/回滚入口。
- 尚未支持时，不能只列出版本号就宣称可以回滚。
- 本轮不为历史版本建设复杂多版本管理系统。

### 6.2 更新的正确顺序

```text
获取目标版本
→ 下载并校验完整性
→ inspect manifest、权限、执行类型、宿主和依赖兼容性
→ 计算影响范围
→ 必要时确认一次
→ 重新检查当前版本和状态
→ 阻止新调用/新任务进入
→ 安全停止受影响实例
→ 提交更新
→ 恢复原有启用/运行状态
→ 刷新能力与面板
→ 展示完整结果
```

先下载、检查，再停止，避免下载失败也让用户的插件停机。

要求：

- [ ] 本地导入、市场更新、URL 导入中的同 ID 更新共用同一流程。
- [ ] 权限确认绑定目标包内容和 manifest，不只信任前端布尔字段。
- [ ] 用户确认后状态或版本改变，重新检查影响，不能按过期方案继续。
- [ ] 原来 Running 的插件更新成功后恢复 Running。
- [ ] 原来 Disabled 的插件更新后保持 Disabled。
- [ ] 更新失败保留旧可用版本。
- [ ] 新版本启动失败时，在安全条件下恢复旧实现，并如实报告结果。
- [ ] 已发生用户数据迁移时，不盲目自动回滚数据。
- [ ] 不把插件升级成功与插件重新启动成功混成一个状态。

builtin 插件需要特别处理：

插件包更新不等于替换已经编译进 Gamer 的业务代码。目标能力需要新版宿主时，应提示升级 Gamer，不通过反复安装 manifest 假装完成代码升级。

### 6.3 依赖影响

- [ ] 对必需依赖按实际运行关系计算受影响插件。
- [ ] 停止按逆依赖顺序，恢复按正向依赖顺序。
- [ ] 更新共同依赖前，展示会临时停止哪些插件。
- [ ] 卸载目标时，可以在确认后停止依赖方，但不自动卸载依赖方。
- [ ] 可选依赖方不整体停用，只降级对应功能。
- [ ] 缺失依赖提供明确安装入口，不静默下载未知来源插件。
- [ ] 不自动授予依赖新增权限。
- [ ] 依赖不兼容时在停止前报告，不先破坏当前可用状态。

不建设自动解版本、锁文件、多版本依赖求解等机制。

### 6.4 三类插件的停止与恢复边界

#### 自动化

- 正在执行的 Run 需要明确取消或等待安全结束。
- 在生命周期写锁等待之前，正确处理取消信号，避免等待自身持有的执行租约。
- 不为更新而直接销毁仍被执行使用的实例。
- 恢复插件只恢复能力，不自动从头重跑被中断脚本。
- 维护期间不要默认补跑错过的一次性任务。

#### Keymap

- 停止、更新和切换前释放已发送的按键与触控。
- 不能只清空前端 pressed 集合而不发送必要释放操作。
- 恢复插件可以恢复方案选择，但不恢复旧按住状态。
- 必须等待新的真实输入再发送 down。

#### Video

- 识别本次操作会影响的录制会话。
- 有录制时说明影响，默认优先安全停止并保存，而不是直接中断封装。
- 取消录制属于明确操作，不以“卸载”隐式替代。
- 录制结束失败时给出结果，不继续删除仍被占用的资源。
- 不停止其他用户或其他作用域无权管理的录制。
- 恢复插件不自动重新录制。

### 6.5 编排所在位置与并发

权威执行尽量放在服务端现有扩展管理服务，前端负责发起、确认和展示。

- [ ] 不只在 Vue 中串联多个请求，导致关闭面板后流程丢失。
- [ ] 同一插件的互斥管理操作不能并发执行。
- [ ] 重复点击、网络重试能够返回已有操作结果或安全拒绝，不重复卸载。
- [ ] 涉及多个插件时使用稳定的锁顺序。
- [ ] 不持有全局生命周期锁执行下载、长耗时录制收尾或插件业务。
- [ ] 复用已有操作锁、调用门禁和状态持久化。
- [ ] 需要恢复信息时只补最小操作记录，不建设通用工作流引擎。
- [ ] 页面刷新后能够从服务端重新获得真实结果。
- [ ] 部分成功时明确报告已完成、失败和待恢复项。

### 6.6 插件中心 UI

- [ ] 市场区分“未安装”“已是当前版本”“有更新”“本地版本较新”。
- [ ] 不对相同版本无条件显示更新。
- [ ] 同版本不同内容按现有不可变版本策略明确拒绝或要求明确修复操作。
- [ ] 展示检查、停止、安装、恢复等必要进度，不要求用户逐步点击。
- [ ] Failed 提供有意义的重试入口和原因。
- [ ] 成功提示在刷新后仍可见。
- [ ] 删除数据说明实际范围，不使用模糊的“清理全部”。
- [ ] 依赖提示提供跳转或启用入口，保留用户当前工作上下文。

### 验收

正在运行的插件可以通过一次“更新”或“卸载”操作完成安全流程。只有真正涉及权限、数据或其他业务影响时才要求用户决策。

## 7. Phase 3：自动化、函数与模板编辑完整修复

### 目标

以实际 V1 Schema 和解释器语义为依据重做表单，不再把 YAML 的内部表示直接暴露为主要编辑方式。

### 7.1 唯一的函数 Schema 消费路径

统一：

```text
函数目录 / Package 函数声明
→ 标准参数 Schema
→ 表单模型
→ 编辑命令
→ YAML 序列化
```

下列路径必须共用：

- 添加函数步骤。
- 切换步骤函数。
- 加载已有脚本。
- 编辑函数内部步骤。
- 复制、粘贴或其他已有快速创建入口。
- 函数测试及运行参数表单中可以复用的部分。

要求：

- [ ] 表单字段遍历 Schema，不只遍历已经存在的 args。
- [ ] 必填且没有默认值的字段立即显示。
- [ ] 未填写状态与合法 null、false、0、空字符串分开处理。
- [ ] 不自动填入 0 坐标、空模板等伪有效值掩盖缺失。
- [ ] 可选参数默认折叠或按重要性展示，不让高级参数淹没核心参数。
- [ ] 加载已有配置时不能因某参数位于高级区域而丢弃它。
- [ ] Schema 获取失败时保留原参数，说明无法生成表单，允许回到原文维护。
- [ ] Schema 缓存按插件版本及 Package 函数变化失效。
- [ ] 快速切换函数使用请求代次保护。

### 7.2 去掉表示形式操作

从普通可视化界面移除：

```text
单值
命名参数
任意参数名 paramN
```

对于已知 Schema，用户操作的是“模板、位置、时长”等具名字段，不需要手动选择 scalar/map。

序列化规则：

- 合法的已有简写能被读取和编辑。
- 不改变参数绑定语义。
- 只有满足当前解释器简写规则时才输出简写。
- 对象、列表等字面量不能因简写而被误解释为命名参数。
- 可选参数的省略与显式值按实际绑定语义处理，不用 truthy 判断。
- 切换函数时尽量保留名称、类型兼容的参数。
- 不兼容参数需要丢弃时明确提示，不静默清空。
- 改变表示形式不能丢失已有值。

### 7.3 统一正式参数类型

CellEditor 直接消费正式类型，或使用唯一集中适配；不再由每个页面维护私有别名。

| 类型 | 编辑方式 |
| --- | --- |
| string | 文本输入，必要时多行 |
| boolean | 真/假，保持真实布尔值 |
| integer | 整数输入与校验 |
| number | 数字输入，保留 0，拒绝非法数值 |
| duration | 数值与合法单位，按当前语义支持毫秒数字 |
| point | X/Y 与画面取点，支持合法引用 |
| template | 当前 Package 模板选择、手填、预览及制作入口 |
| key | 支持的按键选择，以及合法数字 keycode 输入 |
| list | 保持列表类型的结构化输入 |
| object | 保持对象类型的结构化输入 |
| any | 明确区分字符串、数字、布尔、null、列表和对象 |

list/object 第一版可以使用带校验的 JSON 值编辑，不要求树形编辑器。

禁止：

- `String(array/object)` 后把修改结果直接保存为字符串。
- 空数字输入被自动转换成 0。
- 把字符串 `"false"` 自动变成布尔 false。
- 把合法字符串、null、空列表混为同一种“没填”。
- 因有限下拉选项拒绝后端合法的数字 keycode。

### 7.4 必要 Schema 元数据

优先使用已有字段。确实不足时，在同一声明体系补少量可选字段：

```text
enum
min
max
step
format
advanced
```

例如：

- threshold：0～1。
- key.action：实际支持的 press/down/up。
- log.level：实际支持的日志级别。
- region：虽然底层是 list，但通过 format 表达搜索区域。

要求：

- [ ] 不为每个函数写一套专用参数表单。
- [ ] 不在前端另建与运行时无关的函数定义表。
- [ ] min/max/enum 等有效性约束与服务端校验一致。
- [ ] step、advanced 等纯展示信息不错误改变执行语义。
- [ ] 不因 UI 元数据引入新的 YAML 必填字段。
- [ ] 默认值冲突先核对真实绑定和 handler，再统一 Schema 与文档。

特别核对 wait_find 等轮询间隔：不能把文档和 Schema 的差异简单通过全局改值掩盖，也不能让前端使用自己的第三套默认值。

### 7.5 所有现有函数的编辑覆盖

| 函数组 | 前端必须能够表达 |
| --- | --- |
| tap | position 字面量或引用、画面取点 |
| swipe | from、to、duration |
| key | key、action |
| input_text | text |
| launch、stop_app | 默认当前设备配置应用，或显式 Android 包名 |
| sleep | duration |
| log | message 的任意合法类型、level |
| find | template、threshold、region、返回值变量 |
| wait_find | template、threshold、timeout、interval、region |
| tap_template | template 及现有实际支持的查找/点击参数 |
| wait_disappear | template、threshold、timeout、interval、region |
| eq、ne | a、b 的任意合法类型 |
| gt、ge、lt、le | a、b 的数字或合法引用 |
| Package 函数 | 由其 params 生成同一套表单 |

函数默认值和返回值行为以当前正式实现为准，不在 UI 修复中顺便修改执行语义。

### 7.6 find 的目标体验

```text
查找模板

模板 *        [选择或输入模板] [预览]
结果保存为    [button]

高级设置
  匹配阈值    [使用默认值 / 显式输入]
  搜索区域    [默认 / 明确区域]
```

在当前能力可用时提供：

```text
框选新模板
测试当前匹配
```

无设备时仍能编辑模板引用和参数；不能因为无法实时测试而禁用整个编辑器。

### 7.7 参数、变量、返回值和控制结构

完整覆盖当前正式 V1：

```text
脚本：name / params / vars / run
函数：description / params / vars / returns / run
步骤：函数调用 / if / repeat / return
```

要求：

- [ ] params 和默认值保持正确类型。
- [ ] vars 保持当前“字面量表”的语义，不新增引用求值。
- [ ] 引用补全包含当前作用域参数、变量及实际可见的前序 as 结果。
- [ ] 函数局部作用域、分支和循环可见性以解释器为准，不按前端直觉推断。
- [ ] 不向用户推荐当前 V1 不支持的 `$list[0]`。
- [ ] 保留 `$name.field` 与 `$$` 字面量转义语义。
- [ ] 不使用 JavaScript truthiness 代替实际 if 条件语义。
- [ ] repeat 可以表达 0、合法非负整数和合法引用。
- [ ] return 可以表达真实类型或引用。
- [ ] returns 仍按当前设计作为文档/提示，不能在本轮擅自变成新运行时强约束。
- [ ] 已有 as 不因返回提示变化而被静默删除。
- [ ] 拖放、复制、删除和撤销不会丢失嵌套结构或引用。

正式 YAML V1 不增加 `version:`，也不恢复旧 call/args 步骤语法。

### 7.8 原文与可视化往返

必须验证：

```text
合法 YAML
→ 可视化
→ 编辑一个字段
→ 保存 YAML
→ 重新加载
→ 参数类型和执行语义不变
```

- 不要求输出缩进或简写形式逐字节相同。
- 但不得丢失有效参数、函数、分支、变量和数据类型。
- 当前可视化暂不能处理的合法结构，要保留原文并明确提示，不静默删掉。
- 原文解析失败时保留文本和错误位置。
- 不允许切回可视化时用空模型覆盖错误原文。
- 注释保留范围应如实说明；不以删除内容的方式隐藏无法处理的问题。

### 7.9 默认函数库

- [ ] 函数入口只编辑 `automations/_function.yaml`。
- [ ] 文件不存在时显示可编辑空状态，首次保存时按资源机制创建。
- [ ] 一个文件内正常管理多个函数。
- [ ] 额外 `_function*.yaml` 参与加载与只读来源展示，不增加专门多文件编辑 UI。
- [ ] 参数默认值复用修复后的强类型控件。
- [ ] 新增、重命名、删除函数时执行实际命名和冲突校验。
- [ ] 保存后刷新调用补全和 Schema 缓存。
- [ ] 函数测试沿用正式执行入口，明确需要设备或其他权限的动作。
- [ ] “从此步骤测试”缺少前序变量时给诊断，不自动执行前序副作用来补上下文。

### 7.10 模板与匹配测试一致性

区分“独立模板测试”和“测试当前步骤”。

测试当前步骤必须携带：

```text
当前 Package
解析后的模板
阈值
搜索区域
画面来源
确定帧或实时帧上下文
```

要求：

- [ ] 显式 region 不能被模板名中的默认区域替代。
- [ ] 引用尚无值时提示补测试输入，不静默使用默认值。
- [ ] 相对区域、像素区域、x/y/w/h 和边界坐标只在明确边界转换。
- [ ] 测试结果保留来源与坐标信息。
- [ ] 只测试匹配，不顺带点击、执行脚本或启动任务。
- [ ] 框选模板保存使用已经冻结的画面，不在保存时重新截图。
- [ ] 保存结果只能回填仍然存在且上下文一致的目标字段。
- [ ] 模板重命名按实际结构更新引用，不替换普通文本中的同名内容。

### 验收

必须从正常“添加步骤”入口创建 find 并选择模板，不允许测试通过手动构造完整 args 绕过问题。

同时覆盖全部正式参数类型、四种步骤、Package 函数以及原文往返。

## 8. Phase 4：Keymap 编辑与应用流程收口

### 8.1 分离四种状态

明确区分：

```text
列表选中的方案
正在编辑的草稿
已保存的资源
正在应用的方案
```

这些状态可以在简单 UI 中展示，不要求新增四个页面。

行为：

- 刷新列表尽量保留仍然存在的选中方案和当前应用方案。
- 删除非当前方案，不影响当前输入。
- 保存未应用方案，不自动切换到它。
- 修改当前应用方案时，明确说明保存是否立即应用。
- 建议提供“保存”和明确的“应用/保存并应用”语义，不隐式改变真实设备输入。
- 切换 Package 时释放旧输入并清理旧上下文，未保存草稿先处理。
- 资源 ID 用于识别，显示名称只用于展示。

### 8.2 保存与方案切换

- [ ] 正确连接 saving，不与普通 loading 混用。
- [ ] 保存期间防重复提交及草稿替换。
- [ ] expected_version 使用完整版本值，不用展示截断值。
- [ ] 方案详情响应按请求代次和 Package 校验。
- [ ] 准备新方案成功后才提交应用状态。
- [ ] 释放旧输入后再应用新方案。
- [ ] 失败时不恢复旧按住状态。
- [ ] 编辑中的方案绑定创建草稿时的 Package，不随全局 Package 静默改写。
- [ ] 同名方案不能导致错误选中或错误保存到其他资源。

### 8.3 输入来源与动作配置

以当前实际 DSL、校验器和执行器为准列出支持矩阵：

```text
输入来源
→ 可识别的事件
→ 可配置动作
→ 生命周期
→ 前端录入方式
```

- 键盘：按键录入。
- 鼠标：对实际支持的按钮/事件提供选择或采集。
- 手柄：只有实际支持的按钮/轴才开放配置。
- 无可用硬件时说明原因，允许合法配置的文本维护。

不因为运行时存在某种事件结构，就默认任何动作都可以绑定它。

要求：

- [ ] 前端不生成后端不支持的组合。
- [ ] raw_key 的 code/keycode 采用明确选择，避免同时保留互相冲突的值。
- [ ] 录入模式的输入不同时发到真实设备。
- [ ] 录入支持取消，并正确处理失焦。
- [ ] 不把输入框内普通打字当作设备映射输入。
- [ ] 保留已修复的鼠标透传语义。
- [ ] 不为新建方案重新引入已淘汰动作；旧格式处理遵循当前正式策略。

### 8.4 投屏标记和输入释放

修复 hold：

```text
hold
→ at 点位 + 按住状态

swipe
→ from/to + 方向

raw_key
→ 按键状态
```

要求：

- [ ] 编辑模型、运行模型、投屏标记使用一致字段。
- [ ] 取点使用正确画面尺寸和归一化坐标。
- [ ] 显示标记不产生设备操作。
- [ ] 切换方案、设备、Package、输入模式、Stage 来源时正确释放旧输入。
- [ ] 插件停用、页面失焦、设备断开时没有卡住的 down。
- [ ] 视频只读模式不能经 Keymap 误发真机输入。

### 验收

刷新、保存、删除非当前方案不改变正在使用的配置；快速切换最终使用最后一次有效选择；hold 标记及输入释放正确。

## 9. Phase 5：Video 全工作流与前后端入口补齐

### 9.1 素材库

提供清楚的用户操作：

```text
导入
在左侧查看
创建项目
详情
删除
```

要求：

- [ ] 用户不必先创建项目才能查看一个视频。
- [ ] 无 Package 时仍允许使用不依赖 Package 的媒体功能。
- [ ] 只有项目、模板和草稿保存等需要 Package 的操作受对应条件限制。
- [ ] 导入显示进度、错误及当前实际支持的取消能力。
- [ ] 删除被引用素材时，说明引用原因，不直接绕过保护。
- [ ] 网络失败不是“素材库为空”。
- [ ] 详情只展示实际存在的元数据，不编造 codec、帧数、哈希或兼容性结果。
- [ ] 录制完成后刷新素材并提供查看或创建项目入口。

### 9.2 历史录制与当前录制

用户不应手动输入 recording ID。

优先复用现有录制元数据和存储。若缺少历史查询能力，仅补最小查询接口，不新增独立录制管理系统。

要求：

- [ ] 以名称、时间、设备、时长和状态选择录制会话。
- [ ] ID 仅作为诊断信息，可查看或复制，不作为正常操作前提。
- [ ] 当前录制展示停止并保存、取消及异常状态。
- [ ] 刷新页面后能查询有权限查看的活动会话。
- [ ] 多段录制按现有会话结构展示，不把分段当成毫无关联的独立操作。
- [ ] 无事件、部分事件、异常结束均有明确提示。
- [ ] 停止和取消重复请求保持安全。
- [ ] 权限不足时不能接管或停止他人会话。
- [ ] 历史列表为空与历史读取失败分开。
- [ ] 不为了显示历史记录复制一套与录制服务不一致的数据源。

### 9.3 项目素材管理

项目页补齐：

```text
查看主素材
添加素材
移除素材
设置主素材
替换素材
重新关联缺失素材
```

要求：

- [ ] 项目名称修改与内部资源 ID 分开；普通重命名优先只修改显示名称。
- [ ] 确实修改资源 ID 时，内容、路径、版本和打开态一致提交。
- [ ] 项目保存、素材调整和引用维护共用 Phase 1 的安全路径。
- [ ] 删除项目不自动删除原视频。
- [ ] 缺失素材不能提示“重新导入同名文件就自动恢复”。
- [ ] 重新关联由用户明确选择新素材，检查可用的身份或完整性信息。
- [ ] 相同素材恢复与换成另一段视频是不同操作。
- [ ] 替换为不同视频时，标记、校准、事件和模板关联不能被静默赋予新含义。
- [ ] 必要时将相关制作信息标记为需重新验证，而不是假装全部仍有效。
- [ ] 项目切换、重载冲突、Package 切换保护未保存内容。

### 9.4 左侧 Stage 与右侧控制

目标：

```text
左侧：统一画面
右侧视频插件：播放控制、时间轴与制作操作
```

优先复用当前 StageController/UI Bridge，不建立第二套全局播放器框架。

要求：

- [ ] 播放、暂停、seek、倍速、逐帧、标记跳转和事件跳转作用于同一有效画面来源。
- [ ] 不同时维护两个互不关联的播放时钟。
- [ ] 右侧可以显示确定帧缩略图，但它是同一帧身份的视图，不是另一个独立播放器。
- [ ] Stage 状态变化能回传给右侧控件。
- [ ] 命令和状态回传避免循环触发。
- [ ] 视频功能区提供“返回实时”入口。
- [ ] 停用视频插件时安全处理当前媒体来源，不留下无法退出的模式。
- [ ] 返回实时不自动执行录制事件，也不恢复旧按键状态。
- [ ] 保持各 viewer 的 Stage 状态独立。
- [ ] 不改变真实设备连接、Android 应用或后台 Run 身份。
- [ ] 不重新向投屏顶部添加录制、素材选择等插件按钮。

### 9.5 时间轴、标记与校准

- [ ] 上一帧、下一帧、指定帧和事件跳转使用真实 PTS/索引。
- [ ] 首尾边界、空帧表、取帧失败处理明确。
- [ ] 标记保存确定的素材、时间/帧身份和校准版本。
- [ ] 校准表单与实际预览、裁切和匹配使用同一坐标变换。
- [ ] 原始素材保持不变，校准不静默覆盖源文件。
- [ ] 不以非等比拉伸掩盖分辨率或比例差异。
- [ ] 已存在但未开放的工作副本等能力，在覆盖矩阵中明确如何使用；未实现则如实记录，不做假按钮。
- [ ] 不承诺未经平台测试的格式兼容或性能。

### 9.6 模板与草稿联动

通过已有公开能力使用 gamer.yaml，不直接写其私有资源。

要求：

- [ ] 创建模板、离线测试、生成草稿、保存草稿、打开编辑器均有完整入口。
- [ ] 相关按钮按具体能力判断，不只判断“YAML 已安装”。
- [ ] 缺少 YAML 时，导入、播放、逐帧、标记等基础功能继续正常。
- [ ] 依赖缺失提供安装/启用入口，复用插件中心的统一操作流程。
- [ ] 不静默安装依赖或授予权限。
- [ ] 依赖停止、升级后及时降级；恢复后重新探测。
- [ ] 能力探测失败不能沿用旧可调用状态。
- [ ] 草稿生成、保存、打开、运行是不同操作。
- [ ] 保存后跳转只更新正确 Package 和资源。
- [ ] 草稿生成不自动创建定时任务，不自动执行真机输入。
- [ ] 未支持的录制事件产生诊断，不静默丢弃。
- [ ] 清理 v3 等过时文案，但不误删 Keymap 等独立格式的必要版本字段。

### 验收

用户不输入 UUID、不离开工作台手动修改项目 JSON，就能完成：

```text
导入或录制
→ 查看素材
→ 创建/打开项目
→ 定位确定帧
→ 标记或校准
→ 创建模板并离线测试
→ 选择录制事件
→ 生成草稿
→ 保存并打开自动化编辑器
```

缺失素材、依赖缺失、网络失败和保存冲突也必须有实际可走通的处理路径。

## 11. 实施顺序与并行安排


用户选择的是“我要编辑、保存、更新、卸载、查看、制作”，系统应负责完成合理流程。

本轮不扩大架构，而是让已有能力真正做到：填得出、保存对、切换稳、失败可恢复、操作能完成。
