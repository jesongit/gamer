# Gamer AI 助手插件开发计划

状态：P0～P5 已落地，P6 的本地集成、mock 回归、UI 与打包已实施；真实供应商、设备及跨游戏验收待环境。实际接口、调整和证据见 §17 与验收报告。

日期：2026-10-01。核对基线：主仓 `88cc44b`，插件 submodule 固定提交 `837184e50331824573b58271c5b143f06ffc920b`。实施时以工作树为准，不跟随插件仓远端最新提交。

本计划增加通用多模态 AI Runner。用户输入“完成日常”“完成某某活动”“通关一次副本”等目标，AI 根据当前画面、已有经验和必要的联网攻略决定下一步，调用 Gamer 能力完成任务。用户无需预先写脚本、选择特定游戏实现或录入攻略。插件复用设备、视觉、资源、任务、运行和通知机制，并持续维护有执行证据的经验。

## 1 用户需求与默认行为

| 项目 | 已确认要求 |
| --- | --- |
| 通用性 | 不按游戏或活动开发专用分支；验收游戏只是测试样本 |
| 输入 | 用户给自然语言目标，系统提供设备与应用上下文，AI 补充必要信息 |
| 模型 | 支持 API 与本地服务，仅由多模态模型负责游戏决策 |
| 搜索 | AI 自主决定搜索时机和查询；优先供应商原生搜索，不支持时提供外部搜索工具 |
| 自动化 | 与脚本一样支持查看操作、取消、任务调度和后台执行；现有自动化是可选能力 |
| 常规资源 | 正常挑战扣除体力、精力等随时间恢复的常规行动资源默认允许 |
| 额外消耗 | 使用道具、购买体力、消耗货币、门票、钥匙等默认需授权；不把恢复道具视为常规体力 |
| 受阻处理 | 先完成其他无需新增授权的部分，再汇总待处理事项并通知 |
| 授权记忆 | 用户可确认单次或持久规则，限定游戏、账号、用途、额度与有效期 |
| 经验记忆 | 自动维护攻略、失败路径、适用条件和完成记录，下次优先复用 |
| 成本 | 请求级用量、预算门禁、供应商可选对账、上限与通知均纳入设计 |
| 工具接口 | 面向 AI 提供结构化能力；内置 Runner 与 MCP 使用同一执行和授权路径 |

以下是实施默认值提案，不是新的用户确认事项：

- “日常”优先解释为游戏内明确列出的日常任务及对应奖励，不自行扩展到养成、清理背包或额外刷取。
- 无法确定消耗类别、数量或对象时请求授权或澄清，不凭空归入允许的常规资源。
- 体力耗尽后转做其他事项，不占设备等待数小时恢复，不自动购买或使用恢复道具。
- 未完整达到目标时报告部分完成或受阻，不以接口成功或模型的一句“完成了”判成功。
- 用户通过明确的接管操作取消 AI 输入，恢复时重新观察；普通观看不改变运行。
- 无搜索来源时保留画面探索能力，明确显示联网不可用，不生成伪造搜索结果。

## 2 第一版范围与限制

第一版完成一个决策 Agent 的完整闭环：目标输入、模型连接测试、画面观察、基本操作、按需搜索、计划与进度、攻略和完成记录、授权规则、通知、预算、运行历史、调度、MCP 工具入口，以及 gamer-yaml 的受控能力调用。

实现以 Android 设备路径作为首轮原型范围。现有 browser target 的坐标和会话机制保留；浏览器目标适配在 Android 闭环通过后单独验证，不假设相同视觉工具已经兼容。

不增加 YAML 关键字，不复制 YAML 解释器，不要求联网模型或特定品牌，不引入下载包可提供的第三种执行类型。第一版不依赖多 Agent 编排、自动训练模型、向量数据库、图数据库、云端记忆同步或任意 shell 执行。后续扩展需有真实运行数据支持。

纯视觉不能保证识别所有隐含消耗，模型也不能保证完成所有游戏任务。通用性以跨游戏验证衡量；安全与成功率以失败样本和操作证据衡量。即时战斗受请求延迟限制，可以使用已验证且受控的自动化能力执行局部流程。

## 3 当前机制与实际缺口

| 已核对位置 | 当前行为 | 计划处理 |
| --- | --- | --- |
| `server/src/api/runs.rs` | 按 runner 注册表分发通用 RunRequest，设备忙返回 409 | 复用入口和设备互斥，不另设 AI 启动端点绕过运行管理 |
| `server/src/run_manager.rs` | RunManager 只持有一个 RunExecutor | 增加按 runner_id 分发的通用执行器集合，运行管理不解释 AI/YAML payload |
| `server/src/main.rs` | 当前装配 YAML EngineExecutor 与 YAML registrar | 装配执行器集合及复合 registrar，分别接入 YAML 和 AI 插件 |
| `server/src/extensions/service.rs` | 单个 TimerRunnerRegistrar 钩子与 builtin service 注册 | 用复合钩子复用生命周期，停用时取消拥有的 AI 工作并注销 Runner |
| `server/src/extensions/service.rs` 的 call gate | 插件互调及 YAML guest 执行全程持有读租约，生命周期变更先等待写锁 | 长调用须先在锁外撤销准入并发取消，再有界收尾，不能等待读租约结束后才通知停止 |
| `server/src/extensions/builtin.rs` | builtin 实现编译期注册 | 注册 gamer-ai，无占位 guest，宿主能力变化随宿主发布 |
| `server/src/capabilities/adapters/frame.rs` | RGB 帧存储与按需采集，PNG 编码留在输出边界 | 复用同一次采集，补受控图片导出与缩放，保留原图用于操作验证 |
| `server/src/capabilities/adapters/input.rs` | Android 输入不接受 browser FrameStamp | AI 自有 observation 身份与现有 FrameStamp 分开；不盲目传 stamp 到 Android 输入 |
| `server/src/api/devices.rs`、`server/src/webrtc/mod.rs` | REST、DataChannel 和键盘映射入口可直接注入人工输入 | 增加设备输入所有权与服务端接管仲裁，AI 运行时观看和输入分离 |
| `server/src/api/auth.rs` | 现有 Cookie 与回环 token 都是管理员凭据 | MCP 使用独立的受限凭据，不给模型客户端管理员凭据 |
| `server/src/api/packages.rs`、`server/src/package_archive.rs` | 导入/覆盖和导出保留插件文件原文，不经过 ResourceHandler 内容钩子 | 本机验证信任不写入可分享文件，增加不可归档的 Package 实例代次用于失效 |
| `server/src/extensions/mod.rs` | notification.send 的插件 caller 仅为 gamer-yaml | 将动作 caller 契约扩展为显式允许集合，增加 gamer-ai，保持实例身份与权限检查 |
| `plugins/gamer-notify/host/` | 文本发送、全局通道、发送记录、任务结果 hook | 复用发送与历史，新增 AI 事件调用，不创建第二套通知服务 |
| `plugins/gamer-yaml/host/` | YAML 解释、函数冻结、参数绑定、WASM 执行 | 提供同 run 内受控调用接口，不通过另一个 run 抢占同设备 |
| `server/src/api/tasks.rs` 与 runner 描述器 | runner、entrypoint 与函数目录机制已有 | 通过描述器接入 AI 目标，不把 AI 字段硬编码进 Core API |
| `web/src/components/task/runner-editors.ts` | RunnerEditorContribution 可插拔 | AI 插件贡献目标与预算编辑器 |
| `sdk/ui/host-modules.json` | 受信任 UI 模块可共享宿主 SDK | 按现有贡献契约提供 AI 面板与任务编辑接入 |

Core 只补通用执行器分发、可取消长调用、输入所有权、必要的调用方权限契约和本机资源身份等小范围能力接缝。攻略、模型供应商、消耗分类、记忆、计划、预算与 AI 会话语义均归插件。

## 4 插件与运行架构

源码归 `plugins/gamer-ai/`：manifest、host、ui、README、build.ps1。执行类型为 builtin，UI 使用受信任的 `runtime=core` 模块贡献，注册 `runner_id=gamer-ai`。不在主导航添加固定 AI 页面，沿用工作台功能贡献及现有任务页。

```text
工作台目标或定时任务
    → 现有 RunnerRegistry / RunManager
    → gamer-ai Executor 与设备活动租约
    → 读取方案、相关记忆和用户规则
    → 观察 → 模型决策 → 执行门禁 → 动作 → 观察验证
         ↘ 搜索、进度记录、攻略维护、授权待办
    → 证据与用量归档 → 完成或受阻通知

MCP 客户端 → 相同的工具执行层、运行所有权与规则检查
```

### 4.1 生命周期和上下文

扩展进入 Running 后注册 AI Runner、公开动作与工具贡献，停用/卸载时先停止受其所有的工作，再注销。正在执行的请求要可取消；停用后到达的旧模型响应不得触发输入或写入授权。

保持四 Context 独立：device_id 是设备，android_package 来自设备配置，content_package 是 Package 资源域，plugin 身份由宿主确定。模型参数中的设备、包、账号声明不能替换宿主身份。

设备运行槽、活动租约、取消信号和停机 drain 复用现有机制。执行器在一次运行内固定选择，不能在 prepare、acquire、execute 之间因注册表变化换执行器。停用先取消并收尾当前运行，再注销入口；已有 YAML 路径须保持可用。

不能直接把长时间 scoped execute 放进现有整次调用持有读租约的公开 call。生命周期处理先原子关闭新调用准入，在等待写锁之前通过宿主登记的取消句柄撤销长调用，再有界 drain 和清理；取消回调不得在 lifecycle/operation 锁内调用插件。AI 停用取消父 run 及子调用，YAML 停用/更新取消使用该实例的子调用；超时收尾撤销能力，后到的模型响应与 guest 副作用均拒绝。停用、卸载、更新及服务停机使用相同顺序。

### 4.2 目标请求

以下是拟议接口，示例不代表当前已经实现：

```json
{
  "runner_id": "gamer-ai",
  "entrypoint": "default#goal",
  "device_id": "device-id",
  "content_package": "default",
  "payload": {
    "goal": "完成今天的日常",
    "model_profile_id": "primary",
    "budget_profile_id": "daily",
    "resume_session_id": null
  }
}
```

`<package-id>#goal` 为临时目标；`<package-id>/<plan>.json` 为已保存方案，路径由 AI 插件映射到 `plans/`。运行冻结方案和配置版本；模型服务密钥及用户授权不保存在 payload 中。自然语言目标是必填字段，其他配置从用户选择的 profile 获取。Task 仍保存通用 schedule 与 runner 对象。

### 4.3 进度与受阻结果

AI 会话保存 pending、running、waiting_user、partial、completed、failed、cancelled 等插件状态，子目标分别记录待做、进行中、完成、受阻及证据。判断有无进展依据子目标状态与画面证据，不只比较整张图是否变化。

初版复用 Core 已有 success/failed/cancelled 终态：只有目标完整且验证通过返回 success；部分完成、缺授权、预算耗尽返回带明确原因的 failed，AI 面板按插件记录显示“部分完成”“待处理”等业务结果。任务行保留清晰的未完成原因，不用 success 掩盖缺项。若后续通用任务体验需要 incomplete，另行扩展通用契约，不把 AI 专有状态加入 Core。

等待授权时先执行独立可做部分，再保存检查点、结束此次设备运行并释放租约。用户回答后创建关联的新 run，重新取得设备并观察；不重放旧坐标。定时触发会复核当前周期与待办，相同问题未变化时不重复通知；旧周期的待办过期归档。

一次目标尝试使用插件生成的 logical_session_id，可关联多个 Core run_id。恢复、重启及重新取得设备不重置该会话的预算、决策/搜索轮数、已用授权和未结算预留。resume_session_id 指向此逻辑会话，宿主校验 Package 实例、App、已确认账号、目标与方案版本；不一致时拒绝继承，并保留旧账本。定时触发的新目标尝试有新会话；同一目标和周期已有可恢复待办时按宿主规则关联原会话，不用永久 Task ID 或模型选择的新 ID 重置额度。周期授权另绑定 cycle_id。

## 5 面向 AI 的工具契约

工具 schema、说明、执行门禁和错误结构只有一个权威目录。模型供应商与 MCP 只是适配层。以下工具名为提案，实施时保持稳定、明确版本和受控上下文。

| 工具 | 输入和输出要点 |
| --- | --- |
| observe | 返回图片、observation_id、采集时间、原始与模型尺寸、裁剪映射、目标与坐标空间 |
| act | 点击/滑动/按键/文本及 intent、observation_id、预期结果和识别出的消耗；返回已注入或拒绝，不直接声称目标完成 |
| wait | 有界 sleep/画面变化/现有匹配条件等待；本地执行，返回成功或超时；不能自行认定任务完成 |
| search_guides / read_guide | 原生搜索不可用时的外部工具；保留来源、日期、相关摘录及费用信息 |
| memory.search / memory.read | 检索相关攻略、失败路径和进度，不一次加载所有历史 |
| memory.propose | 提交经验新增或修正；宿主挂接真实证据，不接受模型自造成功记录 |
| list_automations / call_automation | 发现当前 Package 可用、经过副作用检查的能力，并在父 run 中调用 |
| request_approval | 创建结构化待办，由真实用户批准；模型无自我批准工具 |
| finish | 子目标结果、整体结论与证据引用；宿主检查是否遗漏、预算是否终止及完成依据 |

### 5.1 画面与操作

复用 FrameCache 和 FrameService，模型图与验证原图来自同一帧；截图以多模态图片内容传输，不当成 Base64 文本让模型阅读。缩放/裁剪必须给出原图坐标映射。设备断连、方向/尺寸变化、人工接管和新 run 会使旧 observation 失效。

时间过旧或目标变化时拒绝操作并要求重新观察。动画可能持续改变像素，不能强制每帧哈希完全相同。画面身份只能防止目标与坐标空间错用，不能保证点击时页面语义未变化；重要按钮应在执行前更新观察。

AI run 和外部工具会话持有设备输入所有权时，REST、DataChannel 的设备副作用与键盘映射派发先检查所有权；未经接管的人工输入明确拒绝，不能仅靠前端禁用按钮。服务端接管先撤销 AI 新输入准入和旧 observation，再取消父 run/子调用，等待已接受输入有界收敛并释放持有的触点/按键，最后开放人工输入；无需等待迟到的模型网络响应。普通观看与刷新画面不申请输入权。Core 只提供通用所有权机制，AI 选择使用；保留现有 YAML 手动运行的输入行为。

输入操作带 operation_id。已完成调用重复提交返回已有结果；动作是否实际注入不明确时记录 outcome_unknown，先观察核验，不自动重发。宿主崩溃与外部游戏操作无法组成原子事务，不能承诺物理输入的 exactly-once。

### 5.2 自动化组合

AI 的 call_automation 不能调用现有 /api/runs 再启动同设备 YAML。新增 gamer-yaml 公开的 scoped execute 契约，由宿主固定 parent_run、AppContext、取消信号、日志和资源冻结版本；无独立设备槽、无嵌套顶层运行。YAML 自己绑定参数、校验语法并调用唯一解释器。

自动化调用不能绕过 AI 的消耗规则。只凭函数名或描述不能证明无副作用；接入执行路径时应把设备副作用通过相同门禁，无法提供检查的现有宏不自动列入可执行工具。调用权限不等于道具授权，模板资源读取也不扩大到兄弟插件私有目录。

scoped execute 携带宿主签发的父 run 能力、取消句柄与 before_side_effect 回调。YAML 原生函数的每次设备副作用通过受控能力包装器，向父 run 提交操作和真实上下文；AI 策略负责取得当前观察、判别消耗、匹配并预留授权，检查本身的模型费用进入同一会话账本。现有 tap/schema 不含消耗语义，不能从函数权限推导许可。等待检查后坐标或条件已过期则拒绝该步并交回 AI 重新决策，不能照旧点下去。无法给出当前步骤的可靠消耗依据时按 unknown 受阻；已验证攻略不提供永久副作用许可。该机制只影响 AI scoped 执行，不增加 YAML 关键字。

门禁检查 tap/swipe 等逻辑操作，在开始前完成；底层触点创建、移动和释放组成有界输入操作，不逐包调用模型。撤销、取消或接管后的宿主触点/按键释放属于收尾路径，无需再次请求模型或道具授权，不能借收尾发起新操作。

函数说明与 schema 按需加载，不把全部 YAML、模板或函数库反复放入上下文；不让 AI 生成任意代码后无检查执行。

### 5.3 MCP 接入

新增受认证的 MCP 适配入口，工具开关受 gamer-ai 生命周期控制。内置 Runner 可直接调用工具层，避免每轮本机网络往返。对外支持目标提交/状态/取消，以及显式工具会话内的观察和动作。

外部客户端须先取得有 scope 的工具会话：会话通过相同 RunManager 占用设备，由宿主绑定 run、Device/App/Package、允许工具和到期时间。未知、过期、已取消或不属于该 run 的调用拒绝。空闲会话自动结束释放设备；外部客户端不能覆盖现有运行、伪装管理会话或创建持久道具授权。

MCP 凭据由已认证用户签发，与管理员 Cookie/回环管理 token 分离，仅在 MCP 路由验证。MCP principal 不能调用管理员 REST、approvals.resolve、settings.save、Package 写入或原始设备控制；工具会话同时绑定 credential_id，知道 session_id 不等于拥有会话。目标提交也只能走受限工具入口。管理员批准保持独立认证，不向外部模型客户端提供管理员登录凭据；无须因此增加通用多用户系统。

MCP 不是新增插件执行类型，不开放免认证的原始点击旁路。凭据由宿主管理和撤销，不传入模型上下文；外部模型请求的 token 费用属于客户端账单，Gamer 只能记录可见工具费用，不能宣称掌握外部推理总成本。

## 6 模型和搜索接入

按协议实现供应商 adapter：OpenAI Responses、Claude Messages、Gemini，以及本地 Ollama/兼容 chat 服务。兼容 chat 不自动拥有供应商原生工具。首轮原型先完成一条 API 路径和一条本地路径，其余 adapter 在相同契约下补齐，第一版验收覆盖承诺的接入类型。

ModelProfile 保存地址、模型名、推理配置、超时、输出上限、价格版本和能力状态。密钥保存在本机私有存储，接口仅返回 has_key 等状态。一次运行绑定配置快照，自动升价或切换供应商必须由预先设置的路由规则允许。

连接测试包含图片读取、坐标定位、结构化动作、工具结果续轮，以及原生搜索与自定义工具组合能力。只按真实响应或官方支持信息设置 available/unavailable/untested，不通过模型名字猜测能力；文本模型不得充当游戏决策模型。

搜索优先级：相关已验证经验 → 当前画面 → 必要时搜索。支持原生搜索时在请求启用工具，由模型决定查询和后续处理；不要求用户额外填写搜索服务。原生搜索缺失或无法与图片/自定义工具组合时提供外部搜索 API/MCP。若 adapter 不支持单请求组合，可以用同一多模态模型分阶段查攻略与做动作决策，保存来源后进入执行轮。

供应商原生搜索和外部搜索都受预算、查询轮数与结果长度限制。原生工具无法约束每次调用费用时，仅提供保守估算而不宣称精确硬上限；严格金额策略使用可计量的搜索路径或停止该请求。搜索失败返回明确错误，不降级为“已经查过”。

网页、截图文字和检索到的经验都是任务证据，不是用户授权。要求扩大权限、修改预算、发送密钥等内容不能作为工具指令执行。攻略引用与来源供用户查看，实际应用仍需画面验证。

## 7 经验与完成记录

### 7.1 记忆分层

| 类型 | 必要字段 | 生命周期 |
| --- | --- | --- |
| 攻略 | 游戏/区服/版本/条件、目标、语义操作、分支、完成证据、来源、修订关系 | 跨运行复用，条件变化时复核 |
| 失败经验 | 实际操作、预期与实际差异、原因线索、是否可重试 | 排除重复失败，不把一次失败等同攻略错误 |
| 完成记录 | 账号范围、子目标、周期标识、时间、证据 | 周期内参考，重新观察后决定是否跳过 |
| 会话检查点 | 方案版本、目标、计划、进度、待办、预算、最近观察与动作 | 中断恢复时复核；过期会话归档 |
| 授权规则 | 用户确认、范围、资源、用途、额度、有效期、修订版本 | 只由用户管理，不受攻略更新影响 |

攻略状态为 candidate、verified、needs_review、superseded。网上查到的先是 candidate；模型生成的成功描述不能直接成为 verified。宿主验证证据存在、属于当前 run，并由观察得出结果。模型可以提出解释和修订，不能改变原始操作记录。

保留成功与失败证据，但不把单次成功解释为每个动作都必要；重复成功用于提高适用性判断。置信度只能辅助检索，不作为权限或真值保证。修订保留来源、条件和被替代记录，用户可查看、修正、删除及标记过期。

### 7.2 账号和周期

Android 包名、显示名称、游戏内 UID/区服等是不同线索。只有有足够证据或用户确认才复用账号级记录；未知账号先使用本次会话范围，不自动继承其他账号额度。设备上切换账号必须失效旧账号状态；单凭“还是同一台设备”不能证明还是同一账号。

日常/周常周期优先由游戏内任务状态和倒计时核对，再参考有来源的重置规则。无法确认时不按本地零点猜测。持久完成记录是线索，不能永久代替新画面。用户无需预先配置游戏专用规则，必要的身份确认应只在缺乏证据时发生。

### 7.3 存储和上下文

可复用方案和攻略归当前 Package 的 `plugins/gamer-ai/plans/`、`guides/` 等私有目录，走 PackageStore 和 expected_version。默认配置包即可使用，不从 Android 包名生成 Package id。

账号进度、授权、检查点、请求账本、证据和模型/通知配置归 `data/extension-data/gamer-ai/`，按真实 Package/App/账号字段建索引。账号信息、密钥和授权不随配置包导出。攻略发布前过滤账号和截图中的个人信息；导入攻略只视为外部候选经验，不继承作者本机的 verified 状态和授权。

可分享文件只保存攻略内容、来源、修订与作者声明，effective verified 状态由本机私有验证记录派生，绑定内容哈希、Package 实例代次、适用条件和本地证据。文件里声称 verified 不被直接信任。Core 维护不可归档、不可由资源写入覆盖的本机 Package 实例代次；新建、复制、覆盖导入和删除后重建产生新代次，普通内容编辑使用版本/哈希失效。代次处理不依赖 AI 插件启用，休眠时导入也必须生效；以实际目录替换结果为准，恢复后无法确认一致性时保守失效。代次变化使旧攻略验证及 Package 级检查点/完成状态失效，预算和授权账本保留而不重置。导入不改写休眠插件文件，不增加 AI 专用归档解析。

首版使用有版本的结构化记录、文本攻略和简单索引，不依赖额外数据库平台。更新采用原子写入和并发检查；损坏记录报错，不能静默重置预算或授权。原始事件与证据分离，设置容量和保留期限；清理后证据缺失要明确降级，不能继续伪装成有证据的验证记录。

每轮保留目标、约束、相关规则、最相关攻略、进度摘要、近期操作及当前图。压缩历史时保持供应商所需的工具调用与结果配对。内存中的模型猜测、宿主执行事实和用户确认分别标记，不让摘要把猜测升级为事实。

## 8 授权与消耗检查

拟议分类为 navigation、regenerative_resource、item、currency、paid、unknown。分类由画面、动作意图和适用经验提供依据，宿主根据匹配到的规则决定执行、创建待办或拒绝。navigation 和正常 regenerative_resource 默认允许；其余按规则检查。

待办包含 screenshot/observation、目标、资源名称、数量、原因、可选免费路径和本次范围。选项为拒绝、仅本次、当前任务额度、保存长期规则。长期规则绑定游戏与已确认账号，限定用途、单次/周期额度和有效期，支持撤销。资源重名、数量不明确或用途变化时不能模糊匹配。

授权与额度由宿主版本化保存，模型只能读取和请求。额度并发预留，结果未知时保守保留占用并等待核验，不能通过重试重复消费。自动化、内置工具和 MCP 都通过同一门禁。

“当前任务额度”绑定 logical_session_id，“本次操作”绑定具体 operation_id，周期额度绑定已确认账号、规则版本和 cycle_id；均不绑定可反复新建的 run_id。拒绝或恢复不能释放结果未知的消耗占用，撤销规则也不能删除历史消费记录。

截图语义仍由模型理解；参数 schema、权限枚举和坐标校验无法消除模型漏判。重要动作前复核画面，未知消耗暂停该子目标，记录漏判/误报案例。第一版不得声称“绝对不会使用未授权道具”。

## 9 通知与待处理事项

gamer-notify 为可选依赖，AI 运行可独立进行；缺失、未启用或未配置通道时，在设置与运行结果明确提示，待办保留在插件界面。不自动安装、启用或改写通知通道。

通过真实 PluginCallContext、显式 caller 集合及 notify.send 权限调用 notification.send。caller 来自当前进程插件身份，不读取请求 JSON 的 caller 字段。UI 展示选择的已有通道，密钥不传给 AI。

通知事件为待授权汇总、需要接管、预算预警，以及按用户配置的完成/失败结果。相同账号、目标、周期和问题组成去重键；预算阈值按越过事件发一次。默认先完成其他独立部分再汇总；需要立即用户处理才能防止超时失效的事项可以提前通知。

现有通道是文本发送，没有聊天回复即授权的接口。通知带摘要和待办标识；可用访问地址配置后提供链接，用户在已认证 Gamer 页面查看画面并处理。通知不携带可绕过登录的批准令牌。接口接受不等于用户已收到；未知发送结果不自动重复发送。

新建 AI 定时任务默认由 AI 插件发送终态及待办摘要，不同时启用通用任务结果通知；手动运行也由 AI 插件负责。若本次对应终态的任务通知规则已启用且有效，则任务 hook 负责同一终态摘要，AI 不重复发送；否则 AI 按自身配置发送。待办和预算仍按各自事件去重，发送失败记录在运行结果，不由另一发送方盲目补发。通用 hook 当前把 partial/waiting 对应的 failed 显示为“失败”，错误说明须附实际已完成项和受阻原因，界面明确此第一版映射。相同待办后续触发默认不再通知；用户显式启用每次 failed 通知的配置保留，并提示可能产生重复提醒，不静默改写既有任务规则。

## 10 用量与预算

每次模型请求前：读取预算 → 原子预留本次保守费用 → 限制输出和工具使用 → 发出请求 → 记录 usage/费用 → 结算差额。请求 ID、模型、价格版本、缓存明细、计费来源、耗时及关联 run 均写账本。多设备共享同一全局预算预留，不各自独立认为还有余额。

支持单次任务、每日、全局金额额度，以及决策轮数、搜索轮数、token、时长、重试和并发上限。API 启用前要求配置有效的预算/价格策略；本地模型至少有轮数、时长与并发上限。具体默认数值待原型量测后确定，不能在文档把估算写成实际成本。

单次任务预算按 logical_session_id 累计，所有关联 run、YAML 门禁推理、搜索和收尾请求共同消费；恢复跨重启保留账本及 pending 预留。执行时长累计实际活动时间，另设会话过期时间，等待用户不消耗执行时长。每日/周期窗口切换不能清除尚未结算的请求或全局占用，超预算后只有真实用户可调整额度。

价格按供应商或代理实际合同取值。缓存 input 往往是总 input 的子集，reasoning 可能是 output 的子集；adapter 归一化时不重复计费。模型图像已计入输入用量时不再次添加图片费用。搜索、记忆整理、最终验证及供应商工具的附加收费也计入账本。

优先使用供应商响应中的费用；仅有 token 时依据版本化价格估算。账单查询可选，不把普通推理 key 当 admin key，不把缺查询或缺价格显示为零。超时/断流无法确认费用时标记 pending_reconciliation 并保留预算，不无条件重试；预算相关 429 不作为普通瞬时限流不断退避重试。

对账按专用 project/key 或明确的统计范围执行，区分 Gamer 账本与账号其他应用消耗；避免把供应商总金额与本地金额直接相加导致重复。独立显示本次估算、供应商已确认、待核对、余额与最后同步时间。

| 接入 | 可选对账方式与限制 |
| --- | --- |
| OpenAI | Usage/Costs 管理接口需要相应管理凭据；项目/组织硬上限是额外保护，执行传播存在延迟 |
| Claude | Usage/Cost Admin API 面向组织，个人账号不可用；数据通常约五分钟出现，不能代替请求前门禁 |
| OpenRouter | 响应 usage 可含费用，查询当前 key 使用信息与额度；按真实返回记录 |
| 自定义代理 | 显式 adapter 或手动价格；不推断其具有上游账单接口 |
| 本地模型 | 不产生供应商推理账单，仍记录调用、token、耗时及资源限制 |

金额门禁在已知价格和请求上界内尽量保守，供应商账单、原生工具和进行中请求仍可能导致偏差。达到额度后保存进度并通知，不承诺取消请求能退回已经发生的费用。严格上限需要结合可约束工具、供应商额度与预留余量。

## 11 界面和公开动作

工作台面板包含目标输入、模型选择、运行/停止/接管、子目标进度、当前动作和简短说明、操作列表、用量和预算、待办入口。查看历史可定位关键截图和动作，不输出冗长内部推理。

方案编辑支持保存目标、预算 profile 与通知配置，任务编辑器引用方案或临时目标。配置密钥、测试连接、授权规则、攻略管理与待办处理收在插件界面，不向 Core 设置页散入 AI 专有字段。

公开动作初稿为 settings.read/save/test、plans.*、sessions.read/events/resume、memory.search/read/update/delete、approvals.read/resolve/revoke、usage.read/reconcile。列表查询有分页/长度上限，事件有序号支持断线续读。批准、配置和删除是用户管理动作，绝不同时暴露为模型自助工具。

REST 管理优先复用扩展公开 call 动作和 Package 资源 API。事件读取先采用游标轮询；需要流式事件时再补通用连接接缝，不为了首版增加 AI 专属常驻消息总线。模型提供的正文和外部攻略按文本渲染，不执行 HTML。

## 12 权限和发布边界

沿用 device/vision/input/runtime/log/resource 等实际所需权限，通知增加 notify.send。建议新增封闭的 ai.infer、ai.search 权限映射到 runtime 域，分别控制模型图像外发与搜索；实际名称和域版本在契约实施阶段锁定并更新 SDK，不开放 network、shell、process 等通用权限。

配置的模型和搜索服务访问由 builtin 适配层完成，模型不能自选请求端点或认证头。推理密钥、管理账单凭据、通知密钥分离，保存与错误/日志脱敏复用已有机制。启用插件不产生付费请求，配置测试才在用户操作和预算内调用。

插件改动在 gamer-plugins 仓提交；主仓只提交宿主机制、文档、SDK 契约与 gitlink。固定 SDK 快照与 lock 哈希必须一致，运行 `node tools/check-plugin-sdk.mjs`。宿主新增 builtin 和权限随本体发布，独立 UI 构建走现有入口，发行按公开插件快照与发布锁流程执行。

## 13 实施顺序

| 阶段 | 交付 | 通过条件 |
| --- | --- | --- |
| P0 工具与模型原型 | 一条 API 和一条本地多模态路径、observe/act/验证、mock provider、逻辑会话账本及单步 YAML 门禁原型 | 可运行有限任务，取消和旧响应不产生后续输入；恢复不重置额度；一条 YAML 点击的副作用检查和费用贯通 |
| P1 正式插件与运行 | builtin、通用 Executor 分发、复合 registrar、可取消长调用、输入所有权与接管、任务编辑器与方案保存 | AI/YAML 同时可用；YAML 等待/循环中停用 AI 或 YAML 可收尾；人工输入不混入 AI 操作；后台与停机通过 |
| P2 搜索与经验 | 原生搜索、外部工具补充、攻略修订、本机验证索引与 Package 代次、账号/周期记录、上下文检索 | 首次探索，再次复用；导入/复制/覆盖不继承信任；过期/错误攻略被修订，跨账号不串记录 |
| P3 授权与通知 | 消耗分类、用户规则、待办、检查点恢复、通知 caller 接入和去重 | 体力正常用；道具需授权；免费部分继续；回答后重新观察恢复 |
| P4 自动化与 MCP | 同 run YAML 完整能力调用、共同副作用门禁、独立受限凭据与工具会话 | 不另起同设备运行，不绕过规则；MCP 凭据访问管理 REST 被拒绝；断连、过期与关闭释放会话 |
| P5 预算与完整接入 | 补齐 provider adapters、跨设备额度、原生工具限制、可选对账、运行回放 | 费用来源清楚，未知费用不算零，预算可停止并通知，协议组合能力真实验证 |
| P6 发行验收 | UI、宿主/插件测试、SDK 锁、构建、跨游戏实测报告和用户说明 | 所有第一版要求达到验收，限制明确，使用固定插件发行快照 |

阶段是开发顺序，不是把预算和授权推迟到最后：P0 就必须有有限轮数、时长、请求预算和禁止额外消耗的基础门禁；在完整授权系统前使用只读或受控测试路径。P5 完成丰富的统计与对账。

## 14 验收与探索指标

自动测试覆盖真实边界，使用 mock 模型、搜索服务、时钟和设备，避免测试产生外部费用或触达用户数据。

| 场景 | 必须观察到的结果 |
| --- | --- |
| 多轮动作与完成 | 输入成功不直接变完成；新画面验证通过才记完成 |
| 无进展与错误攻略 | 重复尝试有上限；记录具体失败条件，不把延迟当攻略错误 |
| 常规体力与道具 | 体力正常扣除；恢复道具/货币/门票无授权受阻；独立免费部分继续 |
| 用户授权与提示注入 | 只有真实用户能批准；网页、截图、记忆与模型参数不能扩大授权 |
| 多账号与新周期 | 旧账号授权不继承，旧日常记录不让新周期误跳过 |
| 断连、停用、接管、重启 | 租约和槽位释放，旧响应无效；恢复用新观察，不重放结果未知输入 |
| 输入接管仲裁 | AI 运行时 REST、DataChannel、映射输入受仲裁；接管后无 AI 输入，观看不触发取消 |
| YAML 组合与停用 | 父 run 所有权、取消、资源和逐次副作用规则贯穿；无二次 submit；等待/循环中停用任一相关插件可收尾 |
| MCP 认证与 scope | 管理 REST、批准、原始控制及跨凭据借用会话被拒绝；过期、错误目标、外来 run、未知工具拒绝；空闲释放 |
| 并发预算与未知费用 | 原子预留，无重复计费；断流费用待核对，不立即退还预留 |
| 跨 run 恢复额度 | 多次批准/恢复/重启累计同一逻辑会话用量及授权；新周期不能抹掉 pending 请求 |
| 原生搜索兼容性 | 支持时模型按需搜索；不支持时明确能力，不伪造来源 |
| 通知 | 待办/阈值去重，未知投递不重发，缺插件不丢待办 |
| 数据导入和损坏 | 新导入/复制/同 ID 同字节覆盖/删除重建/休眠时导入不继承 verified；无密钥/授权导出；损坏记录不静默重置 |
| 架构与生命周期 | 裸 Core 无 AI 业务，AI 停用即入口/工具失效，YAML 现有行为不退化 |

原型必须报告任务成功率、完成误判、消耗漏判/误报、坐标错误、恢复错误、无进展重复、首次与复用搜索次数、请求数、token、费用、耗时和通知噪声。跨游戏样本验证通用性，禁止为测试样本植入业务分支。

现有 Android 原图没有 browser FrameStamp，模型 native tools 组合与费用上界因供应商不同，自动化缺少同 run 的策略传递接口，都是须在原型解决的具体问题。模型语义判断的残余不确定性应报告样本和失败条件，不用置信分数或另一模型的同意声称绝对可靠。

文档阶段只核对设计和源码，不执行付费请求或 ADB。实施时运行相关 Rust、插件 UI、Core 边界和 SDK 检查；首次本机 ADB 验收遵循 AGENTS.md 的 ADB_MDNS=0 准备规则。实际踩坑才追加 docs/PITFALLS.md，不把计划风险当已发生问题。

## 15 参考机制与官方接口

以下资料用于机制设计；供应商、模型和账号能力在接入测试时再次核对，不把文档支持等同所有兼容代理都支持。

- [Deep Agents](https://docs.langchain.com/oss/python/deepagents/overview)提供记忆、上下文管理、任务计划和人工介入机制，作为设计参考；首版不因此引入独立 Python/TypeScript 编排服务。
- [OpenAI 工具门禁与人工授权](https://developers.openai.com/api/docs/guides/agents/guardrails-approvals)说明应在具体工具边界做检查；[单次运行支出控制器](https://developers.openai.com/cookbook/articles/per_run_spending_controller_responses_api)提供请求前预算机制参考。

- [OpenAI 用量接口](https://developers.openai.com/api/reference/resources/admin/subresources/organization/subresources/usage)与[支出限制](https://developers.openai.com/api/docs/guides/spend-limits)支持组织管理和额度保护；[Claude 用量费用接口](https://platform.claude.com/docs/en/manage-claude/usage-cost-api)说明组织凭据要求和通常约五分钟的数据延迟。
