# 配置包发布插件与仓库源方案

日期：2026-09-25。状态：已实现，正在完成发布与验收；宿主版本 0.2.1，发布插件版本 0.1.0。

## 已确认范围

- 配置作者通过软件中的插件发布配置包，复用运行 Gamer 的电脑上的 GitHub CLI（gh）登录。
- 配置包页面允许添加自己的 GitHub 仓库 URL，从公开 Release 发现、下载和导入配置。
- 首版只支持 github.com 公开仓库；下载者无需 gh 或 GitHub 登录。发布者必须具有目标仓库发布权限。
- 本次不修改已经公开的 0.2.0 标签和资产；新增宿主接口需要另发主程序版本。

## 实施前基线

- `web/src/workspace/MarketView.vue` 只读取同源静态 registry.json 的 packages 字段；随程序发行的目录目前只有 plugins。
- `/api/packages/import` 和导出接口已有 .gamerpkg 格式、哈希校验、冲突确认与原子替换逻辑，应直接复用。
- 插件市场已经有服务端发现、下载、缓存模式，可参考其行为；配置源使用独立的配置包目录协议。
- 插件权限闭集明确禁止 shell/process/network，普通插件不能直接启动 gh。发布需要受限的原生宿主适配，不能暴露任意命令执行入口。

## 产品入口

### 配置包页：仓库订阅与安装

新增“仓库源”管理，支持添加、停用、移除和刷新。输入 `https://github.com/owner/repo`，规范化并去重；首版拒绝其他主机、带凭据 URL 和私有仓库。

源设置保存在本机应用数据中，不写入导出的配置包。发布插件禁用或卸载不影响配置发现和安装；移除源也不删除已安装配置。

列表显示包名称、版本、作者、适用应用、必需插件、来源仓库与已安装状态。多个仓库分别显示加载结果，一个源失败不阻断其他源。网络失败保留已校验缓存并显示状态。

同 ID 跨源条目不可自动合并或静默选取。现有本地存储以 Package ID 为唯一键，因此跨源同 ID 安装必须明确提示冲突；同源更新也必须说明会替换本地修改。安装与更新均由用户点击触发，不自动运行脚本。

### 发布插件：面向配置作者

插件 ID 为 `gamer-package-publisher`，通过现有插件工作台贡献面板，采用 builtin 模式；UI 和发布业务归插件仓，原生适配随宿主编译。

操作顺序：

1. 检查 gh 是否可用，显示当前 GitHub 账号和目标仓库；未登录时指导作者在运行 Gamer 的电脑上完成登录。
2. 选择本地配置包或已导出的 .gamerpkg，读取包内元数据并校验归档；版本从包内读取，不私自改写。
3. 输入目标公开仓库和发布说明，生成发布预览：包清单、版本、大小、摘要和相对上次目录的变化。
4. 点击创建草稿：冻结此次归档字节，创建 Release draft，上传全部资产，重新校验后显示草稿链接。
5. 作者点击“公开发布”，公布校验完成的草稿；失败保留可检查的草稿并支持重试。

发布到官方仓库同样需要账号具备写权限，不提供所有用户均可写入的官方账号或内置凭据。首版目标仓库由作者预先创建。

## Release 目录约定

每次发布是一份完整目录快照，Release 标签与配置包自身版本分离，例如 `catalog-20260925.1`。

首版每个 Release 附带 packages.json、SHA256SUMS.txt 和目录内所有配置包当前版本的 .gamerpkg。未修改包沿用原有字节；增量更新目录时必须保留其他配置，移除条目需显式选择。读取上一份目录失败时中止发布，不能将错误当作空仓库。

packages.json 使用独立 schema_version，条目至少包含 id、name、version、author、android_targets、required_plugins、optional_plugins、asset_name、size、sha256。目录字段从实际归档生成，并校验包内 ID/版本与条目一致。

客户端读取最新公开正式 Release；若缺少 packages.json，显示“不符合配置仓库格式”，不猜测普通 ZIP 文件。用户提交的仓库不能仅上传任意 .gamerpkg 就自动被识别，发布插件负责生成完整格式。

下载地址由已验证的仓库、Release 和 asset_name 确定，目录不能指向任意外部 URL。服务端限制目录、单包和总量大小，下载后核对 size/SHA256 与归档元数据，再走已有导入流程。版本已发布后同 ID/版本的内容禁止替换，需要提升包版本。

## 宿主边界

- 配置源发现、缓存、归档下载属于 Core 的 Package 分发机制，复用当前认证 API 与归档校验。
- gh 编排、草稿、发布预览和发布记录属于发布插件原生适配；宿主只增加必要的生命周期、权限与调用接线。
- 新增明确的发布权限与版本要求，安装时展示；原生调用必须通过 Running 状态及权限检查。该接口限定结构化的仓库、包和 Release 参数，不接受任意 gh 参数、shell 命令或文件路径。
- gh 通过参数数组启动，Windows 隐藏窗口，限制执行时间并支持取消；凭据留在 gh，日志和前端响应不返回令牌。
- 发布操作串行化；公开前复核远端基线，检测其他作者的并发发布，避免旧预览覆盖更新后的完整目录。

## 实施与验收

1. 固定目录协议及归档生成/校验函数，覆盖完整目录保留、版本冲突、元数据不一致和恶意下载地址。
2. 接入公开仓库源持久化、目录/下载 API 和配置包页；测试缓存、失败隔离、来源冲突、哈希失败不安装、覆盖取消不改本地数据。
3. 添加发布插件及受限 gh 适配；使用模拟进程测试参数注入、超时、取消、权限、登录失效、草稿失败与幂等重试，不在自动测试中公开真实 Release。
4. 完成插件构建、宿主版本门禁和发行资产集成；旧宿主安装时应提示升级。
5. 用专门的测试仓库完成导出 → 草稿 → 公开 → 添加源 → 下载导入闭环；真实公开操作在作者点击发布后执行。

普通配置包发布不涉及 ADB、设备或游戏，也不需要启动设备测试服务。

## 首版实施收口

- 发布选择软件内已安装的配置；已有导出文件先导入，再通过插件发布，不另增文件上传通道。
- 官方源默认 jesongit/gamer-packages，显式移除后不自动恢复；最多 16 个源，单包 100 MiB、目录 128 包/512 MiB。
- 宿主 resource 1.1 与 package.publish 权限门禁；旧宿主不能安装该插件，应先升级到 0.2.1。
- 发布端检查远端基线，但 GitHub 没有跨作者原子锁；多人发布仍需协调时间，避免同时操作。
- 真正的远端验收由显式 ignored 测试执行；默认自动测试不发布任何 Release。无设备、ADB 或本地 Gamer 服务操作。
