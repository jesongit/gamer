# 直播日志与观众反馈方案

日期：2026-09-28。状态：首版已实现并接入本地开发服务；真实直播姬开播采集待验收。

## 范围和依据

本轮只面向 B 站直播姬，不扩展其他直播软件或平台。保留「直播设置 / 互动规则 / 触发日志」三页签及现有 FIFO 语义。增加展示信息不改变规则匹配、冷却或队列顺序，不按粉丝牌或付费身份插队。

已通过浏览器读取两套官方动态文档，而非只依赖旧 SDK：

- [主播身份码接入：长链命令](https://open-live.bilibili.com/document/f9ce25be-312e-1f4a-85fd-fef21f1637f8)
- [OAuth 接入：长连 CMD](https://open.bilibili.com/doc/4/c7b549c9-d5d6-0331-b510-465ed4107e01)
- [官方弹幕结构示例](https://github.com/bilibili-openplatform/OpenLive_CSharpDemo/blob/main/OpenBLive/Runtime/Data/Dm.cs)、[礼物结构示例](https://github.com/bilibili-openplatform/OpenLive_CSharpDemo/blob/main/OpenBLive/Runtime/Data/SendGift.cs)、[上舰结构示例](https://github.com/bilibili-openplatform/OpenLive_CSharpDemo/blob/main/OpenBLive/Runtime/Data/Guard.cs)。SDK 示例字段少于当前文档，按当前文档建契约测试。
- [B 站开播说明](https://live.bilibili.com/blackboard/era/u4EPvXpDYUMv7hYJ.html)列出窗口采集能力；本机直播姬的具体素材入口、窗口最小化及透明效果仍需实际 GUI 验收。

本机 API 检查时直播未连接、消息缓存为空。因此以下是官方字段能力确认，不声称当前账号已实收全部字段。

## 字段与展示取舍

| 数据 | 官方消息提供的信息 | 建议展示 |
|---|---|---|
| 观众 | 昵称、头像、应用内标识；弹幕等消息含当前房间粉丝牌名、等级、佩戴状态、大航海等级 | 主行昵称、粉丝牌、大航海；头像可选。未佩戴的牌在详情里标明，不伪装成佩戴徽章 |
| 弹幕 | 内容、发送时间、消息标识；普通/表情类型、表情图片、回复对象、荣耀等级、房管身份 | 主行内容、时间、房管；表情显示图片及替代文本，回复显示被回复昵称；荣耀等级放详情 |
| 礼物 | 名称、图标、数量、价格/实际价值、付费标记、连击信息、盲盒信息 | 主行名称×数量；金额、连击、盲盒放详情。不同金额字段和单位分别处理，不能把爆出价值说成实际支付 |
| 醒目留言 | 内容、金额、展示起止、留言标识；粉丝牌与大航海 | 主行内容和金额；到期/撤回同步下屏；撤回不等于取消已入队任务 |
| 上舰 | 用户在嵌套对象内；档位、数量、单位、价格、粉丝牌 | 正确解析用户，主行显示档位与期限；非标准期限遵循平台单位说明 |
| 点赞、进房 | 点赞有聚合次数及粉丝牌；进房有昵称/头像等，但未承诺粉丝牌 | 日志可筛选；不默认在观众屏逐条滚动，不由进房消息推算在线人数 |
| 房间/系统 | 开下播、推送结束；OAuth 文档另列关注、禁言、房间变更与警告 | 后台系统筛选显示；公开屏只展示影响接单/执行的通俗状态 |

语义边界：粉丝牌等级不等于荣耀等级或大航海等级；缺字段表示未知，不填 0 冒充无牌。跨房弹幕按官方约定不显示发送者信息，也不拼接旧用户缓存。应用内标识不等于站内 UID；跨应用标识需要额外权限，不在 UI 常规展示。不同事件/权限/接入方式按实际下发字段显示。

## 实施前的缺口

- `host/events.rs` 只归一化昵称、头像、文本、礼物名称/数量等；完整原消息仅在有限内存缓存中。统一从顶层解析用户会遗漏上舰事件的嵌套用户。
- `host/queue.rs` 的摘要只留观众标识、昵称和少量内容，历史没有粉丝牌快照。旧记录不能补造当时等级。
- UI 把原消息、触发回执、排队项、结果、运行日志分散为多个区块；回执只显示中文字符串，难以稳定筛选和说明未入队原因。
- 原消息缓存最多 500 条，单页最多 100 条；回执 UI 只取最近 100 条。持续日志必须有独立游标及保留策略，不能让页面看起来像完整历史。

## 主播日志

「触发日志」顶部固定显示连接状况、当前执行、等待数量、接单/阻塞状态。主区为平铺的互动记录，不再堆四套重复列表。

每次互动一条主记录：时间｜昵称及徽章｜弹幕或礼物摘要｜命中规则｜当前结果。状态从收到、排队、执行更新到终态，展开同一条记录查看接收、判定、入队、启动、结束的时间线，以及关联运行日志。运行步骤默认收起。

- 默认筛选「触发相关」，可切换全部互动、未入队、执行异常、系统；可搜索昵称/内容/规则。
- 普通聊天的未匹配是中性状态，不作为错误刷红；冷却、队列满、设备忙、参数问题分别说明。
- 设备忙但已接纳的任务仍为排队，解释等待原因。取消请求到终态前显示正在取消，不提前显示取消完成。
- 当前项与完整等待列表可从顶部展开管理，保留取消、移除、清空；列表按真实顺序，管理反馈与日志关联。
- 暂停自动滚动只冻结当前阅读位置，不暂停接收/执行；新记录以数量提示。历史按游标分页，保留当前选中项。
- 仅有观众名而缺少稳定标识时仍显示名字，但不能据此去重或认定同一人。

## 观众反馈：常驻队列卡 + 短提示

第一版建议一块独立的上屏窗口，用直播姬窗口采集放到游戏画面旁。默认不透明深色底便于直接使用；透明/抠色效果视本机素材能力验收，不预设直播姬一定具有任意网页 URL 素材入口。提供打开、预览、重新打开，不要求安装其他直播软件。

上屏窗口只有内容，没有管理按钮、运行日志或页面导航。关闭窗口不影响直播连接或任务执行。主播可在设置里选窄卡片或底部横条，调整字号与显示条数。

建议默认规则：

1. 新互动成功入队：短提示约 6 秒，显示昵称、公开操作名、稳定排队编号、当前位置。
2. 常驻卡：执行中 1 项、接下来 3 项、其余等待总数。持续看得见，避免短提示错过后毫无反馈。
3. 开始、完成、取消、移除、失败都提供明确状态。对观众的失败描述通俗，后台保留技术错误。
4. 命中规则但冷却/队列满/暂不可执行，也给未受理提示；普通无关聊天不逐条提示未命中。指令相近但未命中的帮助提示后续按实际需求决定。
5. 点赞、进房和无关聊天默认不上屏；赠礼感谢和额外弹幕展示默认关闭，主播可选择开启。
6. 每条规则可选公开显示名；缺省使用规则名。不上屏入口路径、运行参数、设备标识、用户内部标识、凭据或原始错误堆栈。默认不上屏完整原弹幕，避免不相关内容被带入画面。
7. 不显示虚假的进度百分比和倒计时。先显示已运行时间、当前位置；只有脚本提供明确阶段信息时才显示阶段。
8. 明确区分“等待第 2 位”和“前面还有 2 项（含执行中）”；稳定编号不会因位置变化而改变。重复昵称仍可据编号区分。
9. 状态断流时及时标记更新中断，不把陈旧排队位置当实时；恢复时读当前快照，不重播大量历史完成提示。重启待核对显示暂停受理/需主播处理，与实际队列状态一致。
10. 显示可以聚合重复短提示、限制速率，但绝不能合并或删除实际任务。排队、失败等关键回执优先于可选感谢消息；极端流量用数量汇总而非无限提示积压。

可选底部横条更省空间，但一次能展示的排队项较少，所以默认推荐窄卡片。示意中的字号与布局仅作方案比较，不代表已接通直播姬。

## 实现落点与验收

在插件内补齐事件归一化和历史快照；每个事件、触发判定和队列项关联稳定标识。给触发结果增加结构化原因码，不能靠解析中文字符串判断。复用真实队列/RunManager 终态作为信息源，展示层不能自行猜测成功。

后台日志和观众展示分别输出数据；观众只读投影采用明确字段白名单，独立、可撤销的读取授权，不能使用管理员令牌或获得控制接口权限。本机窗口生命周期与插件服务解耦。第一版可用带游标的轻量轮询，不为此引入新的通用调度平台。

验收需覆盖：两套 CMD 前缀、上舰嵌套用户、缺字段/跨房弹幕、普通/表情消息、礼物单条/连击/盲盒、金额单位和撤回；一次互动关联全流程、分页不丢记录、断线重启、不改变 FIFO；真实直播姬采集、字体可读、窗口重开、无控制信息泄漏。模拟消息与平台实收样本、实际直播采集分别记录。

## 首版落地记录

- `plugins/gamer-live/host/events.rs` 归一化实际可选字段；`queue.rs` 保存快照、稳定递增日志游标及公开编号。规则可选 `public_name`，已入队操作使用当时的名称快照。旧数据保留，无法补回旧粉丝牌信息。
- `logs.read` 支持向前读取历史、按游标补齐新记录、刷新已显示项的运行状态、搜索及筛选。日志只合并同一个队列项的状态，不改变入队、取消或终态判断。撤回留言在后台标记；不触发取消任务。
- `LiveLogs.vue` 替换原来分散的最近消息、回执和结果列表。队列管理折叠在顶部；单条展开时间线和运行日志入口。固定阅读位置仍刷新已有项的执行状态。单次页面最多显示 500 条，可搜索缩小范围。
- `audience.rs` / `audience.html` 提供独立本机只读窗口（卡片/横条、字号和等待项数）。随机读取授权与管理员权限分开；只绑定 `127.0.0.1`，校验 Host/Origin、禁缓存，停止上屏、停用插件和退出服务后撤销。已有 HTTP 长连接也必须重新校验撤销状态。
- 公开数据只有观众昵称、公开操作名、编号、等待位置和通俗状态；不上屏原弹幕、原始错误、入口、参数、设备、平台用户标识和凭据。普通聊天、点赞、进房、额外礼物感谢未纳入本版上屏。短提示最多保留最近 20 个状态快照，密集更新合并计数，重载/断流恢复不重播旧提示。
- 直播设置中“打开 / 更新反馈窗口”，再在直播姬选择窗口采集。显示偏好保存在当前浏览器；窗口关闭不停止队列，停止上屏撤销旧地址，再打开生成新地址。
