# Gamer 多画面与独立运行开发计划

日期：2026-10-07。状态：功能代码与使用文档已实现，含右侧目标标识的最终前端聚合 1442 项通过，构建与执行专项验证完成；后端全套剩 3 项 ICE 环境失败，真实四路、九路体验与性能尚未验证。结果见 [本轮验收记录](../reports/multiview_execution_acceptance_20261007.md)。当前改动尚未提交或推送。

目标是同时查看多个 Android 或浏览器目标，让每个目标保留自己的配置包、脚本和参数，并能直接启动、停止当前网格中的运行。默认四格，可切换九格；右侧保留一套现有工作面板，跟随选中格。优先保证易用、独立运行和防误操作。

## 一 基线与范围

- 主仓基线：`f571d65268ed05fa919445950244e31cdf44c58b`
- 插件基线：`cfd1d5851f44df2287e24025f7f0ec0229dab668`
- 开发分支：`feat/multiview-independent-runs`

已有 RunManager 按 `device_id` 支持不同目标并发，同一目标最多一个活动运行；运行上下文、脚本快照和日志按运行隔离。本轮复用这些能力，不新增插件、执行器、任务类型、排队或群控，不向多个目标广播同一操作，也不复制多份 Console。

主仓与插件按固定子模块边界交付。遵循 [开发约定](../../AGENTS.md)、[界面规范](../design/gamer-ui-spec.md)、[浏览器目标设计](gamer_cdp_browser_target_design.md) 和 [视频工作台契约](gamer_video_workbench_contracts.md)。本文是工程计划，不表示全部功能或真实多路性能已经通过验证。

## 二 已确定的交互与安全边界

1. 每个目标只占一个格，重复添加应定位已有格。每路连接、预览和状态独立；切换焦点不拆旧流，单路失败不影响其他路。沿用单目标 viewer 冲突与接管规则，不自动强占其他页面。
2. 选中格将设备、配置包、脚本、参数和运行信息投影到现有单套面板。先通过未保存编辑守卫，再共同更新焦点与面板；被拒绝时两者保持原状。参数按目标保存，不能共享可变对象或覆盖另一目标的未保存编辑。
3. 首次点击非选中格只选择，不穿透成设备 tap。切换、移除或失焦时释放旧目标触点、按键及映射状态；保留服务端输入仲裁、暂停屏障和来源代次校验，释放不得发送到新目标。
4. 九格切回四格，隐藏目标、配置和后台脚本保留，界面显示后台数量。放大、退出放大和关闭预览不停止脚本。刷新恢复布局、配置及服务端权威运行状态，不自动启动或续跑。
5. 批量操作只处理触发时捕获的当前可见格。启动逐目标校验，跳过已运行、离线、配置不全及正在提交的目标，展示各自结果。停止确认捕获 `run_id`，确认后不得取消后来替换的新运行；部分失败仍继续处理其他目标。
6. 音频默认静音，最多允许选中一路发声。媒体和模板取帧请求只路由选中格；来源切换后丢弃迟到回包。预览优化不得降低自动化原图质量，离线媒体继续禁止设备输入。

## 三 分阶段实施与并行边界

### 阶段 0 固定基线与最小契约

状态：已完成，基线及接口已对齐。实施前前端基线为 146 个测试文件、1372 项测试通过，build 与 SDK 检查通过；这些结果仅证明旧基线，不计作新功能验收。

统一工作区状态为 `gridSize: 4`、有序 `targetIds`、`selectedTargetId` 和按目标存储的 `configs`；每份配置含 `packageId`、`scriptId`、`args`、`runnerId`。可见格由布局和目标顺序派生，不再维护第二套列表。对外收敛为增删与选择、配置读写、轮询、单目标与可见格启动，以及 `captureVisibleStops` / `stopCaptured`。

交付物：状态契约、文件归属和测试清单。后续三条实现线可据此并行。

### 阶段 1 建立逐目标配置与运行状态

状态：已实现并通过本地状态、面板与集成测试。`multiview-state.mjs`、`multiview-workspace.js`、store 与自动化插件已接线；“运行配置 → 保存配置”可独立保存逐目标参数而不执行脚本，单格、右侧和批量运行复用同一配置。

实现布局持久化、目标去重、配置快照、受守卫保护的选择事务及批量启动/停止。运行状态以服务端记录为准，轮询覆盖已加入工作区的隐藏目标，并对请求乱序、删除目标和正在取消的运行做保护。刷新后的失效目标或缺失配置应明确提示，不能替换为其他目标后悄悄运行。

交付物：工作区模块、自动化面板接线、状态和批量测试。验收重点是配置不串、守卫拒绝不分裂、批量范围准确及旧停止请求不误伤新运行。

### 阶段 2 实现四格九格舞台与安全选中

状态：已实现并通过组件与集成测试，Console、逐目标预览组件和输入路由使用同一工作区接口；右侧“当前操作目标”标识已完成，定向 27/27 及最终聚合复测通过。真实 Android/browser 混合多路画面尚未验收。

每个目标拥有独立预览会话，选中目标复用现有舞台工具及右侧面板。完成空格添加、选中标识、布局切换、放大、移除、离线与错误提示，以及当前网格批量按钮。保持实际画面比例、黑边坐标换算、窄窗口可用性和可访问名称。

交付物：多路舞台、输入与来源测试。验收重点是切焦点不断流、首击不穿透、隐藏目标可恢复、旧输入释放和仅选中路音频。

### 阶段 3 加固连接与真实执行并发

状态：连接代次隔离与执行线程改造已实现并测试。真实 WASM 专项 22 项通过、1 项忽略，native sleep 专项 2 项通过，RunManager 专项 15 项通过；这些计数存在覆盖重叠，不相加为独立用例总数，也不代表真实设备验收。

- 连接线：对异步建连、关闭、重连及迟到信令校验所属会话，旧回调不能关闭新连接、改写新状态或接管新画面。
- 执行线：同步 WASM 执行及原生线程等待移入阻塞工作线程，复用现有 runtime bridge，避免占住 Tokio I/O worker；普通 `sleep` 在同一个 runtime sleep future 外增加取消选择，保持原有时间与虚拟时钟契约。继续等待输入和租约收尾后发布终态，不提前释放同目标运行槽，不改变 YAML 语义。

交付物：连接竞态测试、真实 WASM 多运行测试与取消测试。验证一条脚本等待时另一条能推进、取消一条不终止另一条、同目标重复运行仍拒绝。Cargo 构建由执行线统一调度，避免并行争用；其他工作线不重复启动重型构建。

## 四 验收矩阵

| 验收面 | 自动化验证 | 真实环境验证 |
| --- | --- | --- |
| 布局与配置 | 默认四格、四九切换、去重、持久化、配置隔离 | 九格缩回四格再恢复，隐藏运行继续 |
| 焦点与编辑 | 守卫拒绝无变化、参数不串、首击不发送输入 | 编辑未保存时切格，键盘、拖动与映射释放 |
| 连接与来源 | 迟到回调、重连代次、媒体回包失效 | Android/browser 混合连接，单路断线不拖累其他路 |
| 批量运行 | 可见范围、跳过原因、部分失败、捕获 run_id | 当前网格分别执行不同脚本，隐藏目标不受批量操作影响 |
| 执行隔离 | 真实 WASM 并发、有界取消、同目标互斥、日志隔离 | 长等待与短任务并行，停止其中一路后其余继续 |
| 恢复与资源 | 刷新不启动、状态对账、卸载清理 | 放大、关闭预览和刷新后脚本持续，无连接泄漏 |

## 五 风险与真实验收清单

主要风险是旧 Console 的全局状态泄漏、焦点与面板提交顺序、晚到连接回调，以及多路解码对内存和 CPU 的压力。分别用单一状态源、守卫事务、会话代次和真实负载测量控制；不通过复制面板、放宽输入屏障或压缩自动化原图规避。

- [ ] 分别以四路、九路测试 Android、浏览器及混合目标，记录目标组成、主机、浏览器版本、分辨率、帧率和测试时长
- [ ] 记录预览 FPS、交互延迟、CPU、内存及连接数量，切焦点、放大、隐藏、重连后检查是否持续增长
- [ ] 使用不同配置包、脚本和参数并发运行，核对实际目标、日志、截图与取消结果；不只检查按钮状态
- [ ] 制造单路断线、viewer 冲突、配置缺失和脚本失败，确认其余预览与脚本可继续，错误指向准确目标
- [ ] 验证未保存编辑、媒体取帧迟到、模板裁切、音频静音、旧触点与按键释放，恢复布局后不自动执行
- [ ] 在隔离数据与本机服务上验收；首次 ADB 调用设置 `ADB_MDNS=0`，不为测试改变防火墙或打断现用设备会话

当前尚无真实四路、九路性能结论。完成以上实测后再记录适用条件与限制，不将现有基线、合成帧或单路测试写成多路验收结果。
