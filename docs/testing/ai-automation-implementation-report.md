## 分阶段交付

### 阶段 0 最小契约与架构边界

已整理[跨模块实施合同](../plans/gamer_ai_automation_contracts.md)，明确素材格式、四类验证结果、候选版本、受控 AI 调用和 Trace 图片身份。职责仍归现有三个插件：视频生产证据，自动化管理候选与验证，AI 管理模型与诊断工具；Core 保持输入、资源、媒体和运行机制。

素材、脚本、模板、函数、模型配置和执行设置使用内容身份或版本绑定，避免以可变文件名证明验证有效。真实 Android/CDP 时间对齐结论仍待实际录制确认。

### 阶段 1 录制与操作时序

已区分会话相对时间、原始采集 PTS 和归零后的媒体文件 PTS，使用整数微秒与真实帧索引。语义操作保存实际持续时间、滑动 UP 端点及轨迹，具名按键保留原始语义；未完成手势、非线性/多点输入等显式标记，不伪造成完整点击。

停止、取消、失败、中断与分段边界分开处理；停止录制不等于任务成功。主要代码：[录制服务](../../server/src/recording/mod.rs)、[视频事件映射](../../plugins/gamer-video/ui/src/components/video/recordingEvents.js)。合成录制与媒体测试可验证时序规则，不能证明真实设备不存在偏移。

### 阶段 2 可携带素材包

已增加“制作素材包”：选择已结束录制和 START/END，预览实际边界画面，填写目标并明确确认 END。导出 `.gamersample` ZIP 包含 manifest、原尺寸 PNG、操作、来源时序、分段和可选原视频；默认附带视频以支持等待过程按需取帧。

导入与读取校验路径、重复项、大小、SHA256、实际图片解码、坐标与时间窗口。已导出素材不依赖原录制目录或正在运行的视频插件。视频侧旧“直接生成脚本”主入口已移除，生成归自动化插件；普通外部视频不被当作含完整操作的演示。

实现依据：[素材格式与校验](../../plugins/gamer-video/host/sample.rs)、[素材界面](../../plugins/gamer-video/ui/src/components/video/VideoSamples.vue)、[视频说明](../../plugins/gamer-video/README.md)。当前界面支持边界选择与自动证据提取，不等于已提供任意中间帧人工补选工作台。

### 阶段 3 YAML v2 与同源执行

脚本和函数库均要求 `version: 2`；提供命名 `targets`、只观察的 `wait`、缺失可跳过的 `optional`、验证完成画面的 `finish`，以及 `fail`、`trace`。保留函数、参数、变量、分支、有限循环和底层调用，不建立第二套运行解释器。

必需等待与 finish 默认 10 秒，可选观察默认 0ms；支持受限时长引用。`wait_find` 的默认点击改为 false。运行结束而没有达到完成条件不能当作目标成功。新语法降为权威解释器使用的内部表示，保留源路径及稳定步骤身份。

生产执行冻结源文件、函数、模板及执行设置；观察对象继续受目标、连接代次、坐标版本和新鲜度约束。宿主与 WASM 通过运行契约握手，旧组件不匹配时在输入前拒绝执行。依据：[视觉语法](../../plugins/gamer-yaml/host/syntax/visual.rs)、[解释器](../../plugins/gamer-yaml/interpreter/src/lib.rs)、[运行装配](../../plugins/gamer-yaml/host/runner_adapter.rs)、[语法参考](../reference/YAML.md)。

### 阶段 4 离线素材验证

已建立同源回放宿主，使用虚拟时钟、真实 NCC 模板匹配和截获的待核对输入，不注入真实设备或执行启动应用、通知等外部副作用。按素材的真实顺序检查观察、操作和 END，保留动作对齐证据；不能跳过错误点击后再借未来成功画面通过。

PNG 模式要求足够密集的证据；稀疏 PNG 需要先核验包内视频，再按实际索引取帧。损坏锚点、视频几何/时序不一致、缺帧、未完成目标和不支持操作不能成为通过结果。

报告区分 `passed`、`failed`、`insufficient_evidence`、`unsupported`。有效性绑定源码、模板、函数、素材、受测参数及实际生产点击延迟/默认超时；任何影响验证的变化均需重新检查。依据：[回放验证](../../plugins/gamer-yaml/host/offline_validation.rs)。

### 阶段 5 设备无关 AI 协作

AI 生成复用现有模型配置、私有凭据、图像探测、预算与协议实现，不获取设备控制租约。UI 和服务端检查 AI 的生命周期、依赖及当前配置的图像能力探测；更换模型、端点或协议使旧能力结论失效。

只发送选定任务的必要图片、目标、源码和精简失败信息，不上传全库或视频字节。图片子集有明确数量与字节预算，遗漏信息进入提示上下文。取消、插件停止、配置变化与迟到结果均绑定原候选作用域；AI 不可用时原文编辑和人工候选验证仍可用。

依据：[AI 自动化服务](../../plugins/gamer-ai/host/automation.rs)、[调用契约](../../plugins/gamer-yaml/host/GENERATION_API.md)。协议桩只验证接线，不证明真实模型理解能力或费用精度。

### 阶段 6 多素材生成与有限修正

自动化面板支持多选已有素材或导入归档、填写目标、AI 生成或手写候选。模板必须从选定素材的真实帧裁切，记录来源；模型不能凭空返回模板图片、改写样本或删除失败样本。

候选在独立暂存区循环执行“提议 → 全素材验证 → 携带失败证据有限修正”，受尝试次数、耗时、Token 和并发上限约束。费用不明会明确提示并阻止自动重试。取消后可继续人工检查，不让迟到模型结果覆盖当前包。

只有所有原选素材在当前内容和设置下通过，用户才可正式保存。保存前展示冻结正式源码差异、实际模板、受测参数、默认参数是否匹配、冻结执行设置及素材指纹；草稿保留不写入生产资源。脚本、模板和私有版本记录原子提交，并检查并发冲突。依据：[生成编排](../../plugins/gamer-yaml/host/generation.rs)、[资源事务](../../plugins/gamer-yaml/host/revisions.rs)。

### 阶段 7 Runtime Trace 图片证据

在现有 journal 上增加独立 `image_id`，不混用调用栈 `frame_id`。保存实际识别使用的原尺寸帧和模板，关联步骤、搜索区域、阈值、命中框与原始时间。错误前最后观察帧和错误后新截图分开标记；断连或抓图失败记录 gap，不伪造当前画面。

无损 PNG、哈希去重、有限队列与采样限制控制额外成本。开关边界和异常留证与普通日志分离；临时图片默认完成后保留 24 小时，容量超限先清理最旧已完成记录，活动运行达到上限停止后续采集并留下缺口。显式保留走独立配额，不改变普通日志的默认 14 天策略。

依据：[Trace 实现](../../server/src/runtime_trace.rs)、[管理员 API](../../server/src/api/runs.rs)、[完整保存策略](../reference/RUNTIME_TRACE.md)。真实 Android/CDP 采集开销和长时战斗覆盖仍待实测。

### 阶段 8 受控 AI 调试和撤销

对话可附加用户选定的脚本、候选或具体运行，服务端核对配置包、入口、目标和版本，不使用全局最近记录推断故障。受限工具读取摘要、步骤、相关图片与模板；图片缺失和过期显式返回。

AI 只形成 `pending_proposal`，不能自称用户批准或直接修改正式资源。用户先确认应用到候选，使旧报告失效，再全素材验证并单独确认保存。历史的“撤销此变更”只恢复该次变更涉及资源的 before 状态，保护无关资源并拒绝覆盖后续同资源修改；撤销也形成新记录。

分析不暂停已有 AI 游玩，也不获得游玩/记忆工具。实际试跑仍由现有运行管理和设备租约处理。依据：[AI 对话服务](../../plugins/gamer-ai/host/conversation.rs)、[生成与诊断契约](../../plugins/gamer-yaml/host/GENERATION_API.md)。

### 阶段 9 前端与日常操作

三个现有工作台已接通主流程。自动化以无损 YAML 原文为唯一可编辑表示，不让旧视觉表单删掉 v2 字段；函数库整份保存，测试运行仍选择具体函数。保存和参数流程复用现有服务端校验与资源版本机制。

运行列表增加图像缩略图、原图、搜索/命中框、实际模板、关闭/缺口/过期提示，以及“交给 AI 分析”和“长期保留证据”。报错位置优先展示经身份核对的冻结源码，当前文件变化时不错误定位。界面和异步状态测试覆盖取消、重复操作、乱序响应、切包、保存冲突与审批迟到。

**单帧桥接已交付：**Trace 详情增加“保存画面”，直接下载经过认证的同源原始 PNG，不经过画布重编码。下载文件可复用既有模板“上传”入口作为离线模板输入（单模板 10 MiB、同名不静默覆盖），也可作为回归参考图。已过期或无法读取的图像禁用保存。明确标注单张图不含操作及完成证据，不支持据此伪造完整回放样本、媒体身份或 END；完整演示素材仍由视频流程建立。窄窗口/手机宽度的真实浏览器视觉验收受环境阻塞，组件和构建通过不构成替代。

已提供[本地验收说明](ai-automation-local.md)和[HTTP 验收脚本](../../tools/verify-ai-automation-local.py)：独立临时数据、真实登录、生产插件安装入口、生产解析器/回放/事务以及本机模型协议桩。固定 A/C 有确认、B 无确认，包含移动目标和失败变体；另新增未暴露给协议桩的留出 D，沿用完全相同的生成脚本和模板、无追加模型请求。视频回放用实际 ffmpeg/媒体接口处理生成片段。完整 HTTP 脚本 23 项检查已全部通过，结果见[机器可读验收记录](ai-automation-local-results.json)。

文档、示例、插件版本、最低宿主与旧 WASM 拒绝契约已更新；全部前端套件和七个插件 UI 加 Web 构建已通过。服务端完整测试结果见下节；完整 HTTP、独立解释器与最终组件构建已通过，但浏览器和真实场景不在通过范围。

## 用户主流程

1. 在视频工作台录制演示，结束后进入“制作素材包”；核对 START/END 的真实画面、目标与质量提示，按需导出归档。
2. 在自动化的“AI 生成与验证”选择所有必须通过的素材，填写目标。模型未就绪时先完成配置/探测，或直接使用“手写源码离线验证”。
3. 审阅候选 YAML、模板原图/裁切来源和源码差异；查看每份报告，不排除失败样本。需要时有限修正或保留草稿。
4. 确认受测参数、默认值差异、冻结延迟/超时及素材指纹；全部通过后明确保存脚本和模板。
5. 连接实际目标，使用已有“运行”入口和参数流程试跑。该步骤需要真实设备，未被本地离线验收替代。
6. 在日志中选择对应运行，检查原图、匹配框、缺口与冻结源版本，必要时交给 AI 分析。
7. 修改先审核并应用到候选，重新验证后再确认保存。需要恢复时明确“撤销此变更”，不要把历史运行快照直接覆盖当前文件。

## 轻量实现与已知边界

- **复用三个插件、一个解释器和现有 journal。**没有新增独立 AI 自动化插件、通用 Agent 平台、双语法长期兼容层或游戏模拟器；没有重建大型可视化编排器或视频调试时间线。
- **素材可携带且有硬上限。**归档压缩/展开总量 128 MiB、最多 260 项、240 张 PNG、100 个动作、5 分钟；PNG 有尺寸/解码分配限制。回放还控制总体证据、解码缓存和执行预算，过限拒绝而非无界扩张。
- **证据不是反事实模拟。**没有录到的操作、外部输入、新分支和不支持的长按/多指/非线性手势不能由 AI 猜补。当前普通 tap/key 回放不把超过 200ms 的按压伪装成短按。
- **保留真实时间和执行设置。**不会用录制点击间隔堆成脚本，也不靠把生产点击延迟暗改为 0 来让验证通过。对齐规则有明确证据和诊断；其真实游戏适用性仍待验证。
- **PNG 是有依据的首版取舍。**沿用现有无损编码依赖，不为 WebP 增加新 codec。导出后无损不等于恢复视频压缩已经丢失的信息。
- **有界模型调用不是金额保证。**默认 3 次尝试、180 秒、40000 Token；并发和图像范围另有限制。缺失用量或取消中的请求成本仍可能未知，不宣称精确费用或必然收敛。
- **私有历史不混入配置包导出。**候选、不可变证据快照和撤销历史独立保存，临时 Trace 清理不触碰长期素材或正式资源。
